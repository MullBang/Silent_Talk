## 프로젝트 개요

```
[업로드 영상 | 웹캠]
   → 25fps 타임스탬프 리샘플 → 입술 ROI 96×96 정규화
   → 업로드: 3초 세그먼트 / 웹캠: 발화 단위, 최대 8초
   → 3D-CNN + BiLSTM + CTC 추론
   → CTC Beam Search + 위치별 Unicode 자모 음절 복원
   → [타임스탬프 결과 화면 | 실시간 자막]
```

- **백엔드**: FastAPI. 업로드 추론은 비동기 Job(폴링), 웹캠은 WebSocket 스트리밍.
- **프론트엔드**: React + Vite + Tailwind. 업로드(SCR-01)/결과(SCR-02)/웹캠(SCR-03) 화면.
- **모델**: `lipnet-compact-v1` 경량 모델과 `lipnet-residual-v1` 잔차 모델(3D-CNN+BiLSTM+CTC), 각 3,287,781개·3,683,909개 변수. 자모 69클래스(초성19+중성21+종성27+공백+blank), 실험 가중치 미배포.

교정된 train의 짧은 16문장은 1,600회 갱신 후 greedy·beam·CPU 재로드에서 16/16 복원했습니다. 이는 학습 연결 검사이며 새 화자 인식 성능은 아닙니다. 9단계 당시 잔차 CNN 후보도 GPU 동작 및 같은 16문장 복원 검사를 통과했습니다. 전체 자료 비교는 아래 10단계에서 완료했습니다.
교정된 v4의 전체 학습 20epoch를 완료했다(실제 갱신 9,999회, AMP 보호 1회 건너뜀). 선정 epoch6의 문장 평균 자모 CER는 72.85%, 완전 일치 0/20이다. 같은 v4 검증 영상을 사용한 8단계 모델 79.43% 대비 6.58%포인트 감소했다. 정상 72.85% / 회색 81.62% / 역순 72.68%로, 회색과 차이는 있지만 시간 순서 활용은 미입증이다. 학습 1,000문장 CER는 73.23%, 완전 일치 0/1,000이며 CPU/GPU 검증 출력은 20/20 일치했다. 최종 test50과 실제 웹캠 정확도는 미평가이며 서비스에 배포하지 않았다. 9단계 당시 후속 계획은 잔차 신경망 후보를 같은 자료·초기 학습량·학습률·20epoch 조건으로 비교하는 것이었다. 비교 결과는 아래 10단계에 기록했다.
이번 단계에는 추가 데이터 다운로드가 필요하지 않습니다. 기존 v2/v3 데이터와 1~8단계 모델·평가 기록을 보존했습니다.

[10단계: 잔차 모델 비교 실험](docs/단계별_개선/10_잔차모델_비교실험.md)

seed42·학습률0.0003·batch2·누적1·20epoch(각 10,000미니배치)를 실행했다.

정상 val 점수 기준 비교 후보는 **경량 모델**이다. 이는 서비스 배포 결정이 아니다.
잔차 연결뿐 아니라 CNN 층 구성·ReLU→GELU·변수 수도 함께 달라져 단일 변경의 효과로 해석하지 않는다.
같은 자료·학습 일정의 비교이며 실제 갱신 수, 선정 epoch, 연산량과 학습 시간은 다를 수 있다.
val은 2명·20문장이고 seed42 한 번의 실행이다. 이 val은 모델과 저장 시점 선택에도 사용했으므로
독립된 최종 평가가 아니다. 회색·역순 차이만으로 시간 순서 활용이나 새 화자 인식을 입증하지 않는다.
CER/WER는 오류율이며 삽입 오류로 100%를 넘을 수 있다. 1-CER를 인식 정확도로 환산하지 않는다.
CPU/GPU 일치는 저장된 영상의 실행 일치 검사다. 최종 test50과 실제 웹캠 정확도·지연은 미평가이며
실험 가중치를 웹캠 서비스에 배포하지 않았다. 기존 1–9단계 수치는 당시 조건의 기록으로 보존한다.

이번 조건의 20epoch 비교에서는 잔차 모델의 우위를 확인하지 못했다.
주 선정 지표인 문장 평균 자모 CER는 경량 72.85%에서 잔차
79.87%로 **7.01%포인트 높아졌다**. 따라서 잔차 모델로 교체하지 않고,
후속 실험의 비교 기준은 기존 경량 모델로 유지한다. 이 결론은 이번 자료·학습 방식·횟수에 한정되며
모든 잔차 구조나 다른 학습 조건의 가능성을 부정하는 결과는 아니다.

전체 어절 WER는 102.65%에서 100.53%로 소폭 낮아졌으나,
두 모델 모두 완전 일치 0/20이고 삽입 오류를 포함한 WER도 100%를 넘는다. 모든 지표가 나빠졌다는
뜻은 아니지만 실제 대화 문장을 추출할 수준의 개선으로 볼 수 없다. 두 모델 모두 웹캠용으로 배포하지 않는다.

잔차 모델의 정상/회색/역순 CER는 각각 79.87% / 78.96% /
80.39%다. 정상 영상이 회색보다 나은 결과를 내지 못했고 역순 차이도 작다.
이 대조만으로 영상 정보를 전혀 사용하지 않는다고 단정할 수는 없으나, 정상 입술 동작을 읽는 이점과
시간 순서 활용 능력은 입증하지 못했다. CPU/GPU 검증 출력 일치 20/20은
실행 재현성의 확인이며 인식 정확도의 증거가 아니다.

학습 문장에서도 잔차 CER는 80.96%, 완전 일치는 1/1,000이다.
선행 학습에서 복원했던 16문장도 본 학습 후 완전 일치가 1/16이다.
학습 자료 자체의 복원에 문제가 남아 있으므로, 현재 정체를 새 화자나 데이터 수 부족만으로 설명하지 않는다.
구조를 더 크게 바꾸거나 데이터를 곧바로 늘리기 전에 학습 신호와 영상 특징이 어떻게 사용되는지 확인한다.

**10단계 당시 후속 계획 — 11단계: 정지 프레임·프레임 순서 섞기 대조와 길이별 CTC 출력 분석으로 입술 움직임 활용 및 학습 정체 원인을 진단한다.**
현재 두 모델과 기존 train/val 자료를 고정하고, 문장 길이와 픽셀 분포를 최대한 유지하는 추가 대조,
blank·반복 자모 출력, 문장 길이별 오류를 함께 확인한다. 최종 test50은 계속 제외한다.
이 진단에는 추가 데이터 다운로드가 필요하지 않다. 원인을 확인한 뒤 학습 방식 변경이나
화자·촬영 조건 확대를 결정하며, 새 자료가 필요하면 종류·규모·이유를 먼저 안내한다.

**10단계 당시 다음 작업(11단계, 완료 결과는 아래 참조):** 정지 프레임·프레임 순서 섞기 대조와 길이별 CTC 출력 분석으로 입술 움직임 활용 및 학습 정체 원인을 진단한다.
이번 10단계와 다음 11단계에는 추가 다운로드가 필요하지 않다. 이후 추가 학습 자료가 필요하면
종류·규모·이유를 사용자에게 먼저 알린다.

**2026-09-18 개선11단계 — 고정 가중치의 시간 정보·CTC 출력 진단 완료**

11단계 고정 가중치 진단을 완료했습니다. 검증20문장의 정상/정지 입력 자모 CER는 경량 72.85%/72.74%, 잔차 79.87%/81.20%입니다. 입술 움직임의 시간 순서를 유용하게 활용한다는 근거가 부족하고 일부 자모 반복이 확인됐습니다. 이번 단계는 새 학습이나 정확도 개선 단계가 아닙니다. 최종 test50·실제 웹캠 성능은 미평가이며 미배포입니다. 11단계 당시의 후속 계획은 12단계에서 16문장 계속 학습과 64문장 확대 학습을 비교하여 출력 편중 발생 시점을 확인하는 통제 실험입니다. 기존 자료로 시작하며 추가 자료 필요 시 종류·규모·이유를 먼저 안내합니다.

```bash
# 백엔드 (Python 3.10+)
```

```bash
cd backend
```

#### 인식 모델: 공식 OLKAVS (기본값, 2026-10-20~)
업로드 경로는 공식 OLKAVS 영상 모델을 쓴다. 서버는 시작할 때 상주 워커 두 개를 백그라운드로 띄운다.
- 입술 추출 워커: `.venv-olkavs-roi` (mediapipe 0.10.21)
- 인식 워커: `.venv-olkavs` (torch, `experiments/olkavs_official/weights/multiview_lip.pt`)

두 가상환경과 가중치가 있어야 한다. 서버 자체는 fastapi·mediapipe·torch가 설치된 환경(이 PC에서는 `py -3.11`)으로 실행한다.

```bash
cd backend
py -3.11 -m uvicorn main:app --host 127.0.0.1 --port 8000
```

- `/health`의 `model.roi_worker`와 `model.infer_worker`가 `ready`가 되면 준비 완료다. GPU 기준 약 10초 걸린다.
- 업로드 영상은 최대 12초 창으로 나눠 인식한다. 창 경계는 6~12초 사이에서 입 움직임이 가장 작은 지점이다.
- 워커 로그는 `backend/logs/olkavs/`에 남는다.
- 시연 때는 `--reload`를 빼고 실행한다. 코드가 바뀔 때마다 모델을 다시 올린다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `LIPNET_MODEL_BACKEND` | `olkavs` | `compact`이면 자체 경량 모델(3초 세그먼트) 경로 |
| `LIPNET_OLKAVS_DEVICE` | `auto` | `cpu` / `cuda:0` |
| `LIPNET_OLKAVS_DECODER` | `hybrid` | `ctc`이면 빠르지만 덜 정확함 (8초 기준 hybrid 약 5초, ctc 1ms 미만) |
| `LIPNET_OLKAVS_SEGMENT_SECONDS` | `12` | 업로드 영상을 나누는 최대 창 길이(초). 3~12만 허용, 경계 탐색 폭은 이 값의 절반 |
| `LIPNET_OLKAVS_PRELOAD` | `1` | `0`이면 첫 요청 때 워커를 띄움 |
| `LIPNET_OLKAVS_MIN_CONFIDENCE` | `0.75` | 신뢰도가 이보다 낮으면 `[인식 불가]`로 표시하고 모델 문장은 `candidate`로 남김. `0`이면 끔 |
| `LIPNET_WEIGHTS` | `backend/models/weights/baseline_jamo_v2.pt` | compact 가중치 경로 |

웹캠 실시간(WebSocket v2)은 계속 compact 경로를 쓴다. compact 가중치가 없으면 안내 문구와 함께 연결을 거부한다.

#### 녹화해서 분석 (6단계, 시연 기본 화면)
- 프론트 주소 끝에 `#record`를 붙이거나 업로드 화면의 "녹화해서 분석 →"을 누른다.
- 영상만 녹화한다(마이크 사용 안 함). 기본 8초에 자동으로 멈추고, 30초 모드는 실험용이다.
- 녹화는 `POST /api/record`로 보낸다. 서버가 프레임 시각으로 실제 길이를 재서 0.5초 이상 30초 미만만 받는다. 100MB를 넘는 요청은 413으로 바로 끊는다.
- 입 움직임으로 녹화 앞뒤의 말하지 않는 구간을 잘라 내고 12초 이하 녹화는 창 하나로 인식한다.

## 모델 학습

**현재 기본 명세(`DEFAULT_MANIFEST`)는 `data_cache/datasets/aihub_timed_v4/manifest.json`입니다.**
v4는 시간축을 교정한 train1,000/val20/test50입니다. 명령에도 경로를 명시하여 실험 조건을 남깁니다.
기존 v2 파일럿과 v3 확대 실험은 각각의 이전 명세와 해당 체크포인트를 명시하면 재현할 수 있습니다.
시간 메타데이터가 없는 이전 명세는 이전 캐시만 읽으며, 새 시간축 캐시와의 혼합은 거부합니다.

```powershell
# 현재 교정 데이터의 무결성과 학습/검증 선택만 검사
& '.\.venv-gpu\Scripts\python.exe' scripts/train.py --manifest data_cache/datasets/aihub_timed_v4/manifest.json --check-data
```

공식 Training 10명 중 8명(현재 1,000문장)을 학습, 2명(20문장)을 개발 검증에 사용합니다.
공식 Validation 5명(50문장)은 프로젝트의 최종 평가용으로 보존합니다. AI Hub 공식 Test를 확보했다는 의미는 아닙니다.
파일명 순서로 마지막 일부를 검증셋으로 사용하던 방식을 제거했습니다.

```bash
# 실제 캐시·화자 분리·해시 검사만 실행. 모델을 생성하거나 학습하지 않음
python scripts/train.py --check-data

```

학습은 고정 명세의 train/val만 사용합니다. test는 모델 선택에 사용하지 않습니다.
명세 파일의 SHA-256과 분할 정보를 체크포인트에 저장합니다. 명세 사용 중 `--max-frames`로
일부 자료를 임의 제외하지 않으며, 길이 조건을 바꿀 때에는 새 명세를 생성합니다.
`.venv-tokenizer`는 CPU·서버 검증용, `.venv-gpu`는 캐시 학습용 격리 환경입니다.
GPU 환경은 Python 3.12.14 / PyTorch 2.10.0+cu128로 검증했습니다. 전체 서버 의존성을
학습 환경에 추가할 필요는 없습니다. 설치 절차와 측정치는 [4단계 보고서](docs/단계별_개선/04_경량모델_GPU학습환경.md)를 참고하세요.

```powershell
# 이 컴퓨터에는 설치 완료. 아래 경로는 새 설치 시 자신의 Python 3.12 경로로 대체
.\scripts\setup_gpu.ps1 -Python 'C:\path\to\Python312\python.exe'

# 데이터 연결/GPU 동작만 짧게 검증. 임시 가중치를 웹캠용으로 배포하지 않음
& '.\.venv-gpu\Scripts\python.exe' scripts/train.py --device cuda --batch-size 2 --precision amp --max-steps 3 --out tmp/gpu-smoke.pt --report tmp/gpu-smoke.json

# 교정된 train16 복원 검사 가중치를 초기값으로 사용. 기존 결과와 다른 경로를 지정
& '.\.venv-gpu\Scripts\python.exe' scripts/train.py --manifest data_cache/datasets/aihub_timed_v4/manifest.json --init-weights results/step9-diagnostics/compact-short16-v4/last.pt --device cuda --batch-size 2 --precision amp --epochs 20 --lr 0.0003 --eval-every 2 --out results/compact-warm-v4-new/best.pt --last-out results/compact-warm-v4-new/last.pt --report results/compact-warm-v4-new/training.json
```

`--accum-steps 2`를 추가하면 메모리에 올리는 묶음은 2개로 유지하면서 2회분 기울기를 모읍니다.
CTC와 log-softmax는 FP32로 계산하고 길이 패딩은 CNN/LSTM에서 구분합니다.
가중치에 구조 버전도 저장하며, 기존 대형 모델 가중치는 호환되지 않습니다. 현재 저장 기능은
추론용이며 중단된 학습을 optimizer 상태까지 이어가는 기능은 아직 없습니다.
`--init-weights`는 동일 명세의 train 소수 문장 복원 검사에서 생성한 동일 구조 가중치만 초기값으로 허용합니다.
출처의 명세 해시·표본 ID·검사 목적을 검증하고, optimizer와 scaler는 새로 만듭니다. 옵션을 생략하면 무작위 초기화합니다.
선행 16문장 학습량도 전체 실험의 일부이며, 초기화·학습률·전처리가 다른 실험의 차이를 한 가지 변경 효과로 단정하지 않습니다.
`--snapshot-epochs 12`처럼 지정하면 해당 epoch의 추론용 가중치를 별도로 남깁니다.
중간 저장에도 실제 갱신 횟수를 기록하며, 기존 중간 저장 파일을 덮어쓰지 않습니다.
8단계의 30epoch 실행 조건과 새 출력 경로를 사용하는 재현 명령은 [8단계 보고서](docs/단계별_개선/08_확대데이터_학습_성능검증.md)에 있습니다.

### 원본 데이터 선정 및 캐시 준비

```bash
# 새 자료를 준비할 때 출력은 반드시 새 빈 경로로 지정
python scripts/build_speaker_dataset.py index --source-root "D:/009.립리딩(입모양) 음성인식 데이터/01.데이터" --out data_cache/datasets/aihub_pilot_next
python scripts/build_speaker_dataset.py prepare --selection data_cache/datasets/aihub_pilot_next/selection.json
python scripts/build_speaker_dataset.py validate --manifest data_cache/datasets/aihub_pilot_next/manifest.json
```

- 로컬 MP4와 이미 풀린 JSON을 색인하며 TAR 내부 MP4도 읽습니다. 압축된 영상은 선정된 파일 하나씩만 임시 추출합니다. 전체 TAR를 추가로 풀지 않습니다.
- 정면 A, 화자당 2개 녹화에서 각 5문장, 최대 200프레임(8초)을 기본 파일럿으로 선정합니다. seed=42로 선정을 재현합니다.
- 원본 라벨의 `speaker_info.speaker_ID`, 영상명, 각도를 파일명과 대조합니다. 동일 발화의 다른 각도는 같은 발화 키로 묶습니다.
- 숫자·영문·X 등 미지원 정답, CTC 불가능 구간, 길이 초과, bbox 누락을 별도 기록합니다. 정답을 임의로 고치지 않습니다.
- 이번 로컬 라벨의 `xtl_ytl_xbr_ybr` 값은 영상 대조 결과 **y1,x1,y2,x2 순서**입니다. 이를 x1,y1,x2,y2로 바꾸고, 영상을 돌리지 않은 채 RGB 96×96 ROI를 추출합니다. 다른 자료에서는 좌표 순서를 다시 확인해야 합니다.
- 원본 프레임 선택에는 라벨의 반올림 FPS를 사용하지 않습니다. 실제 영상 FPS·프레임 수·선택 프레임 시각을 검사하며, 캐시와 명세에 `temporal_method`, `video_fps`, `label_fps`를 기록합니다.
- `aihub_pilot_v1`은 회전 ROI 오류로 제외했습니다. `aihub_pilot_v2`와 `aihub_expanded_v3`는 이전 실험 재현용이고, 현재 학습 경로는 시간축을 교정한 `aihub_timed_v4`입니다. 구형 ROI 버전 및 명세·캐시의 시간 버전 혼합은 로더에서 거부합니다.
- 라벨 bbox와 웹캠 MediaPipe의 실제 검출 결과는 다를 수 있습니다. 크기·여백·정규화 규약 외에 실제 크롭 분포를 후속 웹캠 단계에서 확인해야 합니다.

학습은 문장별 가변 길이 T와 last-frame 패딩, 길이별 배치 구성을 사용합니다.
SEQ_LEN=75는 추론 세그먼트 명목값입니다. 150문장 파일럿은 데이터 연결 검증용이며, 자유 발화 인식 성능을 확보할 만큼의 학습 규모는 아닙니다.

## 웹캠 처리 v2

프론트엔드와 백엔드를 함께 업데이트해야 합니다. 서버에 학습된 `baseline_jamo_v2.pt`가 없으면
카메라를 켜기 전에 학습 필요 안내를 표시합니다. 무작위 모델로 자막을 생성하지 않습니다.

- 실제 영상 프레임 시각을 기준으로 40ms 간격의 25fps 입력을 만듭니다. `requestVideoFrameCallback`을 우선 사용하며 rAF에서는 중복 영상 시각을 건너뜁니다.
- 발화 시작 프레임을 포함한 최대 8프레임 버퍼를 보존합니다. 최소 12프레임을 확인한 뒤 최대 11프레임씩 전송합니다.
- 청크에 `frame_count`와 실제 시간 범위를 명시합니다. 서버는 청크 전체 수신 후 한 번 추론하고, 프론트는 해당 응답 후 다음 청크를 보냅니다.
- 정지 시 카메라는 즉시 해제하고, 남은 발화 결과를 받은 다음 세션을 닫습니다. 마지막 청크가 비어 있어도 최종 결과를 요청합니다.
- 3프레임 연속 얼굴 추적 실패나 200ms 초과 촬영 공백은 진행 중 발화를 취소합니다. 연결이 끊기면 오류를 알리고 새 세션으로 다시 시작합니다.
- 발화당 최대 200프레임(8초), 전송 대기 최대 200프레임으로 제한합니다. 서버가 느리면 명시적으로 중단하며 영상이 무한히 누적되지 않습니다.
- 마이크는 사용하지 않습니다. 한 사람의 정면 입술을 대상으로 합니다. 실제 MediaPipe 검출 품질·bbox와의 분포 차이·인식 정확도·지연은 학습 후 측정해야 합니다.

**2026-09-18 개선12단계 — 16문장 유지 / 64문장 확대 학습 진단 완료**

12단계 학습 전환 진단을 완료했습니다. 같은 경량 가중치에서 16문장 유지/64문장 확대를 각각 1,600회 시도했습니다. 유지군은 기존 16개를 계속 복원했고, 확대군은 25회 평가에서 9/16으로 낮아졌다가 최종 16/16로 회복했습니다. 확대군의 추가 48개 greedy CER는 104.72%→49.23%, 완전 일치 4/48입니다. 학습 표본에 대한 결과이며 val/test·실제 웹캠 성능은 이번에 평가하지 않았습니다. 12단계 당시 제안한 같은64개 학습량 확대 실험의 완료 결과는 아래13단계에 기록했습니다. 현재는 추가 다운로드가 필요하지 않으며, 필요해지면 종류·규모·이유를 먼저 안내합니다.

두 군은 같은 v4 train의 short16 가중치·새 Adam·lr 0.0003·batch 2·AMP·clip 1·seed42에서 시작했다. 추가 48개는 예측을 보지 않고 train 화자×길이 구간에서 사전 선정했다. 각 1,600회 시도로 A는 표본당 200회, B는 50회 제시했다. 성공 갱신은 A 1,600/B 1,599회이며 B의 49회에 비유한 기울기를 건너뛰고 가중치가 그대로 유지된 것을 확인했다. 이 skip은 최초 복원 저하 관측 25회보다 뒤다. 확대군의 기존 문장 복원은 일시적으로 낮아졌다가 회복했으며 이번 64개 실험의 최종 시점에는 기존 문장 복원 실패가 나타나지 않았다. 1,000문장 학습의 원인이 해결됐다는 뜻은 아니다.

B 최종 추가 48개의 정상/정지/순서섞기42 greedy CER는 49.23%/60.51%/57.46%, 완전 일치는 4/48·1/48·0/48이다. 기존 16은 정상 16/16이지만 정지 9/16·섞기 10/16도 복원한다. 정상 입력의 이점은 관찰했으나 정적 단서·길이·암기와 일반화는 분리되지 않았다. 실제 웹캠 서비스에는 배포하지 않았다.

새 진단 코드는 매 시도마다 unscale 후 clip 전·후 기울기, 실제 가중치 변화, scaler·skip·표본 노출을 저장한다. 신규 관련 78개 검사 통과(선정·계측 23, 실행기 13, 집계 42) 및 원시 posterior 2,240행 재계산을 완료했다. 전체 프로젝트 검사 재실행은 아니다. 모델 구조·입력 전처리·토큰 사전·웹캠 프로토콜은 이번 단계에서 변경하지 않았다.

12단계 당시에는 같은64개로 총6,400회 등 고정 예산을 비교하는 후속 실험을 제안했다. 12단계 스냅샷에는 optimizer/scaler/RNG가 없어 원래16개 가중치부터 앞1,600회를 재현해야 했다. 이 재현과 연속 학습 결과 및 새 재개 상태 저장은 아래13단계에 기록했다.

정상 입력은 로컬 0/1,600/3,200/6,400회에 평가했다. 정지·순서 섞기는 미학습 80개의 출발·종료에만, beam10은 정상 592개의 출발·종료에만 적용했다. posterior 5,376개 재계산, beam 2,368개 재디코딩, 전체 상태 8개 검사 및 관련 테스트 172개가 통과했다. 로컬/누적 성공·생략과 프레임 제시 수는 상세 보고서에 기록했다.

한 seed의 개발 비교이며 문장 수 외에 길이·반복 빈도·계산량도 달랐다. 검증 점수로 가중치 선정·기존 체크포인트 교체·test50 캐시 접근·웹캠 평가·서비스 배포는 하지 않았다. CER의 보수를 프로그램 정확도로 환산하지 않는다.

17단계 당시 제안한 다음 18단계는 새 화자·새 녹화의 Training 원본 영상과 대응 JSON 라벨을 확보하기 위한 수집 요건과 입력 검수 준비를 우선한다. 현재 확인한 로컬 Training 원본(TS1/TS10, TL1/TL10)에는 기존 학습 8명의 새 녹화나 별도의 새 학습 화자가 없었다. 나머지 두 화자는 기존 val로 남겨야 한다. 다른 각도나 같은 녹화의 추가 문장은 남아 있지만 화자·녹화 다양성을 늘리지는 않는다. 따라서 이 범위를 넓히는 학습에는 추가 자료가 필요하다. 우선 기존 train/val/test 화자와 겹치지 않는 새 Training 화자의 영상·JSON을 첫 검수용 소량 표본으로 준비하고, 메타데이터로 화자·녹화·정답 중복을 확인한 뒤 실제 FPS, 발화 구간, 입술 ROI와 추출 품질을 검수하는 순서가 적절하다. 새 자료를 학습에 넣기 전에 분할과 비교 계획을 고정하고 본 학습에 필요한 화자·녹화 수는 18단계 수집 요건에서 정한다. 기존 ROI 좌표 교정과 9단계 FPS 교정, 11·15~17단계 대조를 오류 징후 없이 반복하는 작업은 우선하지 않는다. 이번 결과만으로 데이터 부족을 유일 원인으로 확정하거나 새 자료만으로 해결된다고 단정할 수는 없으며, 모델 표현력·정규화 등의 영향은 별도 통제 비교가 필요하다.

17단계 종료 당시에는 18단계를 아직 실행하지 않았다. 17단계는 기존 자료로 완료했으며 위 제안의 새 화자·녹화 학습에는 추가 Training 영상과 대응 JSON이 필요하다.

## 18단계 — 신규 원본 무결성 점검 후 복구 대기

TS2·TS20·TS200에서 기존 화자와 겹치지 않는 신규 15명의 6,255문장 메타데이터 후보를 확인하고, 별도 입력 검수용으로 120문장·30영상을 선정했다. 이 숫자는 라벨 기반 후보와 검수 계획의 규모이며, 사용할 수 있는 영상이나 추출 완료 클립의 수가 아니다.

| 검사 범위 | MP4 내부 박스가 파일 끝을 초과 | 0바이트 파일 | 구조 검사만 통과 |
| --- | ---: | ---: | ---: |
| 신규 정면 영상 180개 | 161개 | 2개 | 17개 |
| 선정 파일럿 영상 30개 | 28개 | 0개 | 2개 |

0바이트 파일 2개는 필수 `ftyp` 헤더도 없었다. 구조 통과는 MP4 상위 박스 경계 확인 결과이며, 정상 재생·전체 디코딩·발화 구간 및 ROI 검증을 통과했다는 뜻은 아니다. 현재 생성된 파일럿 클립은 **0개**이고 새 자료의 학습·모델 추론은 실행하지 않았다.

먼저 불완전한 원본의 완전한 사본을 확보하고 파일 크기·해시·컨테이너 구조·디코딩을 다시 확인해야 한다. 이후 기존에 고정한 120문장 계획에 따라 시간축·입술 ROI를 검수한다. 구조만 통과한 일부 영상으로 기존 계획을 대체하지 않았으며, 17단계 체크포인트·성능 기록과 기본 `aihub_timed_v4` 명세도 유지한다.
