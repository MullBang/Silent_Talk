# 새 계획 5단계 — 기존 모델의 시간 보정 입력 재평가

2026-09-24 실행 완료. **기존 평가의 시간 연결을 고쳐도 이전 두 모델의 인식 성능은 회복되지 않았다.** 256문장 학습 A와 512문장 학습 B 모두 보정된 20문장의 greedy 문자 오류율이 **84.56%**, 완전 일치는 **0/20**이었다. 기존 입력과 출력의 정확한 재현을 먼저 확인했으므로, 이번 비교에서 실행 환경이나 다른 전처리 변경을 시간 보정 효과로 섞지 않았다.

이 결과는 **현재 고정 가중치의 성능이 부족하다**는 근거다. 같은 모델 구조를 검증된 자료로 다시 학습해도 가능성이 없다는 증거는 아니다. 학습에 쓰인 원본들의 WAV/MP4 시간 정렬은 아직 미검증이며, 다음은 그 자료를 점검할 차례다.

## 비교 결과

동일한 20개 ID·정답, 두 화자(C025/C294 각각10문장)를 사용했다. 주 지표는 총 NFC 완성형 문자 편집거리/정답667자이며 내부 공백도 센다. 낮을수록 좋고 ‘1−오류율’을 인식 정확도로 부르지 않는다. 실패나 불리한 문장을 제외하지 않았다.

| 고정 모델 | 입력 시각 | greedy 문자 오류 | greedy CER | beam10 CER | 문장 일치(greedy/beam) |
|---|---|---:|---:|---:|---:|
| A: 256문장 학습 | 기존 시각 | 563/667 | 84.41% | 84.26% | 0/20 · 0/20 |
| A: 256문장 학습 | 보정 시각 | 564/667 | 84.56% | 85.16% | 0/20 · 0/20 |
| B: 512문장 학습 | 기존 시각 | 548/667 | 82.16% | 81.86% | 0/20 · 0/20 |
| B: 512문장 학습 | 보정 시각 | 564/667 | 84.56% | 84.86% | 0/20 · 0/20 |

같은 문장별 greedy 문자 오류는 A에서 4개 개선·10개 동일·6개 악화(총1자 오류 증가), B에서 5개 개선·4개 동일·11개 악화(총16자 오류 증가)였다. 정답 구간을 잘못 연결했던 과거 점수가 우연히 더 낮을 수 있다. 그 점수를 되찾으려고 잘못된 시각으로 돌아가거나 정답을 모델 출력에 맞춰 바꾸지 않는다.

| 모델·디코더 | C025 CER: 기존 → 보정 | C294 CER: 기존 → 보정 | WER: 기존 → 보정 |
|---|---:|---:|---:|
| A: 256문장 학습 / greedy | 84.83% → 84.33% | 83.77% → 84.91% | 108.47% → 106.35% |
| A: 256문장 학습 / beam10 | 84.58% → 85.32% | 83.77% → 84.91% | 108.47% → 106.88% |
| B: 512문장 학습 / greedy | 82.34% → 84.83% | 81.89% → 84.15% | 102.65% → 104.76% |
| B: 512문장 학습 / beam10 | 82.09% → 85.82% | 81.51% → 83.40% | 102.65% → 104.76% |

WER는 총 어절 편집거리/189어절이며 삽입 오류가 많으면 100%를 넘을 수 있다. 한 화자의 변화만으로 전체 개선을 주장하지 않는다.

### 이전 17단계 지표와 구분

17단계는 공백/문장부호 정규화 후 한글을 초성·중성·종성으로 분해한 **문장 평균 자모 CER**를 주로 보고했다. 이번 공식 후보 비교의 **전체 완성형 문자 CER**와 단위·정규화·집계가 다르므로 같은 숫자처럼 비교할 수 없다.

| 모델·디코더 | 문장 평균 자모 CER: 기존 → 보정 | 전체 자모 CER: 기존 → 보정 |
|---|---:|---:|
| A: 256문장 학습 / greedy | 80.02% → 80.25% | 79.07% → 79.44% |
| A: 256문장 학습 / beam10 | 80.10% → 80.53% | 79.15% → 79.74% |
| B: 512문장 학습 / greedy | 78.03% → 76.55% | 78.12% → 76.65% |
| B: 512문장 학습 / beam10 | 77.88% → 76.92% | 78.05% → 77.17% |

B의 greedy 자모 평균은 78.03%→76.55%로 조금 낮아졌지만 완성형 문자 CER는 82.16%→84.56%로 높아졌다. 일부 자모의 일치와 사용 가능한 한국어 문장 복원은 다르다. 어느 집계에서도 완전 일치 문장은 0개이며, 유리한 지표만 골라 성능이 회복됐다고 해석하지 않는다.

## 시간 외의 조건을 유지한 방법

비교 대상은 기존 17단계의 사전 지정 종료점 `A_keep256/step_6400.pt`, `B_expand512/step_6400.pt` 두 개다. 두 모델 모두 누적19,200회 시도의 종료 가중치이며 중간 점수를 보고 더 좋은 가중치를 고르지 않았다. 구조는 3,287,781개 변수의 compact 3D CNN → 프레임별 GroupNorm → 투영층 → 2층 양방향 LSTM →69토큰 CTC다.

입력은 기존 준비 함수 `_roi_seq_from_boxes`를 그대로 호출했다. 프레임 수는 `round((끝−시작)*25)`, 선택 원본 프레임은 `round((시작+k/25)*실제FPS)`다. 영상 프레임 번호에 대응하는 제공 입술 좌표에 상하좌우 각각20% 여백을 더하고 RGB96×96으로 보간한다. NPZ의 uint8 원본을 /255한 뒤 ImageNet 평균·표준편차로 정규화한다. 모델은 FP32·패딩 없는 batch1·eval 모드·시간 길이 유지이며, 외부 언어모델 없이 greedy와 기존 prefix beam10을 사용했다.

보정 입력은 기존 라벨 시작과 끝에 4단계에서 파형으로 확정한 이동량만 더했다. C025 A006/A007은 −8.362초, C294 A001/A003은 +0.046375초다. 원본 라벨과 문장은 고치지 않았다. 조건별2,144프레임·문장당35~178프레임으로 기존과 길이가 같고 CTC 최소길이 조건도 유지했다. 공식 후보의 BGR·native-frame·margin0/자동영역·MP4 입력은 기존 모델의 입력으로 재사용하지 않았다.

### 재현 검증

1. 기존 시각20개를 원본 영상에서 다시 추출해 원래 v4 캐시의 모든 uint8 픽셀·정답·토큰과 정확히 일치함을 확인했다.
2. 두 모델로 원래 입력을 다시 추론해 **40개 CTC 로그 확률 배열과80개 greedy/beam 문자열**이 저장된17단계 결과와 정확히 같음을 확인했다. 모든 원래 결과가 재현되기 전에는 보정 입력 추론을 시작하지 않도록 실행기를 구성했다.
3. 보정 입력까지 총80회 추론·160개 출력에서 실행 실패가 없었다. 독립 검산은40입력·4,288개 프레임 선택 기록,80확률 배열의 형상/유한값/확률합,160출력의 NFC/NFD 편집거리 및 전체/화자 집계를 확인했다. greedy는 별도 축약·유니코드 조합 구현으로 확인했고 beam10은 고정한 기존 디코더로 재실행했다. beam 알고리즘 자체를 독립 구현한 것은 아니다.

입력 준비의 필수 테스트9개가 통과했다. 짝지은40개 대표 프레임을 육안으로 확인했고 입술 영역과 RGB 색상이 정상이었다. 대표 이미지 검수가 모든 프레임의 발화 전사 정확성까지 보증하지는 않는다.

이번 준비는 약63.64초였고 새로 저장한20개 NPZ는36.09MB다. 원본 전체 사본이나 새 데이터셋 다운로드를 만들지 않았다. 기존 모델·원본·캐시·서비스 코드는 변경하지 않았으며 학습과test50 추론도 실행하지 않았다.

## 공식 후보와 비교할 수 있는 범위

같은 시간 매핑·20개 정답을 사용한4단계 공식 후보는 제공 좌표 경로CER32.68%·5/20문장 일치, 개선한 자동 영역 경로CER33.58%·5/20문장 일치였다. 이번 기존 A/B의 greedy는84.56%·0/20이다. **현재 가중치와 입력·디코딩을 합친 전체 처리 경로의 차이**를 보여준다. 모델 크기·사전학습량·토큰·프레임 속도·색상·crop·디코더가 다르므로 이 차이를 특정 신경망 구조 하나의 우열로 분리할 수 없다.

val20은 반복 사용한 두 화자의 개발 자료다. 공식 가중치의 사전학습 자료와 평가 원본의 중복 여부는 미확인이다. 두 시스템 모두 처음 보는 사용자의 실제 웹캠 성능으로 일반화할 수 없다.

## 남은 문제와 다음 단계

현재 고정 가중치는 발화 구간을 바로잡아도 한국어 문장 복원이 부족하다. 예를 들어 B의 보정 입력에서 정답 ‘아주 기쁘고 감사해’는 ‘하수 우 낡아 결혼해’로 출력됐다. 출력의 `�`는 저장 파일 인코딩 오류가 아니라 기존 토크나이저가 조합할 수 없는 예측 자모를 U+FFFD로 표시한 것이다. 이를 삭제하거나 문법적으로 다듬지 않고 그대로 오류로 계산했다.

1. **다음6단계는 학습 원본의 시간축 점검이다.** 실제 A/B 학습에 사용한59개 녹화를 대상으로 원본 WAV 보유 여부를 먼저 확인한다. 8명의 화자별 소수 녹화부터 앞·중간·뒤의 파형을 점검해 범위를 파악하고, 새 학습에 쓸 녹화는 각각 매핑을 검증한다. 검사량을 나누고 필요한 짧은 구간만 읽으며 Drive가 원본을 캐시할 수 있는 점도 고려한다.
2. 시간 불일치가 확인되면 해당 원본의 검증된 이동량으로 **별도 캐시**를 만들고, 기존 구조의 작은 복원/학습 대조부터 진행한다. 이상 여부를 확인하기 전에 C025의 −8.362초를 다른 화자에 적용하거나59개를 모두 잘못된 자료로 취급하지 않는다. 현재 확인된 C025/C294는 A/B 학습 집합에 없었으므로 이번 발견만으로 학습 오염을 주장할 수 없다.
3. 학습 정렬이 정상이라면 데이터 다양성·사전학습/특징 전달·토큰 출력·시간 정보 활용을 순서대로 비교한다. 같은 자료와 설정으로 반복 학습만 늘리는 것을 기본 다음 행동으로 삼지 않는다. 공개 후보는 비교 기준으로 보존하고 기존 모델을 개선할 여지도 구분해서 검증한다.

현재 단계에 새 학습 데이터는 필요하지 않았다. 다음 점검에서 원본 WAV가 빠져 있다면 필요한 파일명·용도·최소 용량을 먼저 특정해서 알린다. 이번 실험은 모델 폐기나 공식 모델의 서비스 채택을 결정하지 않았다.
