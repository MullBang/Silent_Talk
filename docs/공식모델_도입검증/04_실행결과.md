# 새 계획 4단계 — 시간 정렬 재점검과 자동 입술 영역 교정

실행일: 2026-09-24(KST). **완료 및 독립 검산 통과.** 보유 영상 네 개의 20문장을 사용했다. C025 두 녹화의 라벨 시간과 MP4 시간 사이에 −8.362초 차이를 확인해 평가용 매핑을 교정했다. 같은 교정 시간에서 자동 입술 처리 개선으로 문자 오류율(CER)이 **75.11% → 33.58%**, 문장 완전 일치는 **0/20 → 5/20**이 됐다. 이는 두 화자의 개발 자료 결과이며 웹캠 완성 성능을 뜻하지 않는다.

새 학습·AIHub 데이터 다운로드·서비스 모델 교체는 진행하지 않았다. 원본 라벨과 기존 실험 결과를 보존했고, 최종 test50은 사용하지 않았다. 모델의 입력은 영상뿐이다.

## 완료 결과와 선택

20문장 × 5가지 입력 × 2가지 디코딩 = **200개 출력**을 모두 평가했다. 주 지표는 NFC 정규화·앞뒤 공백 제거 후 내부 공백을 포함한 총 문자 편집거리/667자이며, WER는 총 어절 편집거리/189어절이다. 문장별 CER의 단순 평균이나 ‘정확도’가 아니다. 모든 입력·출력이 성공했다.

| 입력 방식 | Hybrid 문자 오류 | CER | WER | 완전 일치 | CTC 직접 출력 CER |
|---|---:|---:|---:|---:|---:|
| 제공 입술 좌표(참고 조건) | 218/667 | 32.68% | 53.44% | 5/20 | 41.68% |
| 기존 자동 직사각형 | 501/667 | 75.11% | 92.59% | 0/20 | 75.26% |
| 자동 정사각형 | 253/667 | 37.93% | 59.26% | 2/20 | 47.23% |
| 자동 정사각형 + 주변 1.5배 | 234/667 | 35.08% | 55.03% | 4/20 | 44.23% |
| 자동 정사각형 + 주변 1.5배 + EMA | 224/667 | 33.58% | 52.91% | 5/20 | 41.38% |

CTC 직접 출력의 문장 완전 일치는 다섯 조건 모두 0/20이다. Hybrid는 기존에 수정·고정한 CTC/attention 결합 검색이며 이번 단계에서 튜닝하지 않았다.

**다음 개발 실험의 자동 처리 후보는 `stable_context_square`다.** 정사각형·주변 1.5배·중심과 크기의 인과적 EMA(alpha 0.4)를 적용한다. EMA 추가 전후 총 문자 오류는 234→224개로 줄었고 C025는 218→214개, C294는 16→10개로 모두 감소했다. 따라서 추론 전에 정한 ‘전체 오류 엄격 감소, 화자별 악화 없음, 실패 증가 없음’ 기준을 만족했다. 기존 자동 직사각형보다 20문장 모두 개선됐지만, EMA만의 효과는 8문장 개선·5문장 동일·7문장 악화로 작고 고르지 않다. 더 많은 독립 자료에서도 EMA가 우수하다고 확정하지 않는다. 선택 기록은 `results/step04_decision.json`이며 서비스 기본값은 바꾸지 않았다.

| 입력 방식 | C025 CER(10문장·402자) | C294 CER(10문장·265자) |
|---|---:|---:|
| 제공 입술 좌표(참고 조건) | 50.25% | 6.04% |
| 기존 자동 직사각형 | 88.06% | 55.47% |
| 자동 정사각형 | 55.22% | 11.70% |
| 자동 정사각형 + 주변 1.5배 | 54.23% | 6.04% |
| 자동 정사각형 + 주변 1.5배 + EMA | 53.23% | 3.77% |

C025는 시간 교정 후에도 선택 후보의 CER가 53.23%이고 10문장 완전 일치가 0개다. 시간 불일치와 자동 영역 차이는 확인된 원인이지만, 남은 오류를 모두 설명하지는 않는다. 발화 내용·입술/음성 동기·화자 및 촬영 조건·학습 분포 차이를 다음 점검에서 구분해야 한다.

### 시간 교정 효과와 영역 처리 효과의 구분

제공 좌표·같은 모델/디코더의 3단계 기록은 345/667(CER 51.72%)였고 시간 교정 후에는 218/667(32.68%)이다. C025는 330→202개 오류, C294는 15→16개 오류였다. 이것은 평가 입력과 정답의 시간 연결을 바로잡은 효과이며 새 모델 학습의 성과가 아니다. 영역 처리 효과는 이번에 교정한 동일 프레임에서 직사각형 501개 → 선택 후보 224개 오류로 비교한다. 3단계의 잘못된 구간과 이번 후보를 직접 비교해 전부 ROI 개선 효과라고 보고하지 않는다.

3단계의 산술 기록은 보존하지만 기존 모델과 공식 후보의 일반화 성능 차이를 확정하는 근거로 사용할 수 없다. 기존 17단계의 개발 평가도 정확히 같은 val20을 썼다. 다만 현재 v4 학습 집합에는 C025/C294가 없고, 17단계는 검증 점수 기반 조기 종료·체크포인트 선택을 사용하지 않았으므로 이번 발견만으로 기존 가중치가 이 오류 때문에 학습됐거나 선택됐다고 판단하지 않는다. 실제 17단계 학습은 8화자·59녹화에서 뽑은 256/512문장이었으며, 해당 학습 녹화의 WAV/MP4 정렬은 아직 검사하지 않았다. 전체 v4 학습 자료는 1,000문장·96녹화다. 관련 범위 감사는 `results/step04_legacy_impact_scope.json`에 기록했다.

[20문장·200개 전체 출력](04_문장별_출력.md)에서 성공과 실패 사례를 모두 확인할 수 있다.

## 진행 중 발견한 정답 연결 문제

처음에는 자동 입술 영역의 종횡비·주변 문맥·시간적 안정화를 비교하려 했다. `step04_eval_plan.json`에 직사각형 대조군, 정사각형, 1.5배 주변 영역, 같은 영역의 인과적 EMA(alpha 0.4)를 고정했다. 구현과 테스트를 준비하던 중 C025의 내용 정렬 문제가 발견되어, 이 최초 계획의 추출·추론을 실행하기 전에 보류했다.

C025 제공 좌표·hybrid 출력 10개 중 7개는 목표보다 바로 다음 라벨 문장에 더 가까웠고, 6개는 같은 녹화의 전체 문장 중 다음 문장이 가장 가까웠다. 이는 진단 단서이며, 모델 출력에 맞춰 정답을 다음 문장으로 교체할 근거는 아니다.

| 확인 항목 | C025 A006 | C025 A007 |
|---|---:|---:|
| MP4 영상 길이 | 301.868초 | 302.569초 |
| 마지막 발화 라벨 종료 | 309.419초 | 309.717초 |
| 라벨의 영상 범위 초과 | 7.550초 | 7.148초 |
| 원본 WAV 길이(헤더) | 310.243초 | 310.944초 |
| 원본 WAV와 영상 길이 차이 | 약 8.375초 | 약 8.375초 |

C025 두 영상은 마지막 두 문장의 일부 또는 전부가 MP4 범위를 넘어간다. C294 두 영상은 모든 라벨 발화가 영상 범위 안에 있고 마지막 발화 뒤에 약 3.8초·5.7초의 여유가 있었다. 따라서 네 파일에 공통된 초 단위 반올림으로 설명하기 어렵다.

파일명·화자·카메라·라벨 SHA·프레임 수·프레임 좌표 연결은 맞았다. MP4 네 파일의 edit list는 모두 같은 약 0.0667초의 media 시작값이며 7~8초의 차이를 설명하는 빈 앞부분은 없었다. 기존 실제 FPS 교정만으로 해결되는 문제도 아니다.

### 사용자 청취 확인

평가에 쓰인 C025 `A006_001`의 실제 MP4 시각 10.076733~11.478133초에서 원본 음성만 추출했다. 사용자의 응답은 **“'끝나는 거야' 라고 들림”**이었다. 이 구간의 기존 정답은 “아주 기쁘고 감사해”, 립리딩 출력은 “정말 좋아해”였다. 사용자가 확인한 내용이 두 후보 모두와 다르므로 어떤 출력에도 맞추어 라벨을 바꾸지 않는다. 한 구간의 내용 불일치 확인이며 전체 녹화의 시간 이동량을 확정하는 검사는 아니다.

음성은 **자료의 시간 정렬 검사에만 사용**한다. 립리딩 모델에는 영상만 입력하며 음성을 제공하지 않는다. 외부 음성인식 서비스에 올리지 않았다. 작은 FFmpeg 도구를 별도 폴더에 설치해 WAV 발췌를 만들었고 기존 Python 모델 환경은 바꾸지 않았다.

## 독립적인 시간축 검사

동일 녹화의 원본 WAV 두 개를 기존 inventory에서 찾았다. 각 약 59.6MB, 48kHz·2채널·16bit PCM이다. 전체 원본을 복사하는 대신 앞·중간·뒤의 짧은 파형을 MP4의 음성과 비교하여 이동량과 일관성을 확인했다. 파형 근거를 확보한 뒤 별도 시간 매핑 파일을 만들었고 원본 JSON과 기존 실험 결과는 보존했다.

이후 C294 두 개까지 포함해 네 녹화의 원본 WAV와 MP4 음성을 대조했다. WAV 시각 30·150·270초에서 6초씩 발췌하고, MP4의 ±15초 범위에서 같은 파형을 찾았다. 양쪽을 8kHz·mono로 변환하고 100~3,400Hz 대역을 사용해 정규화 교차상관을 계산했다. 이는 발화 인식이나 모델 정답을 이용한 검색이 아니다.

| 녹화 | MP4 시각 − 원본 WAV 시각 | 세 앵커 최저 상관계수 |
|---|---:|---:|
| C025_A_006 | **−8.362초** | 0.99936 |
| C025_A_007 | **−8.362초** | 0.99926 |
| C294_A_001 | **+0.046375초** | 0.99700 |
| C294_A_003 | **+0.046375초** | 0.99605 |

각 녹화의 세 앵커에서 같은 보정값이 나왔고, 다른 피크보다 최소 약 5.06배 뚜렷했다. 별도 검산에서 24개 발췌 파일의 해시·형식·길이와 12개 시각 계산을 확인했으며, 독립 구현으로 서로 다른 두 화자의 앵커 최고점을 재현했다. 단순 WAV/영상 길이 차이 8.375초를 그대로 빼지 않고 **측정한 파형 차이**를 사용한다.

평가용 매핑은 `영상 시각 = 기존 라벨 시각 + 위 보정값`으로 별도 저장했다. 라벨이 원본 WAV의 시계를 사용한다는 판단은 `Audio_Name`, 48kHz 정보, 길이, 파형 일치와 사용자 청취 확인에 근거한다. **이 검사는 두 오디오 시간축을 연결하며, 모든 문장 전사의 정확성과 입술-음성 동기까지 독립적으로 증명하지는 않는다.** 세 앵커만으로 영상의 모든 위치에 내부 편집이 없다고 보증하지 않는다. 다른 녹화에 이 숫자를 일괄 적용하지 않는다.

이 근거를 확인한 후 새 추론 전 `step04_aligned_eval_plan.json`에 보정값·geometry 코드·동일 20문장·5개 비교 경로를 다시 고정했다. 정답 문자열과 기존 원본 JSON은 변경하지 않았다. 실제 FPS를 이용해 `ceil((라벨시각+보정값)*FPS)`로 프레임을 고르고, 제공 좌표는 해당 **영상 프레임 번호**의 박스를 사용한다. 자동 경로는 교정된 영상에서 같은 검출기를 실행한다. 기존 잘못된 시각의 좌표 추적을 새 구간에 복사하지 않는다.

네 녹화 모두 보정값이 0이 아니므로 3단계와 입력 프레임이 달라진다. 3단계와의 비교는 시간 정렬 개입의 효과이며, 이번 다섯 경로끼리의 비교는 **같은 교정 시각에서** crop 방식의 효과를 분리한다. 새 실험은 계속 개발 검증이며, 최종 성능을 확정하는 test가 아니다.

## 구현한 자동 입술 영역 후보

- `square`: 검출 사각형의 긴 변을 한 변으로 하는 정사각형으로 만든다.
- `context_square`: 정사각형의 한 변을 1.5배로 늘려 주변 영역을 포함한다.
- `stable_context_square`: 같은 영역의 중심과 크기에 현재 0.4·직전 상태 0.6의 EMA를 적용한다. 미래 프레임을 사용하지 않고 발화마다 초기화한다.

영상 경계에서는 정사각형을 이동해 비율을 보존하며, 화면에 들어갈 수 없는 크기는 실패로 처리한다. 원본 직사각형 경로도 대조군으로 보존한다. 정사각형 crop·EMA 자체의 학술적 신규성을 주장하지 않으며, 이 단계의 기여는 명시한 문제에 대한 처리 모듈 설계와 통제된 효과 검증이다. 효과는 위의 동일 조건 비교 결과로만 보고하며 범용 성능이나 신규 신경망의 성과로 확대하지 않는다.

## 검증·재현과 시간 비용

입력 100개 모두 전체 디코딩·파일 해시·정답 ID·시간 경계를 검사했다. 각 조건은 2,574프레임이고 자동 검출은 2,574/2,574 성공했다. 이전 검출 좌표 재사용과 제공 좌표 fallback은 없었다. 5조건의 원본 프레임 해시는 문장마다 같았다. 정사각형/EMA 7,722프레임의 기하 계산을 독립 재계산했으며, 대표 프레임 100장의 입술 표시도 확인했다.

독립 검산은 200개 출력의 문자·어절 편집거리, 화자별/전체 집계, 토큰→문자열, 100개 특징 파일의 유한값·형상·해시와 CTC argmax/중복 제거를 확인했다. 모델을 다시 실행해 유리한 결과를 고르지 않았다. Hybrid 최대 탐색 깊이는 33~139였고 길이 제한 도달은 0개다. geometry 12개·기존 준비 8개·보정 준비 7개로 고유 단위 테스트 27개가 통과했다. 보정 준비 실행 로그의 15개는 기존 준비 8개를 포함하므로 중복 집계하지 않는다.

100개 crop 영상 준비는 약 52.22초였으며 영상 파일 합계는 약 3.11MB다. 이 안의 원본 디코딩 측정 합계는 10.23초, 검출은 15.10초였다. 선택 후보의 GPU 준비 입력→특징 추출+hybrid 시간은 문장당 중앙값 2.73초, 평균 3.34초, 범위 0.78~9.19초였다. CTC 직접 출력은 중앙값 0.111초였지만 CER 41.38%이고 문장 일치는 0/20이다. 측정에는 촬영·발화 종료 대기·crop·전송이 포함되지 않고 첫 호출 예열도 없으므로 실시간 웹캠 지연으로 해석하지 않는다.

ROI는 미래 프레임을 쓰지 않지만, 현재 후보 모델 실험은 정답 발화 경계와 발화 전체 정규화를 사용한다. 따라서 이 모듈의 인과성만으로 전체 시스템이 실시간 스트리밍이라고 주장할 수 없다.

## 다음에 진행할 작업

1. **기존 모델을 보정된 동일 개발 문장에서 다시 평가.** 기존 모델의 69토큰/RGB/25fps 계약과 공식 후보의 72토큰/BGR/native-frame 계약을 각각 지키면서 정답과 실제 발화 구간을 일치시킨다. 이번 결과만으로 이전 모델이 가망 없다고 결론내리지 않는다. 필요 시 시간축을 확인한 소량 자료로 재학습 여부를 판단한다.
2. **기존 학습 자료의 시간축 감사.** 확인한 네 녹화는 별도 매핑으로 관리하고, 다른 녹화는 각자의 원본 WAV/MP4 파형을 확인한다. −8.362초를 전체 파일에 적용하지 않는다. 실제 학습에 사용한 59녹화에서 소수부터 점검하고, 필요 시 전체 96녹화로 넓힌다. 시간 불일치가 확인된 경우 검증된 매핑으로 별도 캐시를 만들고 제한된 재학습을 비교한다. 기존 v4와 가중치는 과거 재현용으로 남긴다.
3. **자동 입력 후보의 독립 검증.** 여기서 고른 주변 영역+EMA 설정을 고정한 뒤 새 화자·실제 웹캠에서 발화 검출, 촬영 조건, 인식과 지연을 확인한다. 반복 사용한 val20은 개발 자료이며 최종 test는 설정 확정 전까지 보존한다. 공개 사전학습 모델과 평가 원본의 중복 여부도 미확인이다.

현재 단계에 새 대용량 학습 데이터는 필요하지 않았다. 후속 점검에서 원본 WAV가 없거나 독립 화자 자료가 부족한 경우 필요한 파일·이유·최소 용량을 먼저 특정해서 알린다. 이번 정상 파일의 시간 연결 문제는 TS2·TS20·TS200의 잘린 MP4 복구 문제와 별개다.

졸업 프로젝트에서는 공개 모델 출처와 사용 범위를 밝히고, 직접 구현한 시간축 검증·자동 입술 처리·비교 실험·웹캠 시스템을 개발 기여로 구분해 제시할 수 있다. 정사각형/EMA를 새로운 학습 모델로 표현하지 않으며 학과의 인정 여부를 확정하지 않는다.
