# 새 계획 3단계 — 보유 영상 평가 설계의 독립 검토

검토일: 2026-09-24(KST). 이 문서는 실행 결과를 보기 전에 기존 코드·고정 입력 계약·평가 집합 메타데이터를 읽고 작성한 설계 검토다. 신경망 추론, 원본 영상 읽기, 추가 학습은 수행하지 않았다. 실제 결과는 별도 실행 보고서와 원시 JSON에 기록한다.

**보유한 정상 val20으로 제공 bbox 경로와 자동 입술 crop 경로를 비교하는 것은 적절하다. 다만 이 단계는 기존 개발 자료에서의 경로 검증이며, 처음 보는 웹캠 환경의 인식 성능을 증명하지 않는다.**

## 1. 평가 집합과 변경 금지 범위

- `results/step18-intake/run01/protected_reference.json`의 기존 val20 ID와 순서를 그대로 사용한다. 20개는 C025·C294 두 화자, 네 녹화에서 왔다. 2단계 진단 train4와 구분되지만, 이전 6~17단계에서 반복 확인한 개발 집합이다.
- 기존 manifest와 공개 가중치의 사전학습 분할은 같다고 확인되지 않았다. “기존 자체 학습에 없던 화자”와 “공식 모델이 처음 보는 화자”를 구분한다. 공개 사전학습 중복 여부는 불명으로 기록한다.
- `reference_profile_96_v1.json`의 공식 가중치·72토큰·96px BGR·전체 발화 평균/표준편차(correction=1)·수정 hybrid·beam 1·CTC 0.6·max_len 200·종료 규칙을 고정한다. 3단계의 시간 선택 어댑터는 아래 메타데이터 검토에 따라 **결과를 보기 전에 native CFR 시각 기준으로 일률 변경**한다. 2단계 원본 profile은 보존하고 변경 계약을 별도로 잠근다. 정답이나 이번 출력으로 설정을 선택하지 않는다.
- 두 경로는 같은 원본 프레임 범위, 동일한 resize/압축/색상/정규화/검색을 사용한다. 변경 요인은 입술 crop 경로다. 이전 25fps RGB·ImageNet 정규화 캐시를 새 모델 입력으로 쓰지 않는다.
- test50은 자동 경로와 오류 처리 검증이 끝날 때까지 보존한다. 최종 평가 전에 실행 가능한 설정·수용 기준을 고정하고, test50 결과를 보고 설정을 반복 고르지 않는다. 최종 평가를 수행해도 공개 사전학습 중복 불명이라는 한계는 남는다.

## 2. 제공 bbox와 자동 crop의 비교가 뜻하는 것

기준 경로는 공식 방식의 프레임별 라벨 bbox를 여백 없이 사용한다. 자동 경로는 MediaPipe 외측 입술 20점과 상하좌우 20% 여백을 사용한다. 따라서 이 비교는 **검출기, 박스 정의, 여백, 프레임별 흔들림이 함께 달라지는 전체 crop 경로 비교**다. 자동 경로가 나쁘다고 검출 누락만 원인이라고 단정하거나, 제공 bbox를 참 정답 입술 형태라고 단정하지 않는다.

자동 경로는 다음을 명시적으로 고정해야 한다.

1. MediaPipe 버전, 모델/Face Mesh 설정, 얼굴 선택 규칙, 검출용 너비 640, 보간법과 좌표 반올림 규칙을 기록한다. 축소 영상에서 검출한 좌표로 원본을 자르는지, 축소 영상 자체를 자르는지도 명시한다.
2. 각 발화에서 추적기를 새로 시작한다. 발화 간 마지막 박스를 전달하지 않는다. 검출기에는 RGB를 넣되 신경망에는 고정된 BGR 입력을 넣는다.
3. 일시적 누락에는 그 발화의 이전 유효 박스를 현재 프레임에 적용한다. 아직 이전 박스가 없는 초기 미검출은 실패로 센다. 정답 bbox로 대체하지 않는다. 미검출을 허용하는 최대 연속 프레임 수를 출력 전에 고정한다.
4. 최초·중간·끝 프레임의 제공/자동 crop을 함께 보존해 입술 잘림, 얼굴 선택 오류, 색상 반전, 과도한 확대 등을 시각 확인한다. 시각 확인 후 임의로 해당 문장만 고치면 최초 결과와 수정 진단을 분리한다.

기존 `backend/preprocessing/roi_extractor.py`의 구현은 초기 누락을 나중의 최초 ROI로 back-fill하며, 누락 프레임에는 이전 **ROI 픽셀**을 복제한다. 이번 인과적인 이전 **박스** 정책과 동일하지 않다. 따라서 이번 자동 평가를 기존 서비스 전처리의 완전한 재현이라고 설명하면 안 된다. 서비스 코드 교체도 이번 설계 검토 범위가 아니다.

## 3. nominal 30fps 편차와 사전 결정한 시간 선택 정정

2단계 기준은 공식 코드처럼 `[int(start×30), int(end×30))` 프레임을 선택한다. 원본의 약 29.970fps와 차이가 있어 녹화 뒤쪽으로 갈수록 실제 영상 시각이 늦어진다. 두 crop 경로에 동일하게 적용하면 비교의 공통 조건은 유지되지만, 텍스트 오류에는 잘못된 발화 경계도 영향을 줄 수 있다.

기존 `aihub_timed_v4/manifest.json`의 val20 메타데이터만 재계산한 결과는 다음과 같다. 실제 프레임 PTS를 새로 측정한 결과는 아니다.

| 항목 | 메타데이터 기반 결과 |
|---|---:|
| 발화 시각 범위 | 10.069~249.216초 |
| 발화 길이 범위 | 1.408~7.125초 |
| 총 라벨 발화 길이 | 약 85.839초 |
| nominal 선택 경계 − 원래 라벨 경계 | −22.7~+233.2ms |
| 시작 또는 끝 편차가 100ms를 넘는 발화 | 8/20 |

편차 식은 `int(t×30) / native_fps − t`다. 1~2단계의 앞부분 네 클립보다 편차가 크다. 검토 결과 root는 **val20 출력을 보기 전에** 20개 전부를 `start <= frame_index/native_fps < end`로 선택하기로 결정했다. 프레임 인덱스는 `ceil(start×native_fps−1e−9)`부터 `ceil(end×native_fps−1e−9)` 직전까지다. 두 crop 경로에는 같은 실제 프레임을 사용한다. 이번 단계에서 nominal/native 정확도 대조를 추가하지 않으며, 2단계 결과와의 단순 차이를 모델 변화 효과로 설명하지 않는다.

원래 nominal 선택과 정정된 native 선택의 시작·끝 인덱스 및 경계 편차를 모두 기록한다. 현재 계산은 고정 프레임율(CFR)의 `index/fps` 모델이며, 실제 PTS 전수 검사나 가변 프레임율(VFR) 처리를 검증한 것은 아니다. 원본 FPS/프레임 수, 선택 범위, 읽힌 프레임 수, 디코딩 실패, 원본/라벨 해시 및 선택 crop 해시를 기록한다. 불연속 프레임을 이어붙이거나 일부만 디코딩된 발화를 정상 입력으로 처리하지 않는다. 결과가 좋은 문장에만 다른 경계를 적용하지 않는다.

## 4. 실패를 포함한 지표

주 지표는 20개 전부를 분모로 유지한다. 읽기 실패·초기 검출 실패·연속 미검출 초과·추론 실패는 사유를 남기고 예측을 빈 문자열로 처리한다. 따라서 해당 정답의 전체 문자와 단어가 삭제 오류로 반영되며, 문장 완전 일치에서 실패한다. 성공한 문장만 남겨 산출한 CER를 전체 성능처럼 제시하지 않는다.

- CER: 모든 발화 편집거리의 합 / 모든 정답 문자 수의 합. 문장별 CER의 단순 평균과 구분한다.
- WER: 공백으로 분리한 어절 편집거리의 합 / 정답 어절 수의 합. 한국어 형태소 단위 오류율이 아니라고 표시한다.
- 완전 일치: 동일한 정규화 조건에서 문자열이 완전히 같은 발화 수 / 20.
- 출력 정규화: **strip-only를 주 지표**, NFC·공백 정규화를 보조 지표로 잠그고 두 정의를 함께 남긴다. strip-only는 내부 공백을 합치지 않는다. NFC 사용 여부도 코드와 결과 schema에 명시한다. 자동 맞춤법 교정·정답 기반 후처리를 넣지 않는다.
- 원본 라벨 문장과 기존 정제 정답을 모두 보존한다. 이번 정답은 기존 manifest의 문장부호가 정리된 텍스트이며, 원문 구두점 복원 능력을 평가하는 지표가 아니다. 현 정제 정답은 총 667문자(내부 공백 포함), 189어절이다.
- 검출은 직접 검출 프레임, 이전 박스 사용 프레임, 초기 실패, 연속 누락 최댓값, 발화 실패를 나눠 기록한다. 제공 bbox 경로와 자동 경로의 동일 발화별 오차 차이를 보존한다.

독립 재계산에서 ID 집합·순서·20개 분모·각 정답·편집거리·완전 일치·집계 합을 대조한다. 표본이 두 화자의 상관된 발화 20개뿐이므로 “일반 사용자 인식률”이나 통계적으로 확정된 모델 우열로 표현하지 않는다.

## 5. 출력 길이·검색 수치 안정성

`max_len=200`은 200개 한글 음절이 아니라 SOS 공간과 종료 토큰을 포함하는 검색 버퍼다. 현재 수정 어댑터는 최대 인덱스 199까지 탐색하며 최종 반환은 SOS를 제외하고 EOS를 포함한다. val20 정제 정답의 자모·공백 토큰은 19~128개여서 정답 자체가 이 한도를 넘지는 않는다.

출력 원시 토큰, 반환 길이, EOS 위치, PAD/blank 특수 토큰, 완성 전 자모 문자열과 최종 문자열을 보존한다. `selected_length`만으로는 검색이 199회 상한에 도달했는지 알 수 없다. 비침습적인 호출 계측으로 마지막 검색 길이·종료 이유를 기록하는 것이 좋다. cap에 도달한 결과도 누락하지 않는다. 모델 특징·CTC/attention 확률·반환 토큰을 가능한 범위에서 유한성/범위 검사한다.

2단계에서 남겨 둔 blank 진행 허용, upstream CTC prefix 확률/EOS 점수, 종료 휴리스틱은 이번에도 유지된다. 긴 발화의 수치 불안정이나 반복 출력이 발견되면 문장별 실패와 함께 후속 진단 항목으로 남기며, 이번 결과를 보고 검색 정책을 몰래 바꾸지 않는다.

## 6. 시간과 웹캠 목표의 관계

GPU 측정 전후 CUDA 동기화를 하고 최초 호출과 반복 호출을 구분한다. 신경망 인코더·디코더, CPU 입력 준비, 입술 검출, 파일 읽기 시간을 구분한다. 중앙값·최댓값을 기본으로 제시하고 표본 20개의 p95를 쓰면 산출 규칙을 명시한다. 실패 호출의 경과 시간도 보존하되 성공 추론 시간 분포와 혼합하지 않는다.

Google Drive 원본 읽기 시간은 캐시 상태와 네트워크 영향을 받으므로 모델 지연이나 웹캠 지연으로 부르지 않는다. 이번 실험은 라벨로 발화 시작·종료를 알고 전체 발화를 준비한 뒤 추론한다. 자동 입술 검출을 넣더라도 발화 검출·프레임 누락·브라우저 전송·실시간 자막까지 평가한 것은 아니다. 전체 발화 평균/표준편차 정규화도 마지막 프레임까지 있어야 적용된다.

실행 결과가 좋으면 다음 단계에서 사용자 촬영·시간 기반 샘플링·발화 분리까지 이어진 경로를 확인할 근거가 된다. 나쁘면 crop 분포, 시간 경계, 검색, 화자 차이의 순서로 근거를 나누어 조사한다. 어느 경우에도 이번 평가만으로 테라바이트 추가 다운로드나 대규모 학습이 필요하다고 결론 내리지 않는다.

## 7. 실행 완료 시 확인할 항목

1. 기존 manifest, profile, 가중치, 사전, 수정 검색기의 해시와 val20 ID를 고정했다.
2. 두 경로의 입력 프레임·텍스트 기준이 같고, 실패를 포함해 20개 결과가 각각 존재한다.
3. 자동 crop은 미래 프레임·정답 bbox·음성·정답 문자열을 추론에 사용하지 않았다.
4. 지표를 원시 출력에서 독립 재계산했으며 경계 편차·검출 실패·검색 제한·시간 측정 범위를 보고했다.
5. test50 영상/캐시와 새 학습·웹캠 촬영·서비스 배포를 실행하지 않았다. 필요하면 이후 고정된 별도 계획으로 진행한다.
