# 6단계 이후 제안 — 기존 경량 모델에 시각 특징 전달하기

이 문서는 다음 실험 제안이다. 6단계에서 추가 학습을 실행하거나 서비스 모델을 교체한 결과가 아니다. 59개 녹화의 확정 판정은 [6단계 결과](06_실행결과.md)를 기준으로 삼으며, 매핑이 지지된 원본만 후속 입력에 사용한다.

다음에는 **기존 compact 모델을 유지하면서, 공개 모델이 배운 입술 영상 특징을 학습에 보조적으로 전달하는 비교**를 권한다. 효과는 아직 알 수 없다. 현재 모델을 계속 반복 학습하는 것과 구별되는 가설을 시험하고, 성공 여부를 측정하는 것이 목적이다.

## 이미 했던 작업과 이번에 새로 확인할 점

기존10단계에서는 compact와 잔차 모델을 비교했지만 잔차 모델의 개발 성능 우위는 없었다. 11단계의 정지·순서 섞기·역순 대조에서는 영상의 시간 정보 활용이 부족했고, 12단계에서는 gradient 전달과 실제 가중치 갱신이 확인됐다. 13~14단계에서는 학습 문장을 잘 암기하도록 만들 수 있었으나, 15~17단계에서 새 문장·화자로의 일반화가 충분히 개선되지 않았다. 새5단계에서는 검증 시간만 보정해도 기존 고정 가중치가 회복되지 않았다.

따라서 소수 문장 암기 성공, gradient 존재, 같은 자료의 추가 반복을 다시 확인하는 것만으로 다음 개선을 대신하지 않는다. **다른 모델에서 학습한 시각 표현을 기존 compact에 전달하면 미학습 녹화의 인식이 개선되는가**를 분리해서 살펴본다. 이전의 층별 특징·gradient 계측은 이 특징 전달 학습을 수행한 것이 아니다.

## 비교할 두 조건

| 항목 | A: 기본 학습 | B: 특징 전달 학습 |
|---|---|---|
| 최종 추론 모델 | 기존 compact 3D-CNN+BiLSTM+CTC | 같은 compact 구조 |
| 입력과 정답 | 같은 보정 영상·원래 정답 | 동일 |
| 초기 상태 | 새 무작위 초기화 | A와 정확히 같은 초기 가중치 |
| 학습 목표 | 원래 정답을 맞히는 CTC 손실 | 같은 CTC + 고정 교사의 영상 특징을 따르는 보조 손실 |
| 공개 모델 | 사용하지 않음 | 학습용 특징을 사전 추출할 때만 사용 |
| 추론 시 공개 모델 필요 여부 | 없음 | 없음 |

교사가 예측한 문장을 정답으로 바꾸지 않는다. 기존 모델은69토큰, 공개 후보는72토큰이므로 문자 확률을 곧바로 비교하지 않고 프레임별 시각 특징을 대상으로 한다. 입력의 색상·정규화·프레임 시각도 모델마다 다르므로 각각의 전처리를 지키고 실제 시간 좌표로 특징을 연결해야 한다. 연결용 투영층은 학습에만 쓰고 최종 compact 추론에서는 제거한다.

로컬 코드에서 확인한 연결 후보는 교사의 `model.encoder.front(video)` 출력512차원과 학생의 `projection[2]` 출력256차원이다. 교사 front는 시간축 길이를 유지하므로 native 프레임 특징에서 학생이 실제로 선택한 **같은 원본 프레임 번호**의 행을 가져올 수 있다. 교사 구간이 학생의 최소·최대 선택 번호를 모두 포함하도록 준비해야 하며, 길이 비율만 맞추거나 범위 밖을 임의로 가장자리 값으로 바꾸면 안 된다. 기존11단계 진단 hook은 `detach()`를 사용하므로 학습용 연결에 그대로 쓸 수 없다.

512문장·58,419프레임에 맞춘 교사512차원 FP32 특징의 원시 저장량은 **119,642,112바이트(119.64MB)**다. 파일 헤더·압축률·입력 캐시는 제외한 수치이며 GPU 메모리 측정값이 아니다. 문장별로 교사 특징을 미리 저장하면 반복 학습에서 교사와 학생을 동시에 GPU에 올리지 않아도 된다. 새4단계에 저장한 특징은 encoder 이후 출력이므로 이 front 특징을 대신하지 않는다.

이 실험은 ‘교사 특징을 사용하는 전체 학습 방식’의 효과를 비교한다. 교사의 구조·학습 자료·표현 하나하나의 인과적 효과까지 분리하는 실험은 아니다. 특징을 따라가는 손실이 낮아지는 것만으로 립리딩 성능이 좋아졌다고 판정하지 않는다.

## 분할과 평가에서 지킬 점

17단계의 종료 모델은 이미512문장을 학습했다. 그중 일부를 새 평가용으로 떼어내면서 이 가중치로 초기화하면, 평가 문장을 이미 학습한 문제가 생긴다. 이번 비교에서는 두 군을 같은 **새 초기 가중치**에서 시작한다.

가능한 분할 후보는 감사한59개 중 화자별 사전식 첫 녹화1개씩, 총8개 녹화를 통째로 개발 평가에 남기는 것이다. 메타데이터 기준으로 나머지51개는441문장, 남겨둔8개는71문장이다. 두 집합의 정규화 정답 중복은 없다. 결과를 보고 녹화를 교체하지 않는다. 이71문장도 프로젝트의 과거 개발 과정에 등장했던 자료이므로, 완전히 새로운 최종 시험으로 부르지 않는다.

이 분할은 익숙한8명 안에서 **학습하지 않은 녹화**로의 전이를 비교한다. 최종목표인 처음 보는 화자·실제 웹캠에 대한 일반화를 대신하지 못한다. 별도 개발20문장은 반복 사용한 한계가 있으므로 손실 계수·종료점 선택에 계속 사용하지 않는다. 최종test50도 이 실험의 설정 탐색에 쓰지 않는다. 공개 교사의 사전학습과 AIHub 원본이 겹치는지는 미확인 상태이므로, 최종 확인에는 추후 별도 촬영한 자료가 필요하다.

## 실제 진행 순서

1. **입력과 시간 연결을 준비한다.** 검증된 원본별 이동량을 새 캐시에 적용하고 원래 캐시는 유지한다. 기존 RGB96·25fps 입력과 공개 모델용 입력의 시각을 대조한다. 모든512문장을 한 번에 다시 만들기 전에 소수 입력에서 프레임 연결을 검증한다.
2. **학습용 특징을 소량 추출한다.** 공개 모델을 고정한 상태에서 영상 특징을 추출한다. 반복 학습은 로컬의 작은 특징 캐시를 읽게 한다. GPU 최대 메모리와 실제 처리 시간을 재고 전체 추출·학습 예산을 정한다.
3. **비교 조건을 결과 전에 고정한다.** 분할 ID, 초기 seed, 배치 순서, 종료 횟수, 손실 계수, 특징 층·정렬 방식, 지표를 파일로 고정한다. 짧은 학습 연결 검사에서는 유한한 손실, 학생 갱신·교사 고정, 재시작 재현을 확인한다. 이 연결 검사는 인식 성능 결과로 사용하지 않는다.
4. **같은 예산으로 A/B를 학습한다.** 가능하면 서로 다른 seed2개에서 짝지은 비교를 한다. 정해진 종료점의 전체 완성형 문자 CER, 문장 완전 일치, 화자·녹화별 변화와 계산 비용을 함께 보고한다. 정지·순서 섞기 대조는 종료 시의 보조 분석으로 한 번 수행한다.
5. **후속 방향을 결정한다.** 두 seed에서 개선 방향이 일관되고 실제 문자열도 좋아지면 학생 모델의 전달 효과를 더 검증한다. 결과가 불분명하면 개발20문장에 맞춰 손실 계수를 반복 조정하기보다, 이번 가설의 제한을 기록하고 새 화자·촬영 환경의 자료 확보로 넘어간다. 적은 seed의 결과에 통계적 확실성을 과장하지 않는다.

처음 입력·특징 연결을 준비하는 데에는 보유 자료를 사용할 수 있다. 새 화자 자료나 기존에 없는 원본이 필요해지는 경우 파일명·용도·필요 용량을 먼저 특정한다. AIHub 전체 테라바이트 자료를 내려받는 것을 이 실험의 선행 조건으로 삼지 않는다.

## 졸업 프로젝트에서 설명할 수 있는 작업

원본별 시간 매핑 검증, 영상 전처리·특징 시각 연결, 기존 경량 모델 학습 코드, 공정한 대조 실험, 학습과 추론의 자원 측정이 본 프로젝트에서 수행할 작업이다. 특징 증류 자체를 새 알고리즘이라고 주장하지 않으며 공개 모델의 출처와 의존성을 밝힌다. 실제 웹캠 자막 프로그램으로 연결하는 작업과 사용자 촬영 평가도 별도로 남는다. 학과의 인정 여부는 아직 안내된 기준이 없어 보장할 수 없다.
