1. 주제 선정 배경 및 필요성

음성을 이용한 의사소통과 텍스트 입력은 일상에서 널리 사용되지만, 주변 소음이 크거나 소리를 내기 어려운 상황에서는 활용에 제약이 있다. 또한 발성이 어렵더라도 입술을 움직일 수 있는 사용자를 위해서는 음성 외의 정보를 활용하는 의사소통 보조 방식이 필요하다. 이에 본 프로젝트는 카메라로 관찰한 입술 움직임을 한국어 텍스트로 변환하는 시각 기반 의사소통 인터페이스의 구현 가능성에 주목하였다.

‘Silent Talk’는 마이크나 음성 신호를 인식 입력으로 사용하지 않고, 웹캠 영상에서 추출한 입술 영역의 시간적 변화를 분석하여 발화 내용을 추정하는 시스템이다. 별도의 전용 입력 장치 대신 웹캠과 웹 브라우저를 활용함으로써, 사용자가 접근하기 쉬운 형태의 시연 환경을 마련하고자 한다. AI Hub의 한국어 립리딩 데이터를 기본 학습 자료로 활용하고, 영상 전처리와 딥러닝 모델, 한글 출력 처리, 웹 서비스 연동을 하나의 흐름으로 구성한다.

입모양만으로 발화 내용을 추정하는 과정에는 유사한 입모양의 구별, 화자별 움직임 차이, 조명과 촬영 각도의 변화 등 해결해야 할 문제가 있다. 특히 일반 발화 영상에서 음성을 사용하지 않는 조건과, 실제로 소리를 내지 않고 입만 움직이는 조건을 구분하여 평가할 필요가 있다. 따라서 본 프로젝트는 자유로운 한국어 대화 전체의 인식을 단기간에 보장하기보다, 정면의 단일 화자와 데이터가 확보된 제한된 발화 범위에서 실제 무음 인식 가능성을 검증하고 단계적으로 개선하는 방향으로 추진한다.

1학기에는 기획·설계 문서와 영상 전처리, 기본 인식 모델, 업로드·웹캠 인터페이스 등 개발 기반을 마련하였다. 2학기에는 이를 바탕으로 데이터와 정답의 대응 관계, 학습·추론 전처리의 일관성, 실제 웹캠 무음 발화에 대한 성능을 집중적으로 검증하고자 한다. 이를 통해 화면과 기능을 연결하는 단계에서 나아가, 어떤 조건에서 얼마나 정확하게 작동하는지 설명할 수 있는 결과물을 완성하고자 한다.


2. 프로젝트 운영 목표

○ 정성적 목표

[2026-1학기 진행 성과]

① 프로젝트 기획 및 시스템 설계 기반 마련
입술 영상으로 한국어 텍스트를 추정하는 시스템을 기획하고, 기능명세·화면명세·데이터 관리 방안을 포함한 설계 문서를 작성하였다. 백엔드, 프론트엔드, 데이터 처리 및 학습 스크립트를 구분한 프로젝트 구조를 구성하고, 영상 입력부터 전처리·추론·결과 표시까지의 개발 흐름을 정리하였다.

② 영상 전처리와 초기 학습 데이터 준비
영상 프레임을 25fps 기준으로 재구성하고, MediaPipe를 이용하여 입술 영역을 추출한 뒤 96×96 크기의 RGB 영상으로 가공하는 전처리 코드를 구현하였다. AI Hub 라벨의 문장별 시작·종료 시각과 정답 문장을 연결하는 데이터 준비 및 일괄 처리 스크립트를 작성하였다. 현재 초기 학습용 폴더에서 문장 클립 캐시 180개가 확인되어, 반복적인 학습 실험에 활용할 수 있는 기초 자료를 마련하였다.

③ 한국어 립리딩 기본 모델 및 학습 코드 구현
LipNet 구조를 참고한 3D-CNN·양방향 LSTM·CTC 기반 모델과 한국어 자모 인코딩, CTC 빔 탐색, 자모를 한글로 조합하는 기본 디코더를 구현하였다. 학습·검증 데이터 분리, 검증 문자 오류율 확인, 모델 가중치 저장 및 불러오기 기능을 마련하여 모델 실험을 수행할 수 있는 구조를 구성하였다.

④ 영상 업로드 및 웹캠 인터페이스 구현
FastAPI 기반 영상 업로드·추론 요청·진행 상태 조회 기능과 React 기반 업로드·결과 화면을 구현하였다. 결과 화면에는 구간별 시간 정보, 텍스트 및 전체 복사 기능을 구성하였다. 웹캠 입력, 브라우저 내 입술 영역 추출, 입 움직임 기반 발화 구간 감지, WebSocket 전송, 자막 표시를 위한 인터페이스와 연동 코드도 마련하였다.

⑤ 기능 검증 및 운영 관리 기반 마련
전처리, 모델·디코더, API, 작업 상태 관리, WebSocket 처리 등에 대한 단위·통합 테스트 코드를 작성하였다. 문자 오류율(CER)과 어절 오류율(WER), 처리시간 등을 산출하고 CSV·그래프로 저장하는 별도 평가 스크립트를 구현하였다. 업로드 파일의 형식·크기·길이 검사, 임시 영상 삭제, 카메라 권한 및 연결 오류 안내도 개발하였다.

현재까지의 성과는 인식 시스템을 구성하는 코드와 초기 데이터 준비 기반을 확보한 데 있다. 실제 무음 발화의 인식률, 새로운 화자에 대한 성능, 실시간 자막 지연은 별도 실측이 필요하므로, 2학기에 검증할 핵심 과제로 설정한다.

[1학기 이후 연속개발 사항 — 2026년 7월 기록]
현재 폴더에는 1학기 이후의 추가 개발 내용도 포함되어 있다. 7월에는 긴 문장을 위한 가변 길이 학습 처리와 CTC 정렬 조건 검사를 보완하고, 길이가 비슷한 자료끼리 묶는 배치 구성 및 학습 안정화 기능을 추가하였다. 라벨에 제공된 입술 좌표를 이용하는 전처리 경로와 영상·라벨의 회전 방향을 맞추는 처리도 구현하였다. 이 내용은 1학기 성과와 구분하여 2학기 시작 전의 연속개발 기반으로 활용한다.

[2026-2학기 계획 및 목표]

① 실제 웹캠 무음 발화 인식 검증
웹캠 기반 인식을 최종 필수 산출물로 설정하고, 정면의 단일 화자가 소리를 내지 않고 발화한 영상을 텍스트로 변환하는 흐름을 검증한다. 인식 대상 문장은 실제 확보된 데이터의 문장별·화자별 분포를 확인한 뒤 선정한다. 영상 업로드 기능은 모델과 전처리의 오류를 확인하는 중간 검증 수단으로 활용한다.

② 데이터 및 한국어 출력 처리 개선
영상 구간과 정답 문장의 대응 관계를 점검하고, 학습·검증·평가 자료를 화자와 원본 촬영 단위로 구분한다. 입술 영역의 위치·크기·색상·프레임 간격을 비교하여 학습 자료와 웹캠 입력 사이의 차이를 줄인다. 겹받침, 띄어쓰기, 비정상 자모열 등 한국어 출력 규칙을 보완하고 평가 시 적용할 텍스트 정규화 기준을 확정한다.

③ 인식 모델과 평가 기능 고도화
소수의 정상 샘플로 학습 경로를 먼저 점검하고, 검증된 자료를 점진적으로 확대하여 기본 모델의 성능을 측정한다. 오류 원인을 분석한 뒤 데이터 정제, 전처리 조정, 디코딩 개선 또는 모델 변경 중 효과가 확인되는 방법을 적용한다. 평가 API를 실제 평가 스크립트와 연결하고, 실측 결과를 모델 버전 및 평가 조건과 함께 저장한다.

④ 발화 구간 처리와 시연 안정성 개선
발화의 시작·종료 구간을 명확히 지정하는 검증부터 수행한 뒤 자동 발화 감지로 확장한다. 입술 랜드마크와 감지 기준을 점검하고, 발화 앞부분이나 종료 부분이 누락되지 않도록 처리한다. 웹캠 프레임 수집 주기, 전송 청크, 최종 자막 확정 절차를 정리하여 누락·중복·지연 문제를 개선한다.

⑤ 사용 가능 범위와 한계의 명확한 제시
AI Hub 평가 자료, 웹캠 일반 발화, 실제 무음 발화, 비발화·얼굴 미검출 조건을 구분하여 평가한다. 인식이 어려운 입력에는 불확실 또는 검출 실패 상태를 안내하고, 결과 보고서에 적용 가능한 환경과 남은 과제를 제시한다. 부가적인 저장 기능이나 중간 자막 고도화는 핵심 인식 기능을 검증한 이후에 추진한다.

1) 깃허브 활동(팀원 전원)

3. 프로젝트 운영방법 및 세부내용

○ 프로젝트 운영 방법

① 기존 결과물 점검과 완료 기준 구체화
기획·설계 문서와 현재 구현 코드를 대조하여 이미 구현된 기능, 추가 검증이 필요한 기능, 이번 학기 후순위 기능을 정리한다. 지정 문장 인식과 자유 발화 인식을 구분하고, 최종 완료 기준을 ‘실제 무음 웹캠 시연과 그 결과에 대한 객관적 평가’로 구체화한다.

② 데이터 점검과 재현 가능한 실험 구성
AI Hub 영상과 JSON 라벨을 문장별 시간 정보에 따라 대응시키고, 입술 크롭 결과와 정답 문자열을 표본 점검한다. 화자와 원본 촬영 단위로 데이터 분할 목록을 작성하며, 같은 발화의 다른 각도 영상이 학습과 최종 평가에 섞이지 않도록 관리한다. 실제 웹캠 일반 발화와 무음 발화를 별도로 수집하여 촬영 환경과 발화 방식에 따른 차이를 비교한다.

③ 원인 분석에 따른 단계적 개선
영상·라벨 대응, 한국어 인코딩·복원, CTC 입력 길이, 전처리 일관성을 먼저 확인한다. 이후 학습 자료 확대와 모델·디코딩 개선을 수행하고, 변경 전후 성능을 같은 기준에서 비교한다. 각 실험의 데이터 목록, 모델 설정, 가중치 버전 및 측정 결과를 연결하여 기록한다.

④ 웹캠 통합 검증과 오류 대응
수동으로 발화 구간을 지정하는 방식으로 모델 인식 경로를 우선 확인하고, 이후 자동 발화 감지와 전송 절차를 통합한다. 얼굴 없음, 발화 없음, 인식 불확실, 카메라 권한 거부 및 연결 중단을 구분하여 안내한다. 지연시간은 발화 종료 감지, 전송·대기, 추론·디코딩, 화면 표시 구간을 나누어 측정한다.

⑤ 지도·협업 및 결과 정리
주간 회의에서 진행 상황과 미해결 문제를 공유하고, 지도교수와 참여기업의 의견을 우선순위에 따라 반영한다. 코드 검토와 실험 기록을 병행하여 변경 이유를 남기며, 최종적으로 시제품·시연 영상·평가 보고서·실행 안내서를 하나의 결과물로 정리한다.

지도교수: 연구 범위와 평가 방법 검토, 중간 결과 분석 지도, 최종 결과물 검토.

4. 기대효과 및 활용방안

○ 음성 외의 의사소통 보조 수단 제시
웹캠으로 관찰한 입술 움직임을 텍스트로 제시함으로써, 소음이나 발성 제약이 있는 상황에서 활용할 수 있는 의사소통 보조 방식의 가능성을 확인할 수 있다. 발성이 어렵지만 입술 움직임이 가능한 사용자나 시각적 텍스트 안내가 필요한 사용자를 위한 후속 연구의 기초로 활용할 수 있다. 실제 적용 범위는 무음 발화 평가 결과와 사용자 검토를 바탕으로 구체화한다.

○ 제한된 업무·안내 상황의 무음 입력 인터페이스로 활용
정해진 요청이나 응답을 주고받는 안내 업무, 키오스크 명령 입력, 실습 환경의 짧은 지시 전달 등 제한된 문장 범위의 사용 시나리오에 적용 가능성을 검토할 수 있다. 초기에는 입술을 관찰할 수 있는 정면의 단일 화자 환경에서 시연하고, 참여기업의 의견에 따라 필요한 표현과 화면 구성을 조정한다. 범용 의사소통 서비스로 확대하기 전에는 사용 환경별 성능과 오인식 대응을 추가 검증한다.

○ 한국어 시각 음성인식 실험 기반 확보
문장 단위 데이터 준비, 입술 영역 전처리, 한국어 자모 처리, 모델 학습·추론, 성능평가를 연결한 개발 기반을 확보할 수 있다. 데이터·설정·모델 버전과 평가 결과를 함께 관리하면 후속 팀이나 연구자가 동일한 조건에서 개선 효과를 비교하는 데 활용할 수 있다. 입술 주변의 더 넓은 얼굴 영역 활용이나 개인별 적응 학습 등은 기본 성능을 확인한 뒤 후속 실험으로 확장할 수 있다.

○ 데이터 처리와 사용자 안내를 고려한 시제품 개발 경험 축적
음성 입력 없이 입술 영역 중심으로 처리하고, 웹캠 원본 영상 미저장 및 업로드 임시 파일 삭제 기능을 적용하는 과정에서 필요한 데이터만 다루는 서비스 설계를 경험할 수 있다. 인식 실패와 불확실한 결과를 사용자에게 알리는 방식을 함께 검토하여, 출력 문장과 점수를 무조건 신뢰하도록 만드는 문제를 줄이고 실제 사용 가능한 안내 방식을 모색한다.

○ 전공 역량과 산학협력 경험 강화
컴퓨터비전, 시계열 딥러닝, 한국어 텍스트 처리, 웹 서비스 구현을 통합적으로 경험하고, 실험 결과를 근거로 문제를 분석하는 역량을 높일 수 있다. 지도교수 및 산업체와 요구사항·사용성·평가 결과를 논의하고 그 의견을 구현에 반영함으로써 협업과 문서화 역량을 강화한다. 최종 시제품, 성능평가 보고서 및 시연 영상은 졸업과제 발표와 후속 연구·포트폴리오 자료로 활용할 수 있다.
