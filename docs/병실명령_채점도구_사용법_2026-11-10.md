**봉인 자료(P02, `ward_eval`)**
- 모든 도구가 기본으로 거부합니다. `calibrate`는 어떤 옵션으로도 받지 않습니다(봉인 폴더는 `--sealed-folder`로 목록 지문만 계산).
- 나머지 도구는 `--allow-sealed --freeze <동결 파일>`이 함께 있어야 실행됩니다. 동결 파일이 git에 커밋됐고, 커밋 뒤 바뀌지 않았고, `status`가 `frozen`이고, 합성 자료가 아닌지를 **클립 기록·특징을 읽기 전, 서버·모델을 부르기 전에** 확인합니다. `--freeze` 없는 `--allow-sealed`는 거부합니다. 서버 등록(`--enroll-profile`)을 써도 이 규칙은 같습니다.
- 각 출력 파일 머리에 동결 파일의 SHA-256·커밋, 실행 때 git HEAD, 만든 시각이 남습니다. `ward_enroll.py`의 다음 단계는 앞 단계 출력이 같은 동결 파일로 만들어졌는지 확인합니다.
- `report`는 봉인 자료일 때 다음을 모두 확인합니다: 동결 파일 조건(위와 같음), 결과 행·등록 파일이 **이 동결 파일로**(SHA-256 일치) **동결 커밋 뒤에**(실행 때 git HEAD가 동결 커밋과 같거나 그 뒤, 만든 시각이 커밋 시각보다 뒤) 만들어졌는지, 촬영 폴더 목록 지문이 동결 파일의 `sealed_folders` 값과 같은지.
- 봉인 참가자는 `P02`·` p02 `·`P2`처럼 적혀도, 봉인 묶음은 `WARD_EVAL`·`ward_eval2`처럼 적혀도 걸립니다.

## 2. 판정 규칙 (기획 9.3, 화면과 같게)

| 결과 | 조건 |
|---|---|
| 빨간 카드 | 글자 규칙(1·2등 차이 ≥ M, 1등 점수 ≥ S) 통과 + 긴급 명령(W02·W03·W04·W10) |
| 일반 요청 | 글자 규칙 통과 + 일반 명령, 또는 글자 규칙 실패·등록 거리 ≤ D·글자 1등 = 등록 1등 + 일반 명령(글자 2등이 긴급이 아닐 때, 하한이 있으면 2등 긴급 점수가 하한 미만일 때도) |
| 긴급 가능성 | 글자 규칙 실패·등록 거리 ≤ D·글자 1등 = 등록 1등 + 긴급 명령, 또는 등록으로 고른 일반 명령인데 글자 2등이 긴급 명령(하한이 있으면 그 점수 이상), 또는 고르지 못했는데 글자 1·2등에 긴급 명령(하한이 있으면 그 점수 이상), 또는 고르지 못했는데 거리 ≤ D인 등록 1등이 긴급 명령 |
| 고르지 않음 | 그 밖. 글자 규칙 실패·등록 거리 ≤ D인데 글자 1등과 등록 1등이 다르면 고르지 않습니다 |
| 지정 문장 결과 없음 / 발화 없음 / 입술 검출 실패 | 창이 여럿·일부 검출 실패·정렬 불가·병실 묶음이 아닌 결과 / 모든 창이 [발화 없음] / 모든 창이 표시이고 그중 검출 실패가 있음 |

- **등록은 알림을 더하기만 하고 없애지 않습니다.** 등록으로 일반 명령을 골라도 글자 2등이 긴급이면 등록 없이 나던 긴급 가능성 카드를 그대로 보냅니다(고른 명령이 후보 맨 앞, 카드에 "등록한 입 모양으로 고름"). 같은 하한에서 등록 없는 판정이 긴급(빨간 카드·가능성)이면 어떤 등록 결과에서도 긴급인지 검사가 확인합니다. 그만큼 일반 명령의 거짓 알림이 늘 수 있으며(P01 조정 영상 4클립), 줄이려면 하한(`possible_min_score`)으로 조정합니다.
- **글자 1등 ≠ 등록 1등**은 글자 규칙을 통과하지 못해 등록 거리로 고를 때만 봅니다. 글자 규칙을 통과한 클립은 등록 1등과 달라도 그대로 고릅니다. 등록 1등이 긴급이고 거리가 D 이하이면 고르지 않더라도 긴급 가능성으로 올립니다(기획 11.3: 놓치는 쪽보다 확인하는 쪽). 이 읽는 방법은 동결 파일 `enrollment.conflict_rule`에 적힙니다.
- 서버의 `accepted`는 쓰지 않고 저장된 `margin`·`score`로 다시 판정합니다. 서버 등록의 `within`·`accepted`도 쓰지 않고 서버가 적은 거리(`top_id`·`distance`)와 동결 D로 다시 판정합니다. 대신 다시 판정한 값과 서버 값이 다른 클립 수, 서버가 결과에 적은 기준값(`phrase.rule`)이 동결 값과 다른 클립 수를 보고서에 적고, 하나라도 다르면 보고서 맨 위에 경고합니다(화면은 서버 값을 쓰므로 서버가 동결 기준값으로 켜졌는지 확인하는 용도). 봉인 자료에서 다르면 `report`가 종료 코드 1을 냅니다.
- 화면(`wardResult.js`)과 같게, `phrase.set`이 `ward`가 아니거나(옛 서버·문장 모드 결과) 1등 ID가 명령 목록 밖이면 지정 문장 결과 없음, 2등 ID가 목록 밖이면 2등 없음으로 봅니다. 서버 등록은 `status`가 `ok`이고 `top_id`가 명령 목록 안일 때만 씁니다(등록 미완성·오래된 등록·창 여럿이면 앱처럼 글자 규칙만). 결과 행 파일에 `set`이 `ward`가 아닌 phrase가 있거나 실행 때 명령 목록 SHA-256이 지금과 다르면 `calibrate`·`report`·`metrics`가 아예 거부합니다.
- 화면 판정 검사용 고정 사례(`frontend/tests/fixtures/ward_decision_cases.json`, 66개)를 채점 경로로 판정해도 같은 결과인지 검사가 확인합니다.
- **긴급 가능성 점수 하한**(`possible_min_score`)은 이제 화면이 서버 값(`phrase.rule.possible_min_score`)으로 씁니다. 기본은 없음(null)이고, `calibrate --floor`일 때만 초안에 넣습니다. 초안은 `decision_rule.floor_implemented_in_ui: true`로 만들어지며, 하한이 있는 동결 파일도 형식 검사를 통과합니다(이 표시가 없는 옛 초안에 하한이 있으면 막습니다). `report`의 주 결과는 동결 하한을 적용한 앱 규칙이고, 하한이 있으면 하한 없이 낸 표(1-3)를 비교로 덧붙입니다.
- 축소 목록은 `ward_enroll.py`가 계산한 후보 20개 점수로 그 목록 안에서 다시 순위를 매깁니다. 서비스 결과에는 1·2등만 있기 때문입니다(화면에는 축소 목록이 없어 보조 결과입니다).

## 3. 지표 (기획 10.2)

사람·촬영 묶음별(예: `P01/ward_tune`), 사람별, 전체로 냅니다. 0건은 표본 수와 한쪽 95% 상한(1 − 0.05^(1/n))을 함께 적습니다.

- 실행된 명령 중 오답, 1등 정답, 표시 비율(전체·조건별·자세별), 등록 거리로 고른 표시 수(그중 오답)
- 긴급 명령이 빨간 카드나 긴급 가능성으로 간 수(조건별, 주 결과는 소리 없이)
- 거짓 긴급: 긴급 아닌 명령·함정·말하지 않는 동작·문장 촬영 클립이 빨간 카드나 긴급 가능성으로 간 수. 짧은 긴급 표현(E01~E03)은 넣지 않고 따로 셉니다(긴급으로 가는 것이 바라는 결과).
- 함정·말하지 않는 동작·문장 촬영 클립이 명령으로 표시된 수
- **짧은 긴급 표현이 일반 명령으로 실행된 수: 합격 기준 0**(틀린 요청이 실행된 것, 기획 11.4). 기준 맞추기에서도 1등이 일반 명령인 짧은 긴급 표현은 막아야 할 클립으로 넣습니다(1등이 긴급이면 넣지 않음).
- 말 끝이 녹화 끝 0.5초 안에 닿은 클립: 결과 `end_ms`는 마지막 활성 프레임 + 뒤 여유 0.5초(녹화 끝에서 잘림)입니다. 그래서 `녹화 길이 − end_ms ≤ 50ms`인 클립을 셉니다. 병실 묶음(5초 자동 정지)만 셉니다.
- 9음절 이하 명령(W05·W06·W09·W12·W15)의 발화 창 길이, 처리 시간(업로드 시작부터 결과까지)
- 표 제목마다 등록 거리 출처(서버 등록 몇 개, 오프라인 등록 몇 개, 거리 없음 몇 개)를 적습니다.

## 4. 실제 자료로 확인한 것 (P01·P03 문장 촬영 200클립, phrase_set=ward)

> 11/10 오전 기준 기록입니다. 그때는 화면에 긴급 가능성 하한이 없었습니다. 지금은 화면이 서버 하한을 씁니다(2절).

|---|---|---|

- **"1·2등에 긴급이면 긴급 가능성" 규칙을 그대로 쓰면, 목록 밖 말의 대부분이 간호사실에 긴급으로 갑니다.** 200개 중 124개가 긴급 가능성이었고, 그중 97개는 W10, 25개는 W03 때문이었습니다. W10은 목록 밖 말을 가장 많이 끌어당기는 명령입니다(P01 93개 중 42개가 1등 W10).
- 긴급 가능성 점수 하한을 두면 줄어듭니다(−4.0이면 28개, −3.6이면 12개, −3.4이면 6개). 하한을 쓸지는 11/11 조정용 긴급 명령 영상을 보고 정합니다. `calibrate`는 근거 표에 긴급 명령 클립을 하나도 놓치지 않는 하한에서 여유 0.2를 뺀 값을 참고로 보여 줍니다.
- 서버 `accepted`는 185개 모두 임시 기준으로 다시 판정한 값과 같았습니다. 같은 클립을 `ward_enroll.py`로 오프라인 계산한 후보 점수도 서비스 결과와 185개 모두 같았습니다(1·2등, 점수·차이 최대 차이 0.0).
- 리뷰 반영 뒤 포트 8001 서버로 P03 문장 클립 14개를 다시 보내 저장된 결과와 14개 모두 같음을 확인했습니다. 같은 실행에서 이어 하기, 다른 기준값의 동결 파일을 줄 때 첫 지정 문장 클립에서 멈추기(종료 코드 5), 다른 동결 파일로 이어 하기 거부도 확인했습니다.
- 동결 초안 전체 과정(`calibrate` → `report`)은 합성(가짜) 명령 자료 + 이 실제 목록 밖 자료로 끝까지 돌려 확인했습니다. 합성 자료는 세션 임시 폴더에만 있고, 그 초안은 형식 검사에서 "합성 자료"로 걸려 동결에 쓸 수 없습니다.

- 제안 규칙(미리 정함): 기준값은 합친 맞추기 중 정답 표시가 δ=0의 90% 이상인 가장 큰 δ(`--delta`로 직접 고를 수 있음). 맞추기에서 지키는 것은 표시 중 오답 0, 목록 밖 입력의 명령 표시 0, 짧은 긴급 표현의 일반 명령 실행 0입니다. D는 사람별·합친 값 중 가장 작은 값입니다. 축소 목록은 긴급 4개를 지키고, 혼동에 가장 많이 얽힌 명령부터 빼서 12개로 만듭니다(`--target-size`, `--keep`). 긴급 가능성 하한은 `--floor`를 줄 때만 넣습니다.
- D를 정하지 않는 경우(초안에 `null`과 사유): 막는 거리를 모를 때(등록 거리로 표시되거나 긴급 가능성이 될 나쁜 클립이 하나도 없음), 사람마다 거리가 있는 목록 밖 클립이 50개(`--min-negatives`) 미만일 때, 등록 파일의 템플릿 방식이나 특징·거리 이름이 섞여 있을 때. 동결할 수 있는 D는 서버와 같은 템플릿 방식(`voiced`, 소리 내어 한 번)으로 정한 값뿐입니다.
- `--sealed-folder`는 폴더 안 파일의 이름·크기·SHA-256만 계산합니다(8단계 문서 2절과 같은 형식). 메타데이터 JSON이나 영상은 해석하지 않습니다. 따로 확인하려면 `py -3.11 scripts/ward_eval_tools.py fingerprint "<폴더>"`.
- 사람이 검토해 값을 고친 뒤 `status`를 `frozen`으로 바꾸고, **추적되는 위치**(예: `docs/병실명령_동결_2026-11-11.json`)에 두고 커밋합니다. `experiments/` 아래 JSON은 gitignore라 커밋되지 않습니다.
- **서버 환경 변수 4개**: 동결 파일 `full_list.env`에 `LIPNET_OLKAVS_WARD_MIN_MARGIN`·`_MIN_SCORE`·`_POSSIBLE_MIN_SCORE`·`_ENROLL_MAX_DISTANCE`가 들어갑니다(쓰지 않는 값은 `none`). M·S·하한·D를 손으로 고쳤으면 env도 같게 고쳐야 하며, `validate`가 다르면 막습니다. `py -3.11 scripts/ward_eval_tools.py env <동결 파일>`이 PowerShell 줄로 출력합니다.
- 동결 파일에는 결과 행 파일·등록 파일의 SHA-256, 촬영 폴더 목록 지문, 봉인 폴더 지문, 코드·목록 파일(서버 등록 `ward_profiles.py`·`ward_templates.py`, 화면 판정 `wardMachine.js`·`wardResult.js`, 등록 화면, `frontend/src/ward/` 전체 포함)의 SHA-256, git HEAD가 들어갑니다. 바뀐 파일이 있으면 `report`가 맨 위에 적습니다. 시연 노트북 묶음도 동결 커밋 뒤에 **`py -3.11 deploy\build_bundle.py --freeze <동결 파일> --sample-clips`** 로 다시 만듭니다. 노트북 서버는 `LIPNET_*` 환경 변수를 모두 지우고 켜지므로, `--freeze` 없이 만들면 위 4개 대신 코드 기본값(임시값)으로 시연하게 됩니다. `--freeze`로 만든 묶음은 이 4개로 켜지고 `시연_점검.bat`이 `/health` 기준값과 대조합니다.

## 8. 서버 등록으로 채점하기 (`ward_service_batch.py --enroll-profile`)

| 옵션 | 하는 일 |
|---|---|
| `--enroll-profile ID` | 서버 등록 ID(영문·숫자·`_`·`-` 1~32자, 보통 P번호). `--phrase-set ward`에서만 씁니다 |
| `--enroll-from voiced` | 먼저 등록 영상(병실 묶음, 서 있는 자세, 소리 내어 찍은 1회차 명령, 명령마다 하나)을 모두 `enroll_command=<명령 ID>`로 보내 등록(store)하고, 그다음 나머지 클립을 등록 거리와 함께 채점(match)합니다. 오프라인 `ward_enroll.py`의 `voiced` 템플릿과 같은 클립을 고릅니다 |
| `--enroll-match-only` | 이미 완성된(20/20, `ok`) 등록으로 모든 클립을 채점만 합니다. 등록이 완성되지 않았으면 시작하지 않습니다(종료 코드 6) |
| `--enroll-delete-after` | 모든 클립이 done이면 끝에 서버 등록을 지웁니다. done이 아닌 클립이 남으면 이어 하기를 위해 남깁니다 |

- **새 실행**(출력 파일이 없음)에서는 서버에 그 ID의 등록이 없어야 합니다. 다른 실행이 만든 등록이 있으면 그 위에 다시 저장하지 않고 멈춥니다(종료 코드 6). `--redo`를 주면 그 ID의 등록을 지우고 처음부터 합니다.
- **이어 하기**: 등록 행은 이 출력 파일이 저장한 등록(명령마다 등록 시각)이 서버에 그대로 있을 때만 이어 합니다. 서버에 이 실행이 저장하지 않은 등록이 있거나 시각이 다르면(다른 실행이 바꿈) 멈춥니다. 등록 영상이 모두 done이 되기 전에는 시험 단계를 시작하지 않습니다.
- 시험(match) 행마다 채점 때의 등록 지문(`profile_sha256`: 서버 등록 상태·개수·명령별 등록 시각의 SHA-256)을 남깁니다. 이어 하기에서 등록 지문이 바뀌었으면 그 시험 행을 다시 보냅니다.
- 출력 파일 머리 `enroll`에 등록 ID, 방식, 실행 ID, 실행 전·뒤 등록 상태(상태·개수·지문), 등록 영상 목록, 등록 뒤 상태, 지웠는지가 남습니다. 서버 기준값은 `thresholds_from_health`(`/health`)와 `server_rules_seen`(결과의 `phrase.rule`)에 남습니다.
- 등록 없이 만든 출력 파일을 등록 실행으로(또는 그 반대로) 이어 하지 않습니다. 새 출력 파일을 쓰거나 `--redo`를 줍니다.
- 종료 코드: 0 모두 done, 1 done이 아닌 클립이 남음, 2 시작하지 않음(인자·봉인·파일), 3 서버 준비·기준값 문제, 4 서버가 요청한 묶음·등록을 처리하지 않음, 5 서버 기준값·등록 판정이 동결 값과 다름, 6 서버 등록 상태 문제.
- 서버 등록 거리(`backend/services/ward_templates.py`)와 오프라인 DTW(`scripts/ward_tools/enroll.py`)는 같은 코드이며, 무작위 자료로 같은 거리가 나오는지 검사가 확인합니다.
