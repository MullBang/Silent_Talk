# 병실 명령 채점 도구 사용법 (2026-11-10)

> 병실 무음 도우미 기획 9.5·10절의 채점·기준 맞추기·등록 평가 도구입니다. 세션 임시 폴더에 있던 스크립트를 저장소로 옮겨 일반화했습니다. 서비스 코드, 문장 모드 기준값, 명령 목록은 바꾸지 않습니다.

## 1. 도구

| 파일 | 하는 일 | 실행 환경 |
|---|---|---|
| `scripts/ward_service_batch.py` | 촬영 폴더의 클립을 실행 중인 서버(`POST /api/record`)로 하나씩 보내 결과 행 JSON을 만듭니다. 이어 하기, 실패 1회 재전송, 시작·끝 `/health` 기록. `--freeze`를 주면 클립마다 서버 `accepted`가 동결 기준값과 같은지 보고, 다르면 멈춥니다 | `py -3.11` |
| `scripts/ward_enroll.py` | `roi`(서비스와 같은 입술 추출) → `features`(CTC 직전 특징 + 명령 20개 후보별 점수) → `apply`(내 등록 영상과의 DTW 거리, D가 있으면 판정). `run`은 앞의 둘을 각 가상환경으로 실행 | `roi` .venv-olkavs-roi, `features` .venv-olkavs, `apply`·`run` `py -3.11` |

| `scripts/ward_tools/` | 판정표·지표(`metrics.py`), 기준 맞추기(`calibrate.py`), DTW(`enroll.py`), 한국어 표(`report.py`), 공용·봉인 확인(`common.py`) | — |

**봉인 자료(P02, `ward_eval`)**
- 모든 도구가 기본으로 거부합니다. `calibrate`는 어떤 옵션으로도 받지 않습니다(봉인 폴더는 `--sealed-folder`로 목록 지문만 계산).
- 나머지 도구는 `--allow-sealed --freeze <동결 파일>`이 함께 있어야 실행됩니다. 동결 파일이 git에 커밋됐고, 커밋 뒤 바뀌지 않았고, `status`가 `frozen`이고, 합성 자료가 아닌지를 **클립 기록·특징을 읽기 전, 서버·모델을 부르기 전에** 확인합니다. `--freeze` 없는 `--allow-sealed`는 거부합니다.
- 각 출력 파일 머리에 동결 파일의 SHA-256·커밋, 실행 때 git HEAD, 만든 시각이 남습니다. `ward_enroll.py`의 다음 단계는 앞 단계 출력이 같은 동결 파일로 만들어졌는지 확인합니다.
- `report`는 봉인 자료일 때 다음을 모두 확인합니다: 동결 파일 조건(위와 같음), 결과 행·등록 파일이 **이 동결 파일로**(SHA-256 일치) **동결 커밋 뒤에**(실행 때 git HEAD가 동결 커밋과 같거나 그 뒤, 만든 시각이 커밋 시각보다 뒤) 만들어졌는지, 촬영 폴더 목록 지문이 동결 파일의 `sealed_folders` 값과 같은지.
- 봉인 참가자는 `P02`·` p02 `·`P2`처럼 적혀도, 봉인 묶음은 `WARD_EVAL`·`ward_eval2`처럼 적혀도 걸립니다.

## 2. 판정 규칙 (기획 9.3, 화면과 같게)

| 결과 | 조건 |
|---|---|
| 빨간 카드 | 글자 규칙(1·2등 차이 ≥ M, 1등 점수 ≥ S) 통과 + 긴급 명령(W02·W03·W04·W10) |
| 일반 요청 | 글자 규칙 통과 + 일반 명령, 또는 글자 규칙 실패·등록 거리 ≤ D·글자 1등 = 등록 1등 + 일반 명령 |
| 긴급 가능성 | 글자 규칙 실패·등록 거리 ≤ D·글자 1등 = 등록 1등 + 긴급 명령, 또는 고르지 못했는데 글자 1·2등에 긴급 명령, 또는 고르지 못했는데 거리 ≤ D인 등록 1등이 긴급 명령 |
| 고르지 않음 | 그 밖. 글자 규칙 실패·등록 거리 ≤ D인데 글자 1등과 등록 1등이 다르면 고르지 않습니다 |
| 지정 문장 결과 없음 / 발화 없음 / 입술 검출 실패 | 창이 여럿·일부 검출 실패·정렬 불가·병실 묶음이 아닌 결과 / 모든 창이 [발화 없음] / 모든 창이 표시이고 그중 검출 실패가 있음 |

- **글자 1등 ≠ 등록 1등**은 글자 규칙을 통과하지 못해 등록 거리로 고를 때만 봅니다. 글자 규칙을 통과한 클립은 등록 1등과 달라도 그대로 고릅니다. 등록 1등이 긴급이고 거리가 D 이하이면 고르지 않더라도 긴급 가능성으로 올립니다(기획 11.3: 놓치는 쪽보다 확인하는 쪽). 이 읽는 방법은 동결 파일 `enrollment.conflict_rule`에 적힙니다.
- 서버의 `accepted`는 쓰지 않고 저장된 `margin`·`score`로 다시 판정합니다. 대신 서버 `accepted`와 다시 판정한 값이 다른 클립 수를 보고서에 적고, 하나라도 다르면 보고서 맨 위에 경고합니다(화면은 서버 `accepted`를 쓰므로 서버가 동결 기준값으로 켜졌는지 확인하는 용도). 봉인 자료에서 다르면 `report`가 종료 코드 1을 냅니다.
- 화면(`wardResult.js`)과 같게, `phrase.set`이 `ward`가 아니거나(옛 서버·문장 모드 결과) 1등 ID가 명령 목록 밖이면 지정 문장 결과 없음, 2등 ID가 목록 밖이면 2등 없음으로 봅니다. 결과 행 파일에 `set`이 `ward`가 아닌 phrase가 있거나 실행 때 명령 목록 SHA-256이 지금과 다르면 `calibrate`·`report`·`metrics`가 아예 거부합니다.
- **긴급 가능성 점수 하한**(`possible_min_score`)은 화면(`wardMachine.js`)에 없으므로 기본으로 쓰지 않습니다. `calibrate --floor`로만 초안에 넣고, 그때도 화면에 먼저 넣은 뒤 `decision_rule.floor_implemented_in_ui`를 `true`로 바꾸기 전에는 형식 검사가 동결을 막습니다. `report`의 주 결과는 늘 화면 규칙(하한 없음)이고, 하한을 적용한 결과는 보조 표(1-2)로만 냅니다.
- 축소 목록은 `ward_enroll.py`가 계산한 후보 20개 점수로 그 목록 안에서 다시 순위를 매깁니다. 서비스 결과에는 1·2등만 있기 때문입니다.

## 3. 지표 (기획 10.2)

사람·촬영 묶음별(예: `P01/ward_tune`), 사람별, 전체로 냅니다. 0건은 표본 수와 한쪽 95% 상한(1 − 0.05^(1/n))을 함께 적습니다.

- 실행된 명령 중 오답, 1등 정답, 표시 비율(전체·조건별·자세별)
- 긴급 명령이 빨간 카드나 긴급 가능성으로 간 수(조건별, 주 결과는 소리 없이)
- 거짓 긴급: 긴급 아닌 명령·함정·말하지 않는 동작·문장 촬영 클립이 빨간 카드나 긴급 가능성으로 간 수. 짧은 긴급 표현(E01~E03)은 넣지 않고 따로 셉니다(긴급으로 가는 것이 바라는 결과).
- 함정·말하지 않는 동작·문장 촬영 클립이 명령으로 표시된 수
- **짧은 긴급 표현이 일반 명령으로 실행된 수: 합격 기준 0**(틀린 요청이 실행된 것, 기획 11.4). 기준 맞추기에서도 1등이 일반 명령인 짧은 긴급 표현은 막아야 할 클립으로 넣습니다(1등이 긴급이면 넣지 않음).
- 말 끝이 녹화 끝 0.5초 안에 닿은 클립: 결과 `end_ms`는 마지막 활성 프레임 + 뒤 여유 0.5초(녹화 끝에서 잘림)입니다. 그래서 `녹화 길이 − end_ms ≤ 50ms`인 클립을 셉니다. 병실 묶음(5초 자동 정지)만 셉니다.
- 9음절 이하 명령(W05·W06·W09·W12·W15)의 발화 창 길이, 처리 시간(업로드 시작부터 결과까지)

## 4. 실제 자료로 확인한 것 (P01·P03 문장 촬영 200클립, phrase_set=ward)

포트 8001 서버로 P01·P03의 기존 문장 클립 200개를 병실 목록으로 다시 채점했습니다. 결과: `experiments/ward_negatives_20261110/` (gitignore). 클립당 처리 시간 중앙값은 1.39초(P01), 1.11초(P03)였습니다. 리뷰 반영 뒤 같은 자료로 다시 계산한 값도 같습니다.

| 임시 기준 0.5 / −3.40 | P01 (100) | P03 (100) |
|---|---|---|
| 명령으로 표시 | 2 (빨간 카드 1: A09 2회차 → W10, 일반 요청 1: A06 1회차 → W18) | 0/100 (한쪽 95% 상한 3.0%) |
| 긴급으로 감 (빨간 카드 + 긴급 가능성) | 73 (1 + 72) | 52 (0 + 52) |
| 발화 없음 | 7 | 8 |

- **"1·2등에 긴급이면 긴급 가능성" 규칙을 그대로 쓰면, 목록 밖 말의 대부분이 간호사실에 긴급으로 갑니다.** 200개 중 124개가 긴급 가능성이었고, 그중 97개는 W10, 25개는 W03 때문이었습니다. W10은 목록 밖 말을 가장 많이 끌어당기는 명령입니다(P01 93개 중 42개가 1등 W10).
- 지금 화면은 이 규칙 그대로이므로 채점 도구의 주 결과도 이 규칙으로 냅니다. 긴급 가능성 점수 하한을 두면 줄어들지만(−4.0이면 28개, −3.6이면 12개, −3.4이면 6개), 화면에 하한을 넣기 전에는 동결할 수 없습니다(2절). 하한을 쓸지는 내일 조정용 긴급 명령 영상을 보고 정합니다. `calibrate`는 근거 표에 긴급 명령 클립을 하나도 놓치지 않는 하한에서 여유 0.2를 뺀 값을 참고로 보여 줍니다.
- 서버 `accepted`는 185개 모두 임시 기준으로 다시 판정한 값과 같았습니다. 같은 클립을 `ward_enroll.py`로 오프라인 계산한 후보 점수도 서비스 결과와 185개 모두 같았습니다(1·2등, 점수·차이 최대 차이 0.0).
- 리뷰 반영 뒤 포트 8001 서버로 P03 문장 클립 14개를 다시 보내 저장된 결과와 14개 모두 같음을 확인했습니다. 같은 실행에서 이어 하기, 다른 기준값의 동결 파일을 줄 때 첫 지정 문장 클립에서 멈추기(종료 코드 5), 다른 동결 파일로 이어 하기 거부도 확인했습니다.
- 동결 초안 전체 과정(`calibrate` → `report`)은 합성(가짜) 명령 자료 + 이 실제 목록 밖 자료로 끝까지 돌려 확인했습니다. 기본 설정에서 긴급 가능성 하한은 없고, 등록 거리 D는 정하지 않습니다(실제 문장 촬영 클립에는 아직 병실 등록 템플릿이 없어 거리가 있는 목록 밖 클립이 사람마다 10~12개뿐). 합성 자료는 세션 임시 폴더에만 있고, 그 초안은 형식 검사에서 "합성 자료"로 걸려 동결에 쓸 수 없습니다.

## 5. 11/11 순서 (P01·P03 조정)

```powershell
# 0) 서버 (backend/에서)
py -3.11 -m uvicorn main:app --host 127.0.0.1 --port 8000

# 1) 촬영 폴더 점검 (모델 없음). 병실 촬영 클립은 문장 클립과 다른 폴더여야 합니다.
py -3.11 scripts/pilot_evaluate.py check --clips "<P01 ward_tune 폴더>"

# 2) 서비스 경로 채점 (사람마다)
py -3.11 scripts/ward_service_batch.py --clips "<P01 ward_tune 폴더>" --out experiments/ward_tune_20261111/P01_ward_tune.json --phrase-set ward --expect-clips 93

# 3) 등록 평가 자료 (사람마다 병실 폴더와 문장 폴더 둘 다, apply는 한 번에 같이 넣어야 문장 클립에도 거리가 생깁니다)
py -3.11 scripts/ward_enroll.py run --clips "<P01 ward_tune 폴더>" --out experiments/ward_tune_20261111/enroll/P01_ward_tune
py -3.11 scripts/ward_enroll.py run --clips "<P01 문장 촬영 폴더>" --out experiments/ward_tune_20261111/enroll/P01_sentences
py -3.11 scripts/ward_enroll.py apply --enroll-dir experiments/ward_tune_20261111/enroll/P01_ward_tune --negatives experiments/ward_tune_20261111/enroll/P01_sentences --out experiments/ward_tune_20261111/P01_enroll.json

# 4) 동결 초안 (P01·P03 결과를 모두 넣고, P02 ward_eval 폴더는 지문만)
py -3.11 scripts/ward_eval_tools.py calibrate `
  --tune-rows experiments/ward_tune_20261111/P01_ward_tune.json --tune-rows experiments/ward_tune_20261111/P03_ward_tune.json `
  --negative-rows experiments/ward_negatives_20261110/P01_sentences_as_ward.json --negative-rows experiments/ward_negatives_20261110/P03_sentences_as_ward.json `
  --enroll experiments/ward_tune_20261111/P01_enroll.json --enroll experiments/ward_tune_20261111/P03_enroll.json `
  --sealed-folder "<P02 ward_eval 폴더>" `
  --out experiments/ward_tune_20261111/ward_freeze_draft.json
```

- 초안(`.json`)과 요약(`.md`)이 나옵니다. 요약에는 한 사람으로 정해 다른 사람에게 적용한 결과(양쪽), 합친 맞추기(여유 δ 0~0.3), 임시값 결과, 등록 거리 D(사람별 거리가 있는 목록 밖 클립 수 포함), 참고용 긴급 가능성 하한, 축소 목록에서 뺀 순서, 봉인 폴더 지문이 있습니다.
- 제안 규칙(미리 정함): 기준값은 합친 맞추기 중 정답 표시가 δ=0의 90% 이상인 가장 큰 δ(`--delta`로 직접 고를 수 있음). 맞추기에서 지키는 것은 표시 중 오답 0, 목록 밖 입력의 명령 표시 0, 짧은 긴급 표현의 일반 명령 실행 0입니다. D는 사람별·합친 값 중 가장 작은 값입니다. 축소 목록은 긴급 4개를 지키고, 혼동에 가장 많이 얽힌 명령부터 빼서 12개로 만듭니다(`--target-size`, `--keep`).
- D를 정하지 않는 경우(초안에 `null`과 사유): 막는 거리를 모를 때(등록 거리로 표시되거나 긴급 가능성이 될 나쁜 클립이 하나도 없음), 사람마다 거리가 있는 목록 밖 클립이 50개(`--min-negatives`) 미만일 때, 등록 파일의 템플릿 방식이나 특징·거리 이름이 섞여 있을 때.
- `--sealed-folder`는 폴더 안 파일의 이름·크기·SHA-256만 계산합니다(8단계 문서 2절과 같은 형식). 메타데이터 JSON이나 영상은 해석하지 않습니다. 따로 확인하려면 `py -3.11 scripts/ward_eval_tools.py fingerprint "<폴더>"`.
- 사람이 검토해 값을 고친 뒤 `status`를 `frozen`으로 바꾸고, **추적되는 위치**(예: `docs/병실명령_동결_2026-11-11.json`)에 두고 커밋합니다. `experiments/` 아래 JSON은 gitignore라 커밋되지 않습니다. 서버에는 `full_list.env`의 환경 변수(`LIPNET_OLKAVS_WARD_MIN_MARGIN`·`_MIN_SCORE`)로 넣습니다.
- 동결 파일에는 결과 행 파일·등록 파일의 SHA-256, 촬영 폴더 목록 지문, 봉인 폴더 지문, 코드·목록 파일 19개(화면 판정 `wardMachine.js`·`wardResult.js` 포함)의 SHA-256, git HEAD가 들어갑니다.

## 6. 11/12 P02 평가 (동결 파일 커밋 뒤)

```powershell
# 서버는 동결 기준값으로 켭니다 (full_list.env의 두 값)
$env:LIPNET_OLKAVS_WARD_MIN_MARGIN = "<M>"; $env:LIPNET_OLKAVS_WARD_MIN_SCORE = "<S>"
py -3.11 -m uvicorn main:app --host 127.0.0.1 --port 8000   # backend/에서

$F = "docs/병실명령_동결_2026-11-11.json"
py -3.11 scripts/ward_service_batch.py --clips "<P02 ward_eval 폴더>" --out experiments/ward_eval_20261112/P02_ward_eval.json --phrase-set ward --expect-clips 103 --allow-sealed --freeze $F
py -3.11 scripts/ward_enroll.py run --clips "<P02 ward_eval 폴더>" --out experiments/ward_eval_20261112/enroll/P02_ward_eval --allow-sealed --freeze $F
py -3.11 scripts/ward_enroll.py apply --enroll-dir experiments/ward_eval_20261112/enroll/P02_ward_eval --freeze $F --out experiments/ward_eval_20261112/P02_enroll.json --allow-sealed
py -3.11 scripts/ward_eval_tools.py report --freeze $F --rows experiments/ward_eval_20261112/P02_ward_eval.json --enroll experiments/ward_eval_20261112/P02_enroll.json --allow-sealed --out experiments/ward_eval_20261112/P02_report.json
```

- `ward_service_batch.py --freeze`는 클립마다 서버 `accepted`를 동결 기준값과 대조해, 서버를 다른 기준값으로 켰으면 첫 지정 문장 클립에서 멈춥니다(종료 코드 5).
- `apply --freeze`는 동결 파일의 기준값·D·템플릿 방식을 씁니다. 다른 `--template`이나 봉인 자료에 `--D`를 주면 거부합니다. `report`도 등록 파일의 템플릿 방식·특징·거리 이름·명령 목록이 동결 값과 같은지 확인합니다.
- `report`는 전체 목록(주 결과, 화면과 같은 판정), 등록 적용(오프라인, 소리 내어 1회 등록 → 나머지 시험), 축소 목록(보조)을 따로 냅니다. 동결 뒤 바뀐 코드 파일, 실행 뒤 바뀐 촬영 폴더, 서버 `accepted` 불일치가 있으면 맨 위에 적습니다.
- P02 문장 영상을 목록 밖 자료로 더하려면 그 폴더를 `ward_service_batch.py --allow-sealed --freeze`로 채점해 `--rows`에 더합니다(기준 맞추기에는 넣지 않습니다). 이때 그 폴더의 지문도 동결 때 `--sealed-folder`로 넣어 두어야 `report`가 받습니다.

## 7. 한계

- 기준값·D·축소 목록은 조정 참가자 2명으로 정합니다. 처음 보는 사람은 P02 1명뿐입니다.
- 축소 목록 선택 규칙은 이번에 정한 경험 규칙입니다. 축소 목록은 근사 모드(후보 점수 없음)일 때 기준값을 정하지 않습니다.
- 등록 평가는 같은 날 찍은 영상으로 등록하고 시험합니다. 다른 날·다른 조명의 효과는 모릅니다.
- 동결 커밋 순서 확인은 결과 파일 머리의 git HEAD·만든 시각을 믿습니다. 손으로 머리를 고치는 것까지 막지는 못합니다.
- 서버 두 개를 같은 `backend/`에서 띄우면 나중에 켠 서버가 시작할 때 입술 추출 임시 폴더를 비웁니다. 그때 진행 중이던 클립은 실패할 수 있으며, `ward_service_batch.py`가 한 번 다시 보내고, 다시 실행하면 done이 아닌 클립만 보냅니다.
