# 7단계 완료: 학습 데이터 1,000문장으로 확대

작업일: 2026-09-17

기존 로컬 AI Hub 원본을 사용해 학습 자료를 **80문장 → 1,000문장**으로 확대했다.
이전 150개 표본 전체와 화자 분할은 보존했으며 새 학습 문장 920개만 추가했다.
새 버전은 `data_cache/datasets/aihub_expanded_v3/manifest.json`이다.
이번 단계는 데이터 준비·검수까지 완료한 것이며, 새 데이터로 모델을 학습하거나 인식 성능을 측정한 결과는 아니다.

## 1. 실제 준비 결과

| 용도 | 화자 | 이전 문장 | 새 버전 문장 | 영상 길이 |
|---|---:|---:|---:|---:|
| 학습 train | 8명 | 80 | **1,000** | 4,496.80초, 약 74.95분 |
| 개발 검증 val | 2명 | 20 | 20, 동일 표본 | 85.76초 |
| 최종 평가 test | 5명 | 50 | 50, 동일 표본 | 242.40초 |
| 합계 | 15명 | 150 | **1,070** | 4,824.96초 |

- train: C002, C004, C017, C032, C282, C293, C297, C312. 화자당 정확히 125문장.
- val: C025, C294. test: C138, C281, C334, C428, C558.
- 학습 녹화는 16개에서 96개로 확대했다. 각 화자의 12개 녹화에 고르게 분산했다.
- 학습 문장 1,000개의 정규화 정답은 모두 서로 다르다.
- 학습 길이는 22~200프레임(0.88~8.00초). 25fps, RGB uint8, 96×96, 여백 20% 기준을 유지한다.
- NPZ 전체 용량은 **2,013,025,772바이트, 2.013GB(1.875GiB)**다.
- 준비 프로그램 실행 시간은 약 14.8분이다. 검수 시간은 포함하지 않는다.

공식 Training의 화자를 train/val로 나누고 공식 Validation 5명을 프로젝트 test로 보존했다.
AI Hub 공식 Test 제공분을 확보했다는 뜻은 아니다. test의 파일 무결성만 검사했고 추론·모델 선택에는 사용하지 않았다.

## 2. 선정과 보존 규칙

부모 명세 `aihub_pilot_v2`의 모든 표본을 우선 보존한 뒤 seed=42로 추가 문장을 선정했다.
기존 화자 역할을 다시 무작위 분할하지 않았고, 현재 채택 문장 수가 적은 녹화부터 선택했다.
같은 정규화 정답이나 동일 발화 키는 새로 중복 채택하지 않았다.

기존 train 화자 8명의 후보 3,923개에 대한 처리 내역:

| 구분 | 문장 수 |
|---|---:|
| 기존 train 표본 보존 | 80 |
| 부모 표본과 정답 또는 발화가 겹쳐 제외 | 75 |
| 추가 선정 과정에서 다른 새 표본과 겹쳐 제외 | 59 |
| 이번에 추가 추출 | 920 |
| 목표량 충족 후 미선정 | 2,789 |

미선정 후보 2,789개는 전부 중복 제거·영상 검수를 마친 추가 학습량을 뜻하지 않는다.
val/test 정답은 분할 간 정확히 같은 문장 중복을 막는 용도로만 비교했다. test 성능에 따른 선택은 하지 않았다.
색인 단계에서 제외했던 미지원 문자·길이 초과 등의 기준도 유지했으며 정답을 임의로 바꾸지 않았다.

기존 150개 캐시는 새 폴더로 복사하고 모두 SHA-256 일치를 확인했다. 원본 동영상·라벨·이전 데이터셋·가중치는 유지했다.
확대 버전에는 `require_disjoint_text=true` 정책을 기록해 이후 로더에서도 분할 간 정답 중복을 거부한다.
기존 명세의 동작은 그대로 유지한다.

- 부모 명세 SHA-256: `c2a1699c87e20249e90981fc253d47b0be47793d41b3099b1bcc452c5cbbd427`
- 새 명세 SHA-256: `c89f0fbc870fe60e1ad8e29d7a38ccee2310021958c5b930771371e8ec68f0c4`
- 화자·동일 발화·정규화 정답의 train/val/test 사이 중복: 모두 **0건**.

## 3. 전처리와 검수

선정한 새 문장의 정답·시작/종료 시간·화자·각도를 실제 라벨 JSON과 다시 비교했다.
로컬 라벨 좌표는 y1,x1,y2,x2로 해석하여 xyxy로 바꾸며, 영상을 회전하지 않는다.
원본 MP4는 필요한 문장 구간만 읽고, TAR는 필요한 영상 하나씩만 임시로 꺼내 처리 후 정리했다.
전체 대용량 압축 파일을 다시 풀거나 원본을 복제하지 않았다.

새 문장 **920개 각각의 처음·중간·마지막 프레임, 총 2,760개 표본**을
23개 모음 이미지로 검수했다. 검수한 모든 표본에서 입술이 포함된 것을 확인했으며, 배경·옷의 오크롭이나 회전 오류는 발견하지 않았다. 일부 표본에는 고개 자세와 입술 주변 여백의 변화가 있다.
이는 문장의 모든 프레임이나 음성 전사를 사람이 전수 대조했다는 뜻은 아니다.
전체 프레임의 범위/형상과 라벨·CTC 조건은 자동 검사했으며,
검수 표본의 위치 확인만으로 실제 웹캠 크롭 분포까지 일치한다고 판단하지 않는다.

전 프레임 영상 통계로 단색·거의 정지·대부분 검정/흰색인 클립을 보조 점검했다.
자동 검수 표시 대상은 0개였다. 이 통계는 인식 정확도 지표가 아니다.
총 1,070개 캐시의 해시·원문/토큰 정합·프레임 수·출처 검사를 통과했다.
학습 프로그램의 데이터 점검에서 train 1,000개·val 20개만 학습/개발용 목록으로 반환되고
test 50개가 제외되는 것을 확인했다. 모델 생성·학습은 하지 않았다.

## 4. 확대가 개선한 점과 남은 한계

| 정답 범위 지표 | 이전 80문장 | 확대 1,000문장 |
|---|---:|---:|
| 학습에서 등장한 토큰 종류(blank 제외, 공백 포함) | 60 | 63 |
| val에서만 등장한 토큰 종류 | 1 | 0 |
| val 어절 189개 중 train에 같은 어절이 없는 횟수 | 138, 73.0% | 61, 32.3% |

동일 어절 중복 등장도 각각 세는 지표다. 말의 범위가 늘어났다는 설명이며 정확도 향상을 측정한 것은 아니다.
검증 문장의 모든 자모가 학습에 등장해도 문장 인식 성공을 보장하지 않는다.

학습 화자는 여전히 여성 8명, 정면 A, 소음환경1에 편중되어 있다.
새 화자 수가 늘어난 것은 아니며 웹캠 촬영의 조명·거리·검출 방식 차이도 남아 있다.
6단계에서 회색/역순 입력과 정상 입력의 오류율이 비슷했던 문제는 데이터 준비만으로 해결 여부를 판단할 수 없다.
현재 자료를 우선 재학습한 뒤 별도 화자의 val과 대조 입력으로 영상 활용 효과를 확인해야 한다.

**이번 단계에는 추가 다운로드가 필요하지 않았다.** 이후 남성·다양한 연령·새 화자와
정답이 있는 실제 웹캠 자료가 필요해지는 시점에 필요한 종류·규모·이유를 먼저 안내한다.
현재 1,000문장에 모델을 학습하는 첫 실험은 기존 RTX 3080 환경으로 시작할 수 있으며,
실제 처리 시간과 메모리 측정을 보고 외부 GPU 이용 여부를 결정한다.

## 5. 코드·검증·재실행

- `scripts/expand_speaker_dataset.py`: 고정 부모에서 학습 자료만 확대, 원본 라벨 재대조,
  기존 캐시 보존, 부분 준비 재개, 완료 명세 덮어쓰기 거부.
- `scripts/inspect_dataset_rois.py`: 새 클립의 검수 이미지와 영상 통계 생성.
  검수 이미지를 생성했다고 자동으로 시각 검수 통과를 선언하지 않는다.
- `backend/models/dataset_manifest.py`: 새 정책이 명시된 명세의 정답 중복 거부.
- 회귀 검사 **213개 통과**, CUDA 전용 1개 건너뜀, 기존 MediaPipe 검사 2개 선택 제외.
  신규 검사는 부모 표본/해시 보존, 다른 화자·정답 혼입 방지, 선정 재현성·균형,
  원본 시간 대조, 중단 후 이어 준비와 완료 자료 덮어쓰기 방지를 포함한다.

현재 준비된 자료만 검사하려면 프로젝트 루트에서 실행한다.

```powershell
& '.\.venv-gpu\Scripts\python.exe' scripts/train.py --manifest data_cache/datasets/aihub_expanded_v3/manifest.json --check-data
```

새 확대 버전을 만들 때만 다른 빈 출력 경로를 지정한다.

```powershell
& '.\.venv-tokenizer\Scripts\python.exe' scripts/expand_speaker_dataset.py plan --out data_cache/datasets/aihub_expanded_next --per-speaker 125
& '.\.venv-tokenizer\Scripts\python.exe' scripts/expand_speaker_dataset.py prepare --selection data_cache/datasets/aihub_expanded_next/selection.json
# 정상 캐시를 검사하고 빠진 문장만 이어 준비: prepare 명령에 --resume 추가
& '.\.venv-tokenizer\Scripts\python.exe' scripts/inspect_dataset_rois.py --manifest data_cache/datasets/aihub_expanded_next/manifest.json
```

원본 영상과 별도 캐시를 두고 필요한 부분만 추가 처리하는 방식이다. 준비 중 중단되면
`--resume`으로 이미 완성된 캐시도 검사한다. 손상 캐시는 조용히 덮어쓰지 않고 오류로 알려준다.
최초 독립 파일럿용 `build_speaker_dataset.py index`로 기존 화자를 다시 분할하지 않는다.

## 6. 다음 8단계

확대 명세를 명시해 무작위 초기화에서 학습하고, 고정 val20으로 6단계와 비교한다.
데이터가 12.5배가 되었으므로 같은 epoch라도 갱신 횟수·처리 시간이 다르다.
epoch와 갱신 횟수를 함께 기록하고, 먼저 짧은 본 학습 구간에서 손실·개발 검증 성능을 확인한 뒤
학습 길이와 방법을 조정한다. 정상/회색/역순 입력 대조와 train/val 격차도 다시 확인한다.
모델·설정을 확정할 때까지 test50은 보존한다.

기존 명세의 재현성을 위해 기본 명세는 v2로 유지했다. 확대 학습에서는 위와 같이 **v3 명세 경로를 명시**해야 한다.
6단계 가중치는 v2 명세로 학습되었으므로 v3 공식 평가에 강제로 사용하지 않는다.
새 모델의 출처 해시를 기록하고 성능이 확인된 뒤 실제 웹캠 검증을 진행한다.
