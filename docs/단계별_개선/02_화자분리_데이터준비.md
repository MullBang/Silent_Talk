# 2단계 완료: 화자 분리와 실제 데이터 준비

작업일: 2026-09-17

웹캠 입술 영상에서 한국어 문장을 복원하는 최종 목표에 맞춰, 여러 화자의 학습·개발 검증·최종 평가 자료를 분리했다. **15명·150문장의 실제 ROI 캐시를 생성했고, 학습과 평가 코드가 고정 명세를 사용하도록 연결했다.** 모델 재학습과 웹캠 성능 측정은 아직 수행하지 않았다.

새 NPZ 캐시 용량은 **285,930,827바이트, 약 286MB(273MiB)**다. 클립은 35~200프레임이며 RGB uint8, 96×96, 25fps로 저장했다. 학습 모델에는 가변 길이를 유지해 전달한다.

|---|---:|---:|---:|---:|
| Training (TS1·TS10 / TL1·TL10) | 10명 | 600개 | 120개 | 600개 |

원본 영상 수는 풀린 영상과 TAR 내부의 동일 영상을 중복 계산하지 않은 수치다. TS10의 300개 영상은 TAR 내부에서 확인했다. 추가 다운로드 없이 진행했고, 원본 파일은 수정하지 않았다.

정면 영상 180개의 라벨에서 총 7,800문장을 검토했다. 이번 파일럿 조건을 만족한 후보는 7,067문장이다. 제외한 733문장은 첫 번째 불합격 사유를 기록했다.

| 제외 사유 | 문장 수 |
|---|---:|
| 200프레임·8초 상한 초과 | 521 |
| X/x·숫자 등 현재 사전의 미지원 문자 | 191 |
| 문장 끝까지 대응하는 bbox가 없음 | 20 |
| CTC 정렬 최소 프레임 부족 | 1 |

이 기준은 파일럿의 규모와 정답 품질을 관리하기 위한 것이다. 긴 문장이 쓸 수 없는 데이터라는 의미는 아니며, 더 큰 학습 단계에서는 길이 상한을 재검토할 수 있다. 미지원 표기를 조용히 지우거나 발음을 추정하지 않았다.

화자별 2개 녹화에서 5문장씩 선정했다. seed=42, 정렬 및 해시 기반 선정으로 디렉터리 열거 순서가 바뀌어도 같은 입력 자료에서는 재현된다. 준비 단계는 TAR의 선정 영상 하나만 임시 추출하며, 영상 처리 후 임시 원본을 정리한다. 전체 TAR를 새로 풀지 않는다.

## 누수 방지와 학습·평가 연결

명세에는 화자 ID, 각도, 녹화 ID, 각도를 제외한 발화 ID, 원본 구획, 영상/라벨 위치, 라벨 SHA-256, 정답, 캐시 위치와 SHA-256, ROI 버전을 기록했다. JSON의 화자 ID·영상명·각도를 파일명과 대조했다.

- 집합 간 **화자 중복 0건**, **동일 녹화 발화 중복 0건**.
- 이번 선정 결과에서는 **정규화 문장 텍스트 중복도 0건**이다. 다른 사람이 같은 문장을 읽는 경우와 동일 발화 영상의 다른 각도는 구분하여 검사한다.
- 파일명 정렬 후 마지막 15%를 val로 쓰던 코드를 제거했다.
- `train.py`는 명세에 지정된 train/val만 사용한다. 최종 test는 학습 배치·개발 검증·모델 선택에 사용하지 않는다.
- 체크포인트에 학습 명세의 SHA-256과 분할 정보를 저장한다. `test_model.py`는 같은 명세로 학습된 가중치인지 확인한다.
- 파일 경로 중복, 출처 위조, 명세 폴더 밖 경로, 캐시 변조, 구형 ROI 버전, 구형 토큰 사전을 오류로 거부한다.
- `--smoke-data`는 분할 없는 디버깅·소수 샘플 과적합 확인용이다. 일반화 성능으로 보고하지 않으며 별도 임시 가중치 경로를 사용한다.

고정된 명세를 유지해야 비교 실험이 가능하다. 데이터를 늘릴 때 기존 test 화자를 학습에 넣거나 test 점수를 보고 설정을 고르지 않는다. 새 자료 추가 시 seed만 믿고 기존 화자 구성을 다시 섞지 말고, 기존 평가 화자의 보존 여부를 확인해야 한다.

## 시각 검수에서 발견하고 수정한 ROI 오류

첫 캐시를 이미지로 확인하자 일부 영상에서 입술 대신 배경과 옷이 잘렸다. 기존 코드는 좌표가 영상 높이를 넘으면 영상 자체를 90도 회전했다.

실제 원본과 대조한 결과, **이번 로컬 라벨의 `xtl_ytl_xbr_ybr` 값은 필드 이름과 달리 y1,x1,y2,x2 순서**였다. 예를 들어 C002의 한 프레임에서 `[520,908,776,1165]`는 xyxy로 `[908,520,1165,776]`을 뜻했다. 영상을 돌리는 대신 좌표 순서를 바꾸어야 입술에 맞았다.

`prepare_data.py`는 이제 좌표 순서를 명시적으로 변환하고 원래 방향의 영상에서 크롭한다. 다른 라벨을 처리할 때에는 `--bbox-coordinate-order xyxy`를 지정할 수 있다. 현재 자료에서 확인한 사실을 모든 AI Hub 자료에 자동으로 일반화하지 않는다.

문장 구간의 bbox가 실제 프레임 밖이면 거부하고, 영상이 조기에 끝나면 마지막에 읽은 프레임을 계속 재사용하지 않도록 함께 수정했다. 현재 ROI 버전은 `aihub-bbox-yxyx-v2`이다.

처음 생성한 `aihub_pilot_v1`은 시각 검수 실패 자료로 보존했다. 그 안의 `manifest.json`은 `manifest.rejected.json`으로 변경했고 사용 금지 안내를 남겼다. 로더에서도 구형 ROI 버전을 거부한다. **실제 사용할 폴더는 `aihub_pilot_v2`다.** 1단계의 원본 캐시, 라벨만 변환한 `jamo_v2` 캐시, 기존 가중치는 그대로 보존했다. 라벨 변환만으로 과거 ROI 오류가 교정되는 것은 아니다.

교정 후 150개 클립 각각의 시작·중간·끝, 총 **450개 표본 프레임**을 6개 이미지로 검수했다. 입술이 똑바로 포함된 것을 확인했다. 이는 모든 프레임과 전사 정확도를 사람이 전수 검수했다는 뜻은 아니다.

## 검증과 재실행

- 자동 테스트 **143개 통과**, 실패 0개.
- MediaPipe 미설치로 기존 얼굴 검출 관련 테스트 2개는 선택 제외했다. 이번 파일럿은 라벨 bbox를 사용하므로 MediaPipe 없이 준비했다.
- 실제 150개 캐시의 해시·원문/라벨 정합·CTC 길이·형상·출처를 검사했다.
- `train.py --check-data`에서 실제 train 80개·val 20개가 선택되고 test가 반환되지 않는 것을 확인했다.
- 모델 forward·체크포인트 저장/재로드 및 학습 명세 정보 보존 테스트를 포함했다. 실제 모델 학습은 수행하지 않았다.

프로젝트 루트에서 데이터만 다시 검사하는 명령:

```powershell
& '.\.venv-tokenizer\Scripts\python.exe' scripts/train.py --check-data
& '.\.venv-tokenizer\Scripts\python.exe' scripts/build_speaker_dataset.py validate
```

전체 자동 검사:

```powershell
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
& '.\.venv-tokenizer\Scripts\python.exe' -m pytest backend/tests -q -k 'not test_no_face_segment_returns_none and not test_extract_empty_raises'
```

새 자료를 준비하는 방법은 README의 `build_speaker_dataset.py index` → `prepare` → `validate` 순서를 따른다. 현재 폴더에 재실행해 기존 결과를 덮어쓰지 않고, 새 빈 출력 폴더를 지정해야 한다.
