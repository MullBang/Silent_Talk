# 4단계 — 경량 모델과 GPU 학습 환경

작성·실행 확인: 2026-09-17, Windows / RTX 3080 10GB.

**현재 컴퓨터에서 경량 모델의 학습을 시작할 수 있도록 구성하고 실제 역전파까지 확인했다.**
이번 단계는 학습 환경과 수치 계산의 연결 검증이다. 한국어 문장 인식 정확도, 일반화 성능,
실제 웹캠 자막 지연을 측정한 단계는 아니다. 추가 학습 데이터는 필요하지 않았다.

## 1. 모델 변경

| 항목 | 기존 | 개선 후 |
|---|---:|---:|
| 전체 학습 변수 | 115,714,213 | 3,287,781 |
| LSTM 변수 | 115,351,552 | 2,629,632 |
| LSTM 프레임별 입력 차원 | 55,296 | 256 |
| 구조 버전 | 별도 버전 없음 | `lipnet-compact-v1` |
| 입력 | RGB 96×96, 가변 T | 동일 |
| 출력 | T×B×69 | 동일 |

전체 변수를 **97.16% 줄였다.** 단순히 최종 출력 클래스를 줄인 것이 아니라,
공간 특징을 먼저 압축해 LSTM으로 전달하도록 변경했다.

처리 순서:

1. CNN 3개 블록: 32 → 64 → 96채널. 첫 합성곱의 공간 보폭은 2이다.
2. 공간 크기 96 → 48 → 24 → 12 → 6 → 4. 마지막은 4×4 공간 평균 풀링이다.
3. 96×4×4 = 1,536차원을 256차원으로 투영한다.
4. 양방향 LSTM(hidden256, 2층)과 69클래스 CTC 출력을 적용한다.

25fps, RGB, 96×96, ImageNet 정규화, 위치별 한글 자모 69토큰 계약은 유지한다.
**시간축은 줄이지 않으므로 입력 프레임 수 T와 CTC 출력 길이가 같다.**
공간 정보를 압축했으므로 인식 정확도가 좋아졌다고 단정할 수 없다. 후속 학습으로 판단해야 한다.

길이가 다른 문장을 묶을 때는 마지막 프레임 복제 패딩을 계속 사용한다.
다만 CNN 각 블록에서 실제 문장 끝의 특징을 다시 복제하고, 정규화는 프레임마다 별도로
계산하며, LSTM에는 실제 길이로 묶은 시퀀스를 넣는다. 짧은 문장을 단독으로 넣을 때와
긴 문장에 섞어 넣을 때 유효 프레임의 출력이 같은지 자동 검사했다.

가중치에 `architecture_version`을 기록한다. 기존 대형 모델이나 구형 41토큰 가중치를
새 구조에 강제로 넣지 않는다. 기존 `backend/models/weights/baseline.pt`는 보존했다.
기본 배포 경로 `baseline_jamo_v2.pt`에는 이번 임시 가중치를 저장하지 않았다.

| 드라이버 | 596.49 |

| 기본 권장 시작 설정 | batch 2, 최대 200프레임, AMP |

PyTorch 공식 Windows CUDA 12.8 배포 조합을 고정했다. 최신 버전이라는 의미는 아니며,
현재 환경에서 검증한 버전이다. 출처: [공식 설치 안내](https://pytorch.org/get-started/previous-versions/#v2100).
드라이버나 시스템 CUDA Toolkit은 변경하지 않았다. `nvidia-smi`의 CUDA 13.2 표시와
PyTorch가 사용하는 CUDA 12.8은 서로 다른 정보이다.

기존 `.venv-tokenizer`는 CPU·서버 회귀 검증용으로 유지한다. `.venv-gpu`는 준비된 NPZ
캐시 학습용으로 PyTorch·NumPy·pytest와 관련 의존성만 설치했다. MediaPipe, 웹 서버,
영상 전처리 전체를 설치한 환경이 아니며, 서비스 추론 장치도 이번 단계에서 GPU로 변경하지 않았다.
설치된 전체 패키지는 [환경 기록](04_GPU환경_패키지.txt)에 있다. `pip check`도 통과했다.

## 3. 학습 코드 개선

- CUDA에서는 기본적으로 혼합 정밀도 AMP를 사용하고, CPU에서는 FP32를 사용한다.
- log-softmax와 CTC 손실은 FP32로 유지한다.
- GradScaler로 기울기를 조절하고, 원래 크기로 되돌린 다음 gradient clipping을 적용한다.
- `--accum-steps`로 여러 묶음의 기울기를 모을 수 있다. 끝에 남은 작은 묶음도 표본 수에 맞게 반영한다.
- 캐시의 CTC 정렬 조건 검사에 더해, 비정상 손실을 0으로 숨기지 않고 중단한다.
- `--device cuda`인데 CUDA가 작동하지 않으면 명시적으로 오류를 낸다.
- `--max-steps`는 짧은 연결 검증 전용이다. 별도 출력 경로가 필요하며 val/test 추론과 best 선택을 하지 않는다.
- 임시 가중치는 `smoke_only`로 표시해 정식 평가의 분할 출처 검사에서도 구분한다.
- 실행 환경, 배치 길이, 손실, 갱신 횟수, 실행 시간, GPU 메모리를 JSON에 남긴다.

AMP의 기울기 누적·클리핑 순서는 [PyTorch 공식 AMP 예제](https://docs.pytorch.org/docs/2.10/notes/amp_examples.html)를 따른다.
저장은 현재 **추론용 가중치**이다. optimizer/scaler/난수 상태를 복구하는 학습 재개 기능은 아직 없다.

## 4. 실제 검증 결과

### 긴 문장 두 개의 GPU 학습

고정 명세 `aihub_pilot_v2`의 **train 소속에서 가장 긴 두 문장**을 골랐다.
실제 길이는 200/181프레임, 입력 묶음은 `(2,3,200,96,96)`이다.
val/test 문장은 학습이나 추론에 넣지 않았다. 명세 검증 과정의 캐시 무결성 확인은 유지했다.

| 측정 항목 | 결과 |
|---|---:|
| 역전파 및 Adam 갱신 | 4회 성공 |
| 첫 번째 / 네 번째 손실 | 5.9463 / 5.6496 |
| 최대 PyTorch 할당 메모리 | 760.53MiB |
| 최대 PyTorch 예약 메모리 | 1,150MiB |
| 초기 준비 제외 평균 1회 계산 | 약 0.083초 |
| 저장 가중치 | 13,160,607바이트, 약 12.55MiB |
| CPU 재로드와 GPU FP32 출력 최대 차이 | 0.0000663, 허용 오차 이내 |

손실·기울기·갱신된 가중치가 유한한 값인지, 실제 가중치가 달라졌는지 검사했다.
동일 두 문장에 대한 네 번의 갱신이므로 손실 감소를 일반화 성능으로 해석하지 않는다.
메모리는 이 프로세스의 PyTorch 할당/예약량이며 바탕화면·다른 앱·CUDA 드라이버가 쓰는
전체 VRAM은 별도이다. 시간은 데이터 읽기·전처리·웹캠·전송·디코딩을 제외한 학습 계산이다.
장시간 학습 시간이나 실제 웹캠 자막 속도로 환산하지 않는다.

### 학습 명령 전체 연결

별도의 `train.py` 실행에서 batch2, 누적2, 미니배치 3개를 사용했다.
가중치 갱신은 2회, AMP overflow에 따른 건너뜀은 0회였다.
마지막 누적 그룹이 덜 찬 경우도 정상 갱신된다. 고정 명세 해시와 `smoke_only` 출처가
저장된 것을 확인했다. 모든 임시 가중치는 `tmp/step4-*.pt`에만 저장했다.

### 자동 검사

- CPU·서버 회귀 검사: 190개 통과, CUDA 전용 1개 건너뜀.
- GPU 환경의 모델·학습 수치 검사: 21개 통과.
- 기존 MediaPipe 의존 검사 2개는 해당 검증 환경에 MediaPipe가 없어 제외했다.
- 1/17/200프레임 출력 길이, 패딩 영향 제거, 가중치 재로드, 토큰/구조 거부,
  실제 CTC 역전파, 잘못된 CTC 정렬, 누적 기울기와 묶음 평균의 일치를 확인했다.
- 설치 스크립트 구문 검사와 설치된 패키지 의존성 검사도 통과했다.

실측 원문과 실행 명령은 [검증 결과 JSON](04_검증결과.json)에 정리했다.

## 5. 재실행 방법

프로젝트 루트 PowerShell에서 실행한다. **현재 컴퓨터에는 설치가 끝났으므로 다시 설치할 필요가 없다.**

```powershell
# GPU 동작과 긴 문장 2개를 검증
$env:OMP_NUM_THREADS = '2'
$env:MKL_NUM_THREADS = '2'
& '.\.venv-gpu\Scripts\python.exe' scripts/verify_gpu_training.py --report tmp/step4-gpu.json

# 실제 학습 명령을 3개 미니배치로 제한해 확인
& '.\.venv-gpu\Scripts\python.exe' scripts/train.py --device cuda --precision amp --batch-size 2 --accum-steps 2 --max-steps 3 --out tmp/step4-train.pt --report tmp/step4-train.json

# GPU 전용 테스트
& '.\.venv-gpu\Scripts\python.exe' -m pytest backend/tests/test_baseline.py backend/tests/test_training_precision.py -q
```

새 환경에서 설치할 때는 Python 3.12 실행 파일을 지정한다. 아래 설치 명령의 경로는
현재 컴퓨터에서 확인한 경로이므로 다른 컴퓨터에서는 해당 Python 경로로 바꿔야 한다.

```powershell
.\scripts\setup_gpu.ps1 -Python 'C:\Users\HyunE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
```

설치 스크립트는 `requirements-gpu.txt`의 공식 CUDA PyTorch와
`requirements-training.txt`의 학습 의존성을 순서대로 설치한 뒤 실제 CUDA 연산을 확인한다.
실행 정책에 의해 스크립트가 차단된 환경에서는 Python 3.12로 `.venv-gpu`를 만든 뒤
스크립트에 적힌 두 pip 설치 명령을 각각 실행하면 된다. 시스템 실행 정책을 변경할 필요는 없다.

## 6. 추가 데이터와 다음 단계

**4단계에는 새 데이터가 필요하지 않았다.** 현재 15명·150문장 파일럿 중 train 80문장을
이용해 다음 소규모 학습 검증을 시작할 수 있다. RTX 3080에서 이번 구성의 batch2·최대
200프레임 역전파가 확인되었으므로 이 범위에서 코랩은 필수가 아니다.

다음은 **소수의 train 문장을 반복 학습했을 때 정답을 실제로 재현하는지 확인**하는 단계다.
그 검사가 통과하면 고정 train/val로 본 학습을 진행하고, 모델 설정이 확정된 뒤 test를 평가한다.
다양한 사람의 자유로운 한국어를 인식하기에는 현재 데이터가 작고 여성·정면·특정 환경에
치우쳐 있다. 데이터 확대나 미학습 화자의 웹캠 영상이 필요해지는 단계에서 필요한 종류와
규모, 이유를 먼저 알린다.
