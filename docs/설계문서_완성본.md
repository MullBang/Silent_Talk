1.2 영상 FPS 리샘플링 처리
※ 중요: OpenCV cap.set(cv2.CAP_PROP_FPS, 25)만으로는 이미 저장된 MP4 파일의 FPS가 변경되지 않는다.
업로드 영상의 원본 FPS가 25fps가 아닐 경우 반드시 타임스탬프 기반 리샘플링을 수행한다.

항목
내용
웹캠 입력
25fps로 capture 설정 (cap.set 적용 후 실제 fps 검증)
업로드 영상
원본 FPS를 cap.get(cv2.CAP_PROP_FPS)로 읽은 뒤, 영상 duration과 frame index 기준으로 균등 샘플링하여 25fps로 리샘플링
리샘플링 방법
target_timestamps = [i/25.0 for i in range(n_frames)]
원본 프레임 중 각 target_timestamp에 가장 가까운 프레임을 선택하는 nearest-neighbor 방식 적용
적용 범위
업로드 영상 전처리(F-MVP-02), 성능 평가(F-MVP-05) 모두 동일 방식 적용

1.3 3분 영상 세그먼트 분할 처리
★ 신규 추가: '75프레임 초과 시 앞부분 트리밍'은 단일 3초 입력에만 적용되는 표현이다.
업로드된 장편 영상은 반드시 아래 세그먼트 분할 방식으로 처리해야 결과 화면의 타임스탬프를 올바르게 생성할 수 있다.

항목
내용
분할 단위
3초 (= 75프레임) 단위 슬라이딩 세그먼트. 연속 배치 처리
분할 방법
seg_start_ms = 0, 3000, 6000 ... (3초 단위)
각 구간에서 25fps 기준 75프레임 추출 → 각 세그먼트를 독립적으로 모델에 입력
마지막 세그먼트
75프레임 미만인 경우 last-frame padding 적용 후 추론 진행
타임스탬프 저장
각 세그먼트의 start_ms, end_ms를 recognition_result에 저장 → 결과 화면 타임스탬프 표시에 사용
오버랩 옵션
기본: 오버랩 없는 순차 분할
개선 모델 적용 시: stride=25프레임(1초) 슬라이딩 윈도우 실험 가능 (선택)

F-MVP-01  |  영상 파일 업로드  [1차 MVP]

항목
내용
기능 설명
사용자가 로컬 영상 파일을 선택하여 서버에 업로드하고 비동기 추론 Job을 시작한다.
입력 제약
포맷: MP4/AVI/MOV (코덱: H.264/AAC 권장)  |  최대 크기: 500MB  |  최대 길이: 3분  |  최대 해상도: 1080p
※ 시연 합격 기준은 100MB (서비스 제한값 500MB와 별개)
처리 흐름
① 파일 선택 → ② 클라이언트 검증 → ③ POST /api/upload → ④ 서버 MIME 2중 검증 → ⑤ /tmp 임시 저장 + session_id 발급 → ⑥ POST /api/infer로 Job 시작 → ⑦ 1초 간격 폴링 (GET /api/result/{session_id}) → ⑧ status=done 시 SCR-02 전환
예외 처리
미지원 포맷: 400 / 크기 초과: 400 / 길이 초과: 400 / MIME 불일치: 400
업로드 오류: 네트워크 안내 / 추론 타임아웃(5분): 재시도 안내
완료 기준 (DoD)
100MB 샘플 MP4 업로드 성공 + SCR-02 전환 + 오류 메시지 정상 표시
API
POST /api/upload  Body: multipart/form-data {file}  Response: {session_id, file_name, duration_sec}

F-MVP-02  |  추론용 전처리 (세그먼트 분할 + ROI 추출)  [1차 MVP]

항목
내용
기능 설명
업로드 영상을 3초 단위 세그먼트로 분할하고, 각 세그먼트에서 입술 ROI를 추출하여 모델 추론용 텐서 배치를 생성한다.
처리 흐름
① FPS 리샘플링 (25fps 기준 타임스탬프 균등 샘플링) → ② 3초 단위 세그먼트 분할 → ③ 각 세그먼트: MediaPipe 외측 20개 포인트 기준 ROI 크롭 (+ 상하좌우 20% margin) → ④ 96×96 리사이즈 + Uint8 정규화 → ⑤ 75프레임 last-frame padding → ⑥ permute → (B,C,T,H,W) 변환
세그먼트 타임스탬프
각 세그먼트의 start_ms, end_ms를 계산하여 추론 결과와 함께 반환 (결과 화면 타임스탬프 기반)
예외: 얼굴 미검출
연속 12프레임 이상 미검출 시 구간 건너뜀; 결과에 '[검출 실패 구간]' 표기
예외: 다중 화자
바운딩 박스 면적 최대 1인 추적
완료 기준 (DoD)
테스트 영상 10개 처리 시 각 영상당 세그먼트별 텐서 shape (1,3,75,96,96) 정상 생성 + start_ms/end_ms 정상 산출

F-MVP-03  |  립리딩 모델 추론 (비동기 Job)  [1차 MVP]

★ POST /api/infer는 즉시 results를 반환하지 않고 Job을 시작하며 {job_id, session_id, status:"processing"}만 반환한다.
클라이언트는 GET /api/result/{session_id} 폴링으로 status=done 수신 후 results를 가져온다.

항목
내용
처리 흐름
① POST /api/infer → ② Background Job 시작 + {job_id, session_id, status:"processing"} 즉시 반환 → ③ Job 내부: 세그먼트 배치 추론 → CTC Beam Search(beam_width=10) → 자모음 복원(python-jamo) → ④ Job 완료 시 status=done, results 저장
출력 형식
[{start_ms, end_ms, text, confidence:float(0~1)|null}]
각 세그먼트별 start_ms/end_ms 포함하여 타임스탬프 표시 보장
confidence
0.0~1.0 정규화 신뢰도 점수 (CTC 디코딩 확률 기반); 산출 불가 시 null
confidence 0.5 기준은 초기 UI 표시 기준이며, 검증 데이터셋에서 실제 CER/WER 상관관계 확인 후 조정
Job 상태 관리
메모리 dict: {session_id: {job_id, status, progress, error_message, started_at, finished_at, results}}
API (시작)
POST /api/infer  Body:{session_id}  Response:{job_id, session_id, status:"processing"}
API (조회)
GET /api/result/{session_id}  Response:{session_id, status, progress(0~100), error_message|null, results:[...]}
완료 기준 (DoD)
테스트 영상 10개 중 8개 이상 정상 추론 + results에 start_ms/end_ms 포함

F-MVP-04  |  인식 결과 화면 출력  [1차 MVP]

항목
내용
처리 흐름
폴링 → status=done → results 렌더링 → 복사 버튼
표시 형식
[00:01~00:03]  안녕하세요  /  confidence < 0.5: 회색 이탤릭 (초기 기준; 검증 후 조정)  /  '[인식 불가]': 취소선
API 상태 ↔ 화면 상태
processing → INFERRING / done → DONE / error → ERROR / timeout → TIMEOUT
완료 기준 (DoD)

F-MVP-05  |  성능 평가 (비동기 Job + CSV 저장)  [1차 MVP — 검증 기능]

★ MVP 범위 조정: model_evaluation은 성능 평가 시작 시점부터 evaluation_log.csv 또는 SQLite에 즉시 기록한다.
인식 결과는 개인정보 보호상 메모리 관리를 유지하되, 성능 평가 결과는 반드시 영구 기록한다.

항목
내용
MVP 저장 방식
evaluation_log.csv 필수 저장 (eval_id, model_version, cer, wer, avg_latency_ms, detection_rate, test_set_id, eval_unit, test_date)
SQLite 저장

F-2ND-02  |  V-VAD 발화 구간 감지 (캘리브레이션 포함)  [2차 목표]

항목
내용
기능 설명
동적 임계값 기반 발화 구간 자동 감지. 시작 시 환경 캘리브레이션으로 정적 임계값의 한계를 극복한다.
d_raw 계산 정의
윗입술 중심점 (내측 상단 랜드마크 [13,14,312,311,310,415]의 평균 좌표)
아랫입술 중심점 (내측 하단 랜드마크 [17,18,84,181,180,314]의 평균 좌표)
d_raw = 두 중심점 사이의 유클리드 거리 (픽셀 단위)
mouth_ratio
mouth_ratio = d_raw / W  (W: 좌우 광대 랜드마크 간 거리 — 카메라 거리 변화 대응)
Phase 1: 캘리브레이션 (1.5초)
① 시작 후 1.5초 침묵 상태에서 mouth_ratio 시계열 수집
② baseline_mean, baseline_std 측정
③ T_open = baseline_mean + 2×std  |  T_close = baseline_mean + 0.8×std  |  T_var = baseline_var×1.5
→ 캘리브레이션 실패 시 기본값 사용 (T_open=0.08, T_close=0.04, T_var=0.0003) + 경고
Phase 2: 감지 루프
EMA smoothing(α=0.3) → smooth_ratio > T_open AND σ² > T_var → 발화 시작
smooth_ratio < T_close가 12프레임(0.5초) 지속 → 발화 종료
최소 발화 길이 0.5초 미만 무시
예외: 다중 화자
바운딩 박스 면적 최대 1인 추적
예외: 3프레임 연속 미검출
UI에 '입술을 가이드라인 안에 맞춰주세요' 경고

4. WebSocket 메시지 규격
항목
내용
엔드포인트
ws://{server}/ws/stream
업링크 타입
Binary (ArrayBuffer) — 제어 메시지 선행 후 프레임 데이터 전송
다운링크 타입

4.1 제어 메시지 (Control — JSON 텍스트, 프레임 전송 전 선행)
★ 신규 추가: 서버가 다중 사용자 스트림, 프레임 순서, 타임스탬프를 정확히 해석하기 위해
바이너리 프레임 전송 전에 반드시 JSON 제어 메시지를 먼저 전송한다.

// 세션 시작 (WebSocket 연결 직후 최초 1회 전송)
{"type":"SESSION_START","session_id":"uuid-v4","client_ts":1718000000000}

// 청크 시작 알림 (프레임 ArrayBuffer 전송 직전)
{"type":"CHUNK_START","chunk_id":1,"window_start_ms":0,"window_end_ms":480,"is_final":false}

// 발화 종료 알림 (마지막 청크 전송 직전)
{"type":"CHUNK_START","chunk_id":8,"window_start_ms":2800,"window_end_ms":3200,"is_final":true}

// 세션 종료
{"type":"SESSION_END"}

4.2 프레임 데이터 메시지 (Binary ArrayBuffer)
Binary ArrayBuffer 구조:
  [0~3]  : chunk_id (Uint32, Big-Endian) — 제어 메시지 chunk_id와 대응
  [4]    : msg_type (Uint8) — 0x01=FRAME_DATA
  [5~7]  : reserved (3바이트, 0x00)
  [8~N]  : ROI 프레임 픽셀 데이터 (Uint8 RGB)
           크기: 96×96×3 = 27,648 bytes
           서버 수신 후 Float32 변환 + [0,1] 정규화 적용
           (Float32 직접 전송 시 110,592 bytes — MVP 미사용)

4.3 서버 → 클라이언트 응답 (JSON)
// 중간 예측 (is_final=false)
{"type":"PARTIAL","text":"안녕하","confidence":null,"is_final":false,"chunk_id":3}

// 최종 확정 (is_final=true)
{"type":"PARTIAL","text":"안녕하세요","confidence":0.91,"is_final":true,"chunk_id":8}

// 오류
{"type":"ERROR","code":"DETECTION_FAILED","message":"입술을 가이드라인 안에 맞춰주세요"}

// 세션 종료 확인
{"type":"SESSION_END","total_segments":12}

10. DB명세서 개요
※ 사용자 업로드 영상과 인식 결과는 개인정보 보호를 위해 메모리(서버 dict)에만 유지한다.
단, 모델 성능 검증을 위한 평가 결과는 evaluation_log.csv 또는 model_evaluation 테이블에 반드시 저장한다.
아래 DB 구조는 확장 기능 구현 시 사용할 최소 스키마이다.

항목
내용
DBMS
SQLite 3 (단일 파일; 확장 시 PostgreSQL 14+ 마이그레이션 가능)
동시성 설정 (필수)
WAL 모드 + busy_timeout 30초 — 시연 시 다중 사용자 Lock 충돌 방지
MVP 최소 구현
인식 결과: 서버 메모리 dict  /  평가 결과: evaluation_log.csv (필수)  /  model_evaluation SQLite: 선택 적용
개인정보 원칙
업로드 영상: 추론 완료 후 즉시 삭제 + APScheduler 1시간 정리
DB 확장 시: 세션 데이터 24시간 후 자동 삭제

11. ERD
recognition_session (1) ──────────── (N) recognition_result
  PK: session_id (UUID)                 PK: result_id (AUTOINCREMENT)
  created_at, input_type                FK: session_id → ON DELETE CASCADE
  file_name, file_path                  start_ms (NULL 허용), end_ms (NULL 허용)
  duration_sec, status                  sequence_no (웹캠 chunk_id)
  job_id, progress                      predicted_text, confidence (0~1)
  error_message                         raw_score (CTC log-prob, NULL 가능)
  started_at, finished_at

12. 테이블 DDL (SQLite 기준)
12.0 SQLite 초기화 설정 (필수)
PRAGMA journal_mode = WAL;      -- 읽기/쓰기 동시 처리 (시연 Lock 방지)
PRAGMA busy_timeout = 30000;    -- Lock 대기 최대 30초
PRAGMA synchronous = NORMAL;    -- WAL 모드 성능·안정성 균형

12.1 recognition_session
CREATE TABLE recognition_session (
  session_id    VARCHAR(36)  PRIMARY KEY,
  created_at    DATETIME     NOT NULL DEFAULT (datetime('now','localtime')),
  input_type    VARCHAR(10)  NOT NULL CHECK(input_type IN ('upload','webcam')),
  file_name     VARCHAR(255),
  file_path     VARCHAR(500),   -- 추론 완료 후 즉시 삭제; 24h 후 NULL 처리
  duration_sec  FLOAT,
  status        VARCHAR(20)  NOT NULL DEFAULT 'pending'
                             CHECK(status IN ('pending','processing','done','error','timeout')),
  job_id        VARCHAR(36),
  progress      FLOAT        DEFAULT 0.0,
  error_message TEXT,
  started_at    DATETIME,
  finished_at   DATETIME
);
CREATE INDEX idx_session_created ON recognition_session(created_at);
CREATE INDEX idx_session_status  ON recognition_session(status);

12.2 recognition_result
CREATE TABLE recognition_result (
  result_id      INTEGER      PRIMARY KEY AUTOINCREMENT,
  session_id     VARCHAR(36)  NOT NULL
                   REFERENCES recognition_session(session_id) ON DELETE CASCADE,
  start_ms       INTEGER,     -- NULL 허용: 웹캠 스트리밍 시 미사용
  end_ms         INTEGER,     -- NULL 허용: 동상
  sequence_no    INTEGER,     -- 웹캠: WebSocket chunk_id (업로드는 NULL)
  predicted_text TEXT         NOT NULL,
  confidence     FLOAT,       -- 0.0~1.0 정규화 신뢰도 (0.5 기준은 초기 UI 기준; 검증 후 조정)
  raw_score      FLOAT,       -- CTC log-prob 원본값 (음수); 선택 저장
  created_at     DATETIME     NOT NULL DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_result_session ON recognition_result(session_id);

12.3 model_evaluation
CREATE TABLE model_evaluation (
  eval_id          INTEGER      PRIMARY KEY AUTOINCREMENT,
  model_version    VARCHAR(50)  NOT NULL,
  model_type       VARCHAR(100),
  cer              FLOAT        NOT NULL,
  wer              FLOAT        NOT NULL,
  avg_latency_ms   FLOAT,
  detection_rate   FLOAT,
  test_set_id      VARCHAR(100),   -- 서버 config 등록 ID (경로 직접 입력 금지)
  eval_unit        VARCHAR(20)  DEFAULT 'word' CHECK(eval_unit IN ('word','sentence')),
  test_date        DATETIME     NOT NULL DEFAULT (datetime('now','localtime')),
  notes            TEXT
);
