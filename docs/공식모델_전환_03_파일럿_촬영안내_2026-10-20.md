# 공식 모델 전환 3단계 — 팀원 웹캠 파일럿 촬영 안내

> 작성일: 2026-10-20 · 상위 계획: [공식모델_전환_실행계획_2026-10-20.md](공식모델_전환_실행계획_2026-10-20.md)
> 목적: 실제 목표 조건(웹캠·소리 없이·처음 보는 사람)에서 OLKAVS 성능을 처음 확인한다. 이 결과로 시연 범위(지정 문장 수, hybrid/CTC, 입술 상자 배율)를 정한다.

## 1. 준비

- 시연에 쓸 PC·웹캠·브라우저(Chrome 또는 Edge)를 그대로 쓴다. 최종 평가도 같은 장비로 한다.
- 조건: 정면, 카메라와 50~70cm, 고정 실내 조명, 배경 단순. 마스크·손으로 입 가리지 않기.
- 저장 폴더: 저장소 **밖**에 만든다. 예: `D:\silent_talk_webcam\pilot\`. 영상은 git에 올리지 않는다.
- 참가자: 팀원 2~3명. 가명 ID(P01, P02 …)를 정하고 아래 동의 항목을 서면으로 받는다.
  - 목적(립리딩 성능 평가), 영상만 저장(음성 없음), 보관 기한(운영 종료 11/20 후 파기), 외부 비공개, 철회 가능.

## 2. 촬영 (1인당 약 30~40분)

1. 백엔드 없이 프론트만 띄운다.
   ```bash
   cd frontend && npm run dev
   ```
2. 브라우저에서 `http://localhost:5173/#capture` 를 연다(또는 업로드 화면 → "파일럿 촬영 →").
3. 가명 ID 입력 → "저장 폴더 선택"(Chrome/Edge) → "카메라 열기". 화면에 실제 해상도·fps가 표시된다.
4. 화면의 문장을 읽는다. **스페이스바**로 시작, 다시 스페이스바로 정지(8초가 지나면 자동 정지). 정지하면 자동 저장되고 다음 문장으로 넘어간다.
   - 순서: 지정 20문장(소리 내어) → 같은 20문장 2회차 → 지정 20문장(소리 없이) 2회 → 자유 문장 10 → 무발화 10 = **100클립**.
   - 말을 시작하기 전에 녹화를 시작하고, 말이 끝난 뒤 0.5초쯤 있다가 정지한다.
   - 틀리게 읽었으면 "이전 (다시 찍기)"로 돌아간다.
5. 자유 문장 10개는 실제로 말한 문장을 **기록지**에 적는다. 나중에 같은 이름의 `.json`에 `"spoken": "실제 문장"` 으로 넣어야 CER을 낼 수 있다.
6. 소리 없이 말하는 조건에서는 대본과 다르게 말했는지 촬영자가 확인해 기록한다.

저장 결과: 클립마다 `P01_voiced_A03_1.webm` + `P01_voiced_A03_1.json`(정답 문장, 조건, 실제 해상도·fps, 프레임 시각 로그).

## 3. 측정

```bash
python scripts/pilot_evaluate.py run --clips D:/silent_talk_webcam/pilot --out experiments/webcam_pilot_20261022 --device cpu
```

- `roi-all`(입술 추출) → `score`(인식·채점) 순서로 두 가상환경을 자동으로 쓴다. GPU가 있으면 `--device cuda:0`.
- 출력: `pilot_summary.json`(표), `pilot_results.json`(클립별 상세), `roi/<클립>/roi.json`(검출 상자).
- 표에 나오는 것: 조건(voiced/silent)·문장 묶음(AI Hub A / 새 문장 N)별 문자 CER과 완전 일치, 지정 20문장 중 정답 고르기 top-1/top-3(길이만 보는 분류기와 우연 1/20 대비), 무발화 클립의 오수락, 입술 검출 성공률, 처리 시간.

## 4. 판단 기준(게이트 A)

- 소리 내어 말한 조건의 후보 top-1이 길이 분류기보다 높고 60% 이상이면 시연 지정 문장 N=20으로 간다.
- 미달이면 N을 줄이고, 입술 상자 배율(1.3/1.5/1.8)·밝기 정규화 같은 라벨 없는 조정을 먼저 시험한다.
- AI Hub 문장(A)과 새 문장(N)의 차이가 크면 "학습 문구 완성" 효과로 보고 N 결과를 기준으로 삼는다.
- 무발화 클립에서 글자가 나오는 비율은 6단계 "인식 불가" 임계값의 근거가 된다.

## 5. 2026-10-20 사전 확인 결과

- 브라우저 MediaRecorder WebM(VP8/VP9)·MP4를 서버 쪽 cv2가 모두 읽는다. WebM은 fps·프레임 수 메타데이터가 없어 **실제 PTS 기준 30fps 격자 리샘플**을 쓴다(`olkavs_transcribe.py roi`가 자동 판별). 프레임 간격은 6~78ms로 변동한다.
- 실제 입술 영상을 720p WebM으로 바꿔 넣었을 때 hybrid 결과 "아주 싶으로 감사해"가 원본 MP4와 같았다.
- 얼굴이 없는 영상은 `initial_detection_miss`로 거부된다.
- 아직 실제 웹캠 촬영은 하지 않았다. 이 문서의 수치 기준은 파일럿 후 확정한다.
