# 공식 모델 전환 6단계 결과 — 녹화 → 분석 → 결과 화면

> 작성일: 2026-10-21 · 상위 계획: [공식모델_전환_실행계획_2026-10-20.md](공식모델_전환_실행계획_2026-10-20.md) · 이전 단계: [5단계 결과](공식모델_전환_05_서비스연결_결과_2026-10-20.md)
> 결론: 웹캠으로 영상만 녹화하면 서버가 실제 길이를 재고, 말하지 않은 앞뒤를 잘라 낸 뒤 공식 OLKAVS 모델로 문장을 낸다. 이 PC의 브라우저에서 가짜 카메라로 3초·8초 녹화를 각 10회 돌려 20회 모두 결과가 나왔다. 실제 웹캠, Edge, 인터넷을 끈 시연 PC 확인과 처음 보는 사람의 정확도는 남아 있다.

## 1. 사용자 흐름

```
#record 화면 ─ 카메라(영상만) ─ 8초 자동 종료 ─▶ POST /api/record ─▶ 실제 길이 측정(0.5초 이상, 30초 미만)
                                                     │                    └─ 녹화 모드 Job 등록 (결과는 주지 않음)
결과 화면 ◀─ GET /api/result/{session_id} 폴링 ◀─ 입술 추출 + 입 움직임 판정 → 앞뒤 무발화 자르기 → 인식
```

- 녹화 화면: "음성 꺼짐" 표시, 얼굴 안내선, 8초 기본·30초 실험 모드, 3초 카운트다운, 스페이스바 시작·정지, 남은 시간 표시. 1초 미만 녹화는 보내지 않는다.
- 결과 화면: "처음 보는 사람의 입 모양 인식 정확도는 아직 검증되지 않았습니다." 안내와 모델 정보(디코더, 가중치 SHA 앞 12자, 코드 커밋, 입술 영역 규칙)를 항상 보인다. "다시 녹화"로 돌아간다.
- 결과 표시 문구는 세 가지다.

| 문구 | 뜻 |
|---|---|
| `[발화 없음]` | 얼굴은 보였지만 입이 움직이지 않았다 |
| `[검출 실패 구간]` | 얼굴이나 입술을 찾지 못했다 |
| `[인식 불가]` | 인식 신뢰도가 0.75보다 낮다. 모델이 낸 문장은 흐리게 "낮은 신뢰도 추정"으로 함께 보인다 |

## 2. 구현

| 영역 | 파일 | 내용 |
|---|---|---|
| 녹화 접수 | [backend/api/record.py](../backend/api/record.py) | WebM(EBML 서명+DocType)·MP4(ftyp) 내용 판정, 파일명은 서버가 정함, 프레임 시각으로 실제 길이 측정, 녹화 모드 Job 등록 |
| 요청 크기 제한 | [backend/api/limits.py](../backend/api/limits.py) | `/api/record` 100MB, `/api/upload` 500MB를 넘는 요청 본문을 받는 즉시 413. 업로드도 메모리에 통째로 읽지 않고 나눠 저장 |
| Job 연결 | [backend/api/infer.py](../backend/api/infer.py) | `/api/infer`와 `/api/record`가 같은 Job 시작 함수를 쓴다. 결과에 `model`(모델 정보)과 항목별 `candidate` |
| 서비스 | [backend/services/olkavs_service.py](../backend/services/olkavs_service.py) | 녹화 모드 전달, 결과 문구 대응, 신뢰도 문턱, 길이 힌트 전달, 대기열 차례가 오면 바로 처리 중으로 표시 |
| 입 움직임 판정 | [scripts/olkavs_transcribe.py](../scripts/olkavs_transcribe.py) | 입 벌림 비율(내측 입술 거리 ÷ 광대 거리)의 0.4초 범위로 말하는 프레임 판정, 업로드는 말 없는 창을 `no_speech`로, 녹화는 발화 구간만 남기고 NPZ를 다시 저장 |
| 녹화 화면 | [frontend/src/pages/RecordPage.jsx](../frontend/src/pages/RecordPage.jsx) | 위 1절의 화면. 폴링은 업로드 화면과 공용 [ResultPoller](../frontend/src/components/ResultPoller.jsx) |
| 오프라인 | [frontend/vite.config.js](../frontend/vite.config.js) | MediaPipe wasm을 `node_modules`에서 `/mediapipe/wasm`으로 제공하고 빌드에도 복사 |
| 보정 도구 | [scripts/calibrate_vad.py](../scripts/calibrate_vad.py) | 라벨이 있는 녹화로 입 움직임 기준값을 다시 재는 도구 |

계획과 다르게 한 것:
- 녹화 모드도 12초 모델 창을 그대로 쓴다. 기본 8초 녹화는 창 하나지만 30초 실험 모드에서 12초를 넘으면 여러 창으로 나뉠 수 있다.
- MP4도 받는다. Safari의 MediaRecorder가 WebM 대신 MP4를 만들기 때문이다.
- 실시간 웹캠 화면(WebcamPage)의 얼굴 모델 파일 `face_landmarker.task`는 내려받지 않았다. 로컬 파일이 있으면 쓰고 없으면 기존 온라인 주소를 쓴다. 녹화 화면은 MediaPipe를 쓰지 않으므로 이 파일 없이 오프라인으로 동작한다.

## 4. 검토와 수정

다섯 영역을 적대적으로 검토해 17건이 확인됐다. 겹치는 것을 합치면 13개 문제다. 모두 고쳤고, 다른 검증 담당이 검토자의 재현 스크립트로 다시 확인했다.

| 문제 | 수정 |
|---|---|
| 녹화가 무발화로 판정되면 얼굴 미검출 구간까지 버리고 전체를 `[발화 없음]`으로 표시 | 미검출 구간은 남기고 보인 구간만 `[발화 없음]` |
| 12초를 넘는 녹화에서 잘라 낸 뒤 말이 없는 창도 인식 | 실제 움직임이 0.3초 이상인 창만 남기고 짧은 꼬리는 이웃 창에 합침 |
| 브라우저 WebM은 낮은 프레임률 경고가 나오지 않음 | 메타데이터가 없으면 실제 프레임 간격으로 fps를 추정 |
| 브라우저 WebM은 입술 추출 동안 진행률 0% 정지 | 서버가 잰 길이를 힌트로 보내 진행률 계산 |
| 업로드 화면이 Job 생성 전에 결과를 조회해 가끔 영어 404 오류 | Job 시작 뒤 조회, 처음 두 번의 404는 대기로 처리, 오류 문구 한국어 |
| 카메라가 끊긴 뒤 녹화를 누르면 반응 없음 | 끊김을 감지해 안내하고 "카메라 다시 열기" 표시 |
| 카메라 오류가 영어 원문으로 표시 | 권한·장치 없음·사용 중을 한국어로 구분 |
| 버튼 클릭 뒤 스페이스바가 녹화를 시작하지 않음 | 마우스 클릭 뒤 포커스를 풀어 줌(키보드 조작은 유지) |
| 업로드가 파일 전체를 메모리로 읽고 이벤트 루프에서 씀 | 나눠 저장하고 길이 측정은 별도 스레드 |
| 요청 본문 크기 제한이 없음 | 413 미들웨어 |
| 실제 워커 통합 테스트가 `[발화 없음]`에서 깨지고 녹화 모드를 검사하지 않음 | 두 모드 모두 검사, 표시 문구만 나오는 영상은 건너뜀 |
| 녹화를 항상 창 하나로 인식한다는 설명 | 12초 창 동작에 맞게 고침 |
| 기준값 근거 파일이 없음 | 보정 기록 작성 |

## 6. 남은 한계

- 실제 웹캠, Edge, 인터넷을 끈 시연 PC에서의 완료 기준(3초·8초 각 10회)은 아직이다. 위 검증은 이 PC의 내장 Chromium과 AI Hub 영상을 쓴 가짜 카메라다.
- 처음 보는 사람·소리 없이 말하기의 정확도는 미측정이다. 3단계 팀 촬영 후 판정한다.
- 입 움직임 기준값과 신뢰도 문턱은 소리 내어 말하는 고해상도 AI Hub 자료로 정했다. 팀 촬영 자료로 `scripts/calibrate_vad.py`를 다시 돌려 맞춘다.
- 말하지 않을 때도 입을 움직이는 사람은 무발화 구간이 말하는 것으로 잡힐 수 있다. 말을 지우는 쪽보다 남기는 쪽을 택했다.
- 30초 실험 모드에서 12초 경계에 걸친 짧은 말 조각(0.3초 이상)은 1초짜리 별도 창으로 인식될 수 있다.
- 실제 USB 카메라 분리나 절전 복귀 때의 카메라 끊김 처리는 캔버스 스트림으로만 확인했다.
- 413 뒤에도 서버는 클라이언트가 보내는 나머지 본문을 읽어 버린다. 디스크와 메모리는 쓰지 않고 대역폭만 쓴다.
- 실시간 웹캠 화면을 오프라인으로 쓰려면 `face_landmarker.task`를 `frontend/public/mediapipe/`에 직접 넣어야 한다.
