# 병실 "내 목록" 사용법 (직접 만든 문장으로 병실 화면 쓰기)

"내 목록"은 기본 명령 20개 대신 **직접 쓴 문장 4~20개**로 병실 화면(`#ward`)을 쓰는 기능입니다. 시연에서 "우리가 정한 문장으로도 동작한다"를 보여 주려고 만들었습니다.

- **기본 목록은 그대로 기본값입니다.** 내 목록을 고르지 않으면 병실 화면·간호사 화면·등록·기준값이 전과 똑같이 동작합니다.
- 인식 모델, 기준값(1·2등 차이 0.70, 1등 점수 −2.90, 긴급 가능성 하한 없음, 등록 거리 D 0.26), 판정 규칙은 기본 목록과 **같은 것**을 씁니다. 목록만 바뀝니다.
- 내 목록은 **성능을 측정하지 않은 목록**입니다. 병실 화면 위에 늘 그렇게 표시됩니다(5절).
- 시연용 연구 시제품입니다. 실제 환자에게 검증하지 않았고, 호출벨을 대신하지 않습니다.

> **먼저 확인:** 이 기능은 내 목록 기능을 **커밋한 뒤** `py -3.11 deploy\build_bundle.py --freeze docs\병실명령_동결_2026-11-10.json`로 **다시 만든 묶음**에만 있습니다. 묶음은 커밋된 코드(HEAD)로 만들기 때문에, 그 전에 만든 묶음에는 [내 목록 관리]가 없습니다. 노트북에 다시 설치한 뒤 환자 화면 [설정]에 **[내 목록 관리]** 가 보이는지, `시연_점검.bat` 2구역에 "'내 목록' 저장 폴더에 쓸 수 있음"이 나오는지 먼저 확인하세요.

## 1. 기본 목록과 무엇이 같고 무엇이 다른가요

| 항목 | 기본 목록 | 내 목록 |
|---|---|---|
| 문장 | 명령 20개(W01~W20, 동결) | 직접 쓴 4~20개. 저장할 때 서버가 순서대로 U01, U02 …를 붙입니다 |
| 인식 모델·기준값·판정 규칙 | 같음 | 같음 |
| 긴급(빨간 카드·긴급 가능성) | W02·W03·W04·W10 | "긴급"으로 표시한 문장 |
| 취소 문장 | W20 | "취소"로 표시한 문장 하나(없어도 됨) |
| 입 모양 등록 | 기본 목록용 등록 | **목록마다 따로** 등록(4절). 기본 목록 등록은 건드리지 않습니다 |
| 가상 병실 효과(불·커튼·TV 등) | 있음 | 없음. 간호사 카드만 갑니다 |
| 간호사 카드 | 그대로 | 작은 꼬리표 "내 목록: <목록 이름>"이 붙습니다 |
| 스위치 3번 긴급 호출 | 됨 | 됨 |
| 연습 모드(`?practice=1#ward`) | 기본 목록 | 쓰지 않음. 연습 모드는 늘 기본 목록입니다 |
| 성능 | P01·P03로 기준을 정하고 P02로 평가 | 측정하지 않음(5절) |

## 2. 노트북에서 내 목록 만들기

1. `시연_실행.bat`으로 서버와 화면을 켭니다(시연노트북 설치안내 5절).
2. **환자 화면 창에서** 오른쪽 위 **[설정] → [내 목록 관리]** 를 누릅니다(같은 창에서 목록 화면으로 넘어갑니다). 간호사 창이나 새 탭에서 따로 열지 않는 것을 권합니다.
   - 다른 탭에서 열어 [이 목록으로 병실 화면 쓰기]를 눌러도, 열려 있는 환자 화면이 저장소 알림이나 창으로 돌아올 때 다시 읽어 그 목록으로 바뀝니다. 녹화·확인·선택 중이면 끝난 뒤에 바뀝니다.
3. 왼쪽 목록에서 고릅니다.
   - **기본 목록**: 보기만 할 수 있고 고칠 수 없습니다.
   - **내 목록들**: 저장한 목록입니다. 눌러서 고칩니다.
   - **[+ 새 목록 만들기]**: 빈 목록을 만듭니다. **목록 이름**(1~30자, 화면에 보이는 이름)과 **목록 ID**(영문·숫자·`_`·`-` 32자까지, 예: `rehab1`)를 적습니다. 목록 ID는 처음에 `mylist1`처럼 채워져 있고, 저장한 뒤에는 바꿀 수 없습니다. 목록은 20개까지 만들 수 있습니다.
4. 줄마다 다섯 칸을 채웁니다.

   | 칸 | 뜻 |
   |---|---|
   | 입 모양 문장 | 환자가 입으로 말하는 문장. 인식에 쓰입니다 |
   | 화면 문장 | 환자 화면 결과와 간호사 카드에 보이는 짧은 존댓말 |
   | 종류 | 긴급 / 호출·소통 / 몸 돌봄 / 병실 / 대답 |
   | 긴급 | 종류가 "긴급"일 때만 켭니다 |
   | 취소 | "방금 요청 취소"로 쓸 문장 하나에만 켭니다 |

   줄마다 첫 줄에 입 모양 문장·화면 문장, 둘째 줄에 종류·긴급·취소와 [↑]·[↓]·[✕](위로·아래로·줄 지우기) 버튼이 있습니다. 목록 아래 [+ 줄 추가]로 줄을 더합니다.
5. 적는 동안 서버가 바로 검사합니다. **빨간 글씨는 오류**라 저장되지 않습니다([저장] 버튼이 꺼집니다). **노란 글씨는 주의**라 저장은 되지만 고치는 편이 좋습니다(3절).
6. **[저장]** 을 누릅니다.
7. **[이 목록으로 병실 화면 쓰기]** 를 누릅니다(저장했고, 고친 것이 없고, 오류가 없을 때만 눌립니다). 병실 화면 위에 **"내 목록 ‘<목록 이름>’ 사용 중 · 성능을 측정하지 않은 목록"** 띠가 보이면 됩니다.
8. 이어서 나오는 **[이 목록으로 입 모양 등록하기]** 로 등록 화면(`#enroll`)에 갑니다(4절).

- **예시 목록 불러오기**: "재활 병동" 10문장(6절)을 **언제나 새 목록으로** 엽니다(목록 ID는 `mylist2`처럼 비어 있는 것으로 채워짐). 저장한 목록을 열어 둔 채 눌러도 그 목록은 바뀌지 않습니다. [저장]을 누르기 전에는 서버에 저장되지 않습니다.
- **저장이 겹치지 않게 막습니다**: 새 목록은 그 ID가 아직 없을 때만, 저장된 목록은 화면이 불러온 뒤 다른 곳에서 바뀌지 않았을 때만 저장됩니다. 다른 탭에서 같은 ID로 먼저 만들었으면 "같은 ID의 목록이 이미 있어요"가, 다른 탭에서 먼저 고쳤으면 "다른 곳에서 이 목록이 바뀌었거나 지워졌어요"가 나오고 아무것도 덮어쓰지 않습니다. 뒤의 경우 **[이 목록 다시 불러오기]** 를 누릅니다(여기서 고친 내용은 버려집니다).
- 서버에서 목록들을 불러오지 못하면 [+ 새 목록 만들기]와 [예시 목록 불러오기]가 꺼지고 **[다시 불러오기]** 가 나옵니다.
- **기본 목록으로 돌아가기**: [설정] → "명령 목록"에서 **기본 목록**을 고릅니다.
- **목록 지우기**: 목록을 고르고 [이 목록 지우기] → 확인. 그 목록의 입 모양 등록도 함께 지워집니다. 병실 화면이 쓰던 목록이면 설정이 기본 목록으로 돌아가고, 화면에 그렇게 알립니다.
- 목록은 노트북 서버의 `backend\data\ward_lists\<목록 ID>.json`에 저장됩니다(노트북에서는 `C:\SilentTalk\backend\data\ward_lists`). 개발 PC에서는 환경 변수 `LIPNET_WARD_LIST_DIR`로 위치를 바꿀 수 있습니다.

## 3. 문장 쓰는 규칙

### 3-1. 오류 (저장되지 않음)

| 규칙 | 설명 |
|---|---|
| 문장 수 | 4개 이상 20개 이하 |
| 입 모양 문장 글자 | **한글 음절과 띄어쓰기만** 씁니다. 숫자·영문·문장부호는 안 됩니다(예: "3층" → "삼 층"). 앞뒤 공백과 겹친 띄어쓰기는 저절로 정리됩니다. 붙여 넣은 글에 보이지 않는 글자(예: BOM)가 섞이면 "쓸 수 없는 글자: U+FEFF"처럼 코드로 알려 줍니다. 그 칸을 지우고 다시 적습니다 |
| 입 모양 문장 길이 | 2~40자, 토큰 50개 이하 |
| 화면 문장 | 1~30자. 줄바꿈 같은 제어 문자는 안 됩니다 |
| 종류와 긴급 | 긴급은 종류가 "긴급"일 때만, 종류가 "긴급"이면 긴급도 켭니다 |
| 겹침 | 같은 입 모양 문장, 같은 화면 문장은 두 번 쓸 수 없습니다. 입 모양 문장은 **띄어쓰기만 다른 것도 같은 문장**입니다("숨이 차요" / "숨이차요" — 띄어쓰기는 입 모양이 없어 구분되지 않습니다). 화면 문장은 NBSP·전각 공백 같은 공백 문자도 띄어쓰기로 보고 비교합니다 |
| 취소 | 취소 문장은 하나까지, 긴급 문장은 취소 문장이 될 수 없습니다 |
| 일반 문장 | 긴급이 아닌 문장이 하나 이상 있어야 합니다 |

**토큰**은 모델이 읽는 자모 단위입니다. 받침 없는 글자는 2, 받침 있는 글자는 3, 띄어쓰기는 1로 셉니다.
예: "물 좀 주세요" = 물3 + 1 + 좀3 + 1 + 주2 + 세2 + 요2 = **14토큰**(5음절).

### 3-2. 경고 (저장은 됨)

| 경고 | 왜 |
|---|---|
| "짧거나 길어서 잘 읽히지 않을 수 있어요" | 9~13음절, 23~34토큰을 벗어났습니다. 기본 명령 20개도 이 범위로 만들었습니다. 위 "물 좀 주세요"는 짧아서 경고가 나옵니다 |
| "긴급이 많으면 거짓 긴급 알림이 늘어요" | 긴급 문장이 5개 이상입니다. 고르지 못했을 때 1·2등에 긴급이 있으면 긴급 가능성으로 알리므로, 긴급이 많을수록 거짓 알림이 늘어납니다 |
| "입 읽기로는 빨간 카드가 나지 않고 스위치 3번 긴급 호출만 남아요" | 긴급 문장이 없습니다 |
| "입 모양이 거의 같아서 구분하기 어려워요" | 두 문장의 입술 모양 순서가 같거나, 켜/꺼·올려/내려·열어/닫아처럼 한 단어만 반대말로 바뀐 짝입니다 |
| "입 모양이 비슷해요" | 입술 모양 순서가 많이 겹칩니다 |
| "끝부분이 같아요" | 끝의 입술 모양이 같습니다(예: 여러 문장이 똑같은 말투로 끝남) |

입술 모양은 글자를 입술에 보이는 몇 가지 모양으로 묶어 비교합니다. 자음은 입술 닫힘(ㅁㅂㅃㅍ), 혀끝(ㄴㄷㄸㄹㅅㅆㅌ), ㅈㅉㅊ, 거의 안 보임(ㄱㄲㅋㅎㅇ)으로, 모음은 벌림·둥글게·옆으로·중간 네 가지로 봅니다. 그래서 "불 켜 줘"와 "불 꺼 줘"는 입술로는 거의 같습니다.

### 3-3. 잘 읽히는 문장을 쓰는 요령

- **한 단어보다 문장**: "물"보다 "목이 말라 물 한 모금만"처럼 9~13음절로 씁니다. 짧으면 다른 말과 헷갈립니다.
- **반대말 짝을 피합니다**: "불 켜 줘 / 불 꺼 줘" 대신 하나를 "방이 어두워요"처럼 다른 말로 씁니다.
- **끝말을 다양하게**: 모든 문장이 "~주세요"로 끝나면 끝부분이 같아 헷갈립니다. "~해 줘", "~할래", "~싶어요", "~나요"처럼 섞습니다.
- **긴급은 2~3개**: 정말 바로 와야 하는 일만 긴급으로 둡니다. 기본 목록에서는 목록 밖 말의 긴급 가능성 알림이 대부분 두 긴급 명령(W10 "…토할 것 같아요", W03 "…아파서 못 참겠어요")에서 나왔습니다. "~것 같아요"처럼 흔한 말투의 긴급 문장은 다른 말을 끌어당기기 쉽습니다.
- **기본 명령과 비슷한 문장은 피합니다**: 환자가 습관처럼 기본 명령을 말해도 내 목록 문장으로 잘못 고르지 않게 합니다.
- **개인 정보는 쓰지 않습니다**: 환자 이름·병명 같은 개인 정보는 문장에 넣지 않습니다.

## 4. 목록마다 입 모양 등록

등록 방법은 기본 목록과 같습니다(시연노트북 설치안내 5-1절). 다른 점만 적습니다.

- **등록은 목록마다 따로 저장됩니다.** 내 목록의 등록은 `backend\data\ward_profiles\lists.d\<목록 ID>\<등록 이름>\`에 저장되고, 기본 목록 등록(`backend\data\ward_profiles\<등록 이름>\`)은 건드리지 않습니다. 같은 등록 이름을 두 목록에서 써도 서로 다른 등록입니다.
- 등록 화면은 **지금 쓰는 목록**의 문장을 하나씩 보여 줍니다. 예시 목록은 10개라 약 3분 걸립니다.
- 등록은 **문장 글자** 기준으로 저장됩니다.
  - 순서만 바꾸거나, 화면 문장·종류·긴급만 고치면 등록을 그대로 씁니다.
  - 입 모양 문장을 고치거나 새 문장을 더하면 그 문장만 다시 찍으면 됩니다.
  - 모든 문장을 다 찍기 전에는 병실 화면이 그 등록을 쓰지 않습니다. 상태 줄에 "내 입 모양 등록: <등록 이름> (찍은 수/문장 수) — 다 찍지 않아 아직 쓰지 않아요"가 보이면 남은 문장을 찍습니다.
  - 목록 화면(#lists)도 저장한 목록에 등록이 있으면 **"아직 찍지 않은(고친) 문장 N개를 찍어야 이 목록에서 입 모양 등록을 써요"** 를 보여 줍니다. 병실 화면이 그 목록을 쓰는 동안 [이 목록으로 입 모양 등록하기]에서 그 문장만 다시 찍습니다.
  - 등록 화면을 열어 둔 채 다른 탭에서 목록을 고치면, 그 화면에서 찍은 녹화는 저장하지 않고 "목록이 바뀌었어요"를 보인 뒤 새 목록으로 다시 엽니다(옛 문장의 입 모양이 새 문장 등록으로 남지 않게). 창으로 돌아올 때도 목록이 바뀌었는지 다시 확인합니다.
  - 인식 모델 가중치가 바뀌면 "다시 등록 필요"가 됩니다. 지우고 다시 등록합니다.
- 병실 화면 카메라 아래 상태 줄은 **지금 쓰는 목록의 등록**을 보여 줍니다. [설정]의 등록 고르기도 지금 목록의 등록만 보여 줍니다.

## 5. 측정한 것과 측정하지 않은 것

### 5-1. 예시 목록 "재활 병동"으로 미리 확인한 것 (2026-11-11)

- **목록 검사**: 저장할 때와 같은 규칙으로 오류 0, 경고 0입니다. 문장 길이는 10~12음절, 24~34토큰입니다. 입술 모양 비교 방식을 몇 가지로 바꿔 재도 가장 가까운 두 문장의 거리가 0.47 이상이고(같으면 0, 하나도 안 겹치면 1, 경고 기준 0.3), 끝부분 입술 모양이 겹치는 길이는 최대 3입니다(경고 기준 4).
- **목록 밖 말 사전 점검**: 조정 참가자 P01·P03의 병실 명령 촬영과 문장 촬영 가운데 창이 하나인 366클립(P01 184, P03 182)을 썼습니다. 이 클립은 모두 예시 목록 밖의 말입니다(기본 명령 20개, 명령과 비슷한 함정 문장, 짧은 긴급말, 기침·하품·침 삼키기 같은 말 아닌 입 움직임, 촬영용 지정·자유 문장). 저장해 둔 인식 특징(CTC 직전 특징)으로 예시 10문장의 점수를 다시 계산해 병실 기준(1·2등 차이 0.70, 1등 점수 −2.90, 글자 규칙만, 등록 없음)으로 판정했습니다. 다시 계산한 점수는 서버가 그때 낸 기본 명령 점수와 같았습니다(차이 0).

  | 판정 | 366클립 중 | P01 184 | P03 182 |
  |---|---:|---:|---:|
  | 예시 문장으로 표시(일반 요청·빨간 카드) | **0** | 0 | 0 |
  | 긴급 가능성(1·2등에 예시 긴급 문장) | **11** (3.0%) | 2 | 9 |
  | 고르지 않음 | 355 | 182 | 173 |

  - 기본 명령을 말한 클립 140개도 예시 문장으로 표시된 것은 0개입니다(긴급 가능성 2개).
  - 1·2등 차이 0.70을 넘은 클립은 47개였지만 모두 1등 점수가 −2.90보다 낮아 표시되지 않았습니다. 문장 수가 적은 목록은 1·2등 차이가 커지기 쉬워서, 목록 밖 말을 막는 일은 주로 1등 점수 기준이 맡습니다.
  - 같은 방법으로 기본 목록을 채점하면 문장 촬영 185클립 중 긴급 가능성이 125개(대부분 W10·W03)입니다.
- **이 수치의 한계**: 예시 문장은 후보 문장 74개 가운데 **바로 이 366클립에서 알림이 적게 나오도록 골랐습니다.** 그래서 수치가 실제보다 좋게 나왔을 수 있습니다. 한 사람 자료만으로 고른 목록을 다른 사람에게 적용해 보면 P01 클립만으로 고른 목록(예시 목록과 9문장이 같음)은 P03에서 긴급 가능성 10/182, P03 클립만으로 고른 목록(예시 목록과 같음)은 P01에서 2/184였고, 둘 다 표시는 0이었습니다. 처음 보는 사람(P02) 자료는 열지 않았습니다.
- **예시 문장은 이 프로젝트에서 새로 쓴 문장입니다.** AI Hub 문장 목록과 비교해 같거나 포함되는 문장이 없었습니다(한글만 비교, 가장 가까운 문장도 음절 편집 거리 비율 0.71 이상).

### 5-2. 측정하지 않은 것

- **내 목록 문장을 실제로 말했을 때 맞게 고르는지.** 예시 10문장이나 사용자가 쓴 문장을 찍은 영상이 없습니다. 위 점검은 "목록 밖 말을 잘못 고르지 않는가"만 봤습니다.
- 내 목록에서 입 모양 등록이 얼마나 도움이 되는지, 등록 거리 D 0.26이 내 목록에도 맞는지.
- 사용자가 직접 쓴 다른 목록의 거짓 알림. 목록이 바뀌면 결과도 바뀝니다.
- 처음 보는 사람, 실제 웹캠 환경.

그래서 병실 화면은 내 목록을 쓰는 동안 **"성능을 측정하지 않은 목록"** 을 늘 표시합니다. 시연에서 정확도를 말할 때는 기본 목록의 측정값만 씁니다.

## 7. 시연 뒤 지우기 — 등록 자료는 개인 자료입니다

입 모양 등록 파일(명령별 입 모양 특징)은 개인 자료입니다. 영상은 저장하지 않지만, **시연이 끝나면 지웁니다.**

- **목록과 그 등록을 함께 지우기**: #lists에서 목록을 고르고 [이 목록 지우기] → 확인. 그 목록의 등록 폴더도 함께 지워집니다.
- **목록은 남기고 등록만 지우기**: [설정] → "명령 목록"을 그 목록으로 두고 → "내 입 모양 등록"에서 등록을 고르고 **[이 등록 지우기]** → 확인.
- **기본 목록 등록**은 따로 지웁니다(시연노트북 설치안내 5-2절).
- 서버를 끈 뒤 폴더를 통째로 지워도 됩니다.
  - 등록(기본 목록과 내 목록 모두): `C:\SilentTalk\backend\data\ward_profiles`
  - 내 목록 문장: `C:\SilentTalk\backend\data\ward_lists` (개인 자료는 아니지만, 남기지 않으려면 지웁니다)
- 새 묶음을 덮어써도 두 폴더는 지워지지 않습니다. 노트북을 돌려주기 전에 두 폴더가 비었는지 확인합니다.
- **문장을 고쳐도 옛 등록 자료는 남습니다.** 입 모양 문장을 고친 뒤 다시 찍어도, 고치기 전 문장의 입 모양 특징 파일은 화면에 보이지 않을 뿐 그 등록 폴더에 남아 있습니다(문장을 되돌리면 다시 쓰려고). 이 자료는 **목록을 지우거나 그 등록을 지울 때** 함께 지워집니다. 시연 뒤에는 위 방법으로 꼭 지웁니다.

## 8. 문제 해결

| 증상 | 해결 방법 |
|---|---|
| 병실 화면에 "내 목록 ‘…’을 쓸 수 없어요: 내 목록을 찾을 수 없어요"(또는 "…서버에서 내 목록을 가져오지 못했어요")가 보이고 녹화가 안 됨 | 고른 목록이 지워졌거나 서버와 연결이 끊긴 것입니다. 이때도 **스위치 3번 긴급 호출은 됩니다.** [설정]에서 다른 목록이나 기본 목록을 고릅니다. 기본 목록으로 저절로 바뀌지 않는 것은 일부러 그렇게 만든 것입니다(어느 목록으로 판정하는지 헷갈리지 않게) |
| 녹화하면 "내 목록에 오류가 있어요" | #lists에서 그 목록의 빨간 줄을 고치고 다시 저장합니다 |
| 저장하면 "다른 곳에서 이 목록이 바뀌었거나 지워졌어요" | 다른 탭이나 창에서 같은 목록을 먼저 고쳤습니다. 아무것도 덮어쓰지 않았습니다. [이 목록 다시 불러오기]를 누르고 다시 고칩니다 |
| 저장하면 "같은 ID의 목록이 이미 있어요" | 다른 탭에서 같은 ID로 먼저 만들었습니다. 목록 ID를 바꿔 저장하거나, 왼쪽에서 그 목록을 열어 고칩니다 |
| 등록 화면에 "목록이 바뀌었어요" | 등록하는 동안 다른 곳에서 목록을 고쳤습니다. 방금 녹화는 저장하지 않았습니다. 화면이 새 목록으로 다시 열리면 바뀐 문장만 다시 찍습니다 |
| 목록을 지우면 "내 목록을 지우지 못했어요. 잠시 뒤 다시 지워 주세요" | 같은 목록으로 녹화를 처리하는 중이었을 수 있습니다. 잠시 뒤 다시 지웁니다. 다시 지우면 남은 등록 파일까지 지워집니다 |
| [설정]에 [내 목록 관리]가 없음 | 이 기능 전에 만든 묶음입니다. 맨 위 "먼저 확인"처럼 묶음을 다시 만들어 설치합니다 |
| 결과가 계속 "고르지 않음" | 상태 줄에서 지금 목록의 등록이 다 찍혔는지 봅니다. 문장이 짧거나 서로 비슷하면 경고를 보고 고칩니다 |
| 간호사 카드에 "내 목록: …" 꼬리표가 붙음 | 정상입니다. 내 목록의 U05와 기본 목록의 W05는 서로 다른 카드로 나뉩니다. 목록을 고친 뒤(문장·순서가 바뀜) 온 같은 번호의 요청도 고치기 전 카드와 합치지 않고 따로 보입니다. 스위치 3번 긴급 호출은 목록과 상관없어 꼬리표가 붙지 않습니다 |
| 연습 모드에서 내 목록이 안 보임 | 정상입니다. 연습 모드는 늘 기본 목록을 씁니다 |
