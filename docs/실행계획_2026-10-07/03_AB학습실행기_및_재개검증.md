# 새 실행계획 3단계 — A/B 학습 실행기와 저장·재개 검증

작성일: 2026-10-07. [2단계 파일럿](02_고정8문장_입력_교사특징_파일럿.md)에서 준비한 고정8문장과 교사 특징을 사용했다.

## 결과

**자체 경량 모델의 A/B 학습 실행기를 구현했고, 실제 GPU 역전파·가중치 갱신·체크포인트 저장·새 프로세스에서의 재개를 검증했다.** 이 설정의 소규모 학습은 현재 RTX 3080에서 정상 동작한다. 추가 자료 다운로드나 외부 학습 환경은 이번 단계에 필요하지 않았다.

이번 학습은 실행 가능성과 재개 정확성을 확인하는 짧은 검증이다. A/B 인식 성능을 비교하는 본학습이나 웹캠 평가를 완료한 것은 아니다. 생성한 가중치는 별도 실험 폴더에 보관했고 서비스 모델에 적용하지 않았다.

## 비교 학습 방식

학생은 기존 `lipnet-compact-v1` 구조를 유지한다. 3D CNN의 시공간 특징을 프레임별256차원으로 바꾸고, 양방향 LSTM과 CTC로 한국어 자모를 예측한다.

- **A:** 기존 CTC 손실만 사용한다.
- **B:** 같은 CTC에 교사 특징 보조 손실을 가중치1로 더한다. 학생의 dropout 이전256차원 특징을 학습 가능한 선형 adapter로512차원에 연결하고, 정규화한 교사 특징과의 거리를 줄인다.

교사 모델은 학습 프로세스에 적재하지 않는다. 2단계에서 저장한 FP32 특징만 읽으며 교사 쪽 역전파는 없다. 음성도 사용하지 않는다.

두 경로는 같은 난수 시드42에서 새 학생·adapter를 만들었다. 과거 학습 가중치나 파일럿 이전 가중치를 이어 쓰지 않았다. A에서도 같은 adapter를 생성해 초기 난수 소비를 맞추지만, A에서는 adapter를 계산·최적화에 사용하지 않는다. B에서는 학생과 adapter를 함께 최적화하고 둘을 합친 기울기 크기를 제한한다.

고정한 조건은 Adam 학습률0.001, betas=(0.9,0.999), eps=1e-8, weight decay=0, 전역 기울기 norm 상한1이다. 한 번에 가변 길이 문장1개를 처리하고, 문장2개의 손실을 평균해 기울기를 누적한 뒤 한 번 갱신한다. 학생은 GPU FP32, CTC는 CPU FP32에서 계산하되 기울기는 GPU 학생으로 이어진다.

실제 검사에서 학생의31개 파라미터 텐서 모두 유한한 비영 기울기를 받았다. B의 adapter 텐서2개도 기울기를 받고 바뀌었으며 A의 adapter는 그대로였다. 매 업데이트 후 기울기 norm은1 이내였고, 특징을 가져오는 임시 hook도 남지 않았다.

## 실제 저장·재개 검사

먼저 A/B를 각각4업데이트 연속 실행하고 매 업데이트의 상태를 저장했다. 이후 별도 Python 프로세스에서3번째 체크포인트를 불러와4번째 업데이트만 다시 계산했다. 두 실행의 자료 순서, 난수 상태, 학습 설정을 동일하게 유지했다.

| 항목 | A | B |
|---|---:|---:|
| 복원 직후 전체 상태 | 정확히 일치 | 정확히 일치 |
| 다음 업데이트 후 상태 배열 최대 절대 차이 | 1.862645149230957e-9 | 3.725290298461914e-9 |
| 다음 업데이트 후 난수 상태 | 정확히 일치 | 정확히 일치 |
| 사전 허용 범위 판정 | 통과 | 통과 |

저장·복원은 정확했고, 다음 GPU 계산에서는 약10억분의2~4 수준 차이가 발생했다. CUDA 공간 풀링 역전파 등의 연산 특성을 고려해 처음부터 복원 직후의 정확 일치와 다음 업데이트의 수치 비교를 구분했다. 결과를 본 뒤 허용 오차를 넓히지 않았다.

사전 기준은 학생·adapter atol=1e-6/rtol=1e-5, Adam 1차 모멘트1e-7/1e-4, 2차 모멘트1e-10/1e-4, 손실1e-5/1e-5, 갱신 전 기울기 norm1e-4/1e-4다. Adam step과 난수 등 나머지 상태는 정확 일치를 요구했다. 실제 차이와 모든 배열별 판정은 `results/replay_audit.json`에 있다.

이 검사는 같은 장치·실행환경에서 다음1회 업데이트의 재개를 검증한 것이다. 다른 GPU·라이브러리 버전 또는 긴 학습 전체의 비트 동일성을 보장하지 않는다. 실행기는 계획·자료·코드·실행환경·학습군·현재 위치가 달라지면 재개를 거부한다.

## 메모리·시간·저장 공간

| 항목 | A | B |
|---|---:|---:|
| 최대 할당 메모리 | 484.37MiB | 486.27MiB |
| 최대 예약 메모리 | 1,012MiB | 1,016MiB |
| 첫 업데이트 | 0.667초 | 0.537초 |
| 이후 연속 업데이트 | 약0.207~0.224초 | 약0.249~0.257초 |
| 새 프로세스의 재개 업데이트 | 0.463초 | 0.534초 |

시간은 문장2개의 순전파·CTC 계산·역전파·기울기 제한·Adam 갱신을 동기화해 측정한 값이다. 자료 검증·초기 적재·체크포인트 기록·상태 해시·추가 진단 시간은 제외한다. 메모리 최대값은 학습 업데이트 직후 추가 진단용 임시 텐서를 만들기 전에 기록했다. 예약 메모리는 PyTorch의 캐시를 포함하며, 실제 할당 메모리보다 크게 나타날 수 있다.

200프레임 문장을 포함한185~200프레임 입력을 검증했다. 한 번에1문장 처리·2문장 누적·FP32라는 현재 조건의 결과이며 배치나 해상도를 늘린 설정에 그대로 적용하지 않는다.

증거 보존용 체크포인트10개의 합계는405,626,470바이트, 약386.84MiB다. 체크포인트에는 추론 가중치 외에 Adam과 난수 상태도 포함된다. 실행기는 저장 간격을 지정할 수 있고, 향후 본학습 규약은100업데이트마다 저장하도록 설정해 매번 큰 파일이 쌓이지 않게 했다.

## 중단된 작업을 이어가는 경로

`runner.py`는 고정된 예산 안에서 구간 종료와 저장 상태 재개를 지원한다. `train.py`는 이번4업데이트 비교 검증용 진입점이다.

실제 작업이 종료되어 최종 `run_result.json`이 없는 상황도 처리하도록 `resume_segment.py`를 추가했다. 완료된 체크포인트와 대응 SHA 기록을 확인한 후 새 복구 폴더에서 이어간다. 기존 파일은 덮어쓰지 않는다. 파일이 쓰이던 중 종료되어 체크포인트나 대응 기록이 불완전하면 그 파일은 거부하며, 이전의 완전한 저장 상태를 사용해야 한다.

GPU 재개 동작은 위 실제 실행으로 검증했다. 추가 복구 진입점은 최종 결과 파일 없이 연결되는지, 예산을 늘리지 못하는지, 잘못된 경로를 거부하는지를3개 검사로 확인했다. 이 진입점 때문에 추가 GPU 학습을 실행하지는 않았다.

예시 명령은 프로젝트 루트에서 실행한다. 다시 실행하면 실제로1업데이트를 수행하므로 완료 결과를 보기 위해 실행할 필요는 없다.

```powershell
.venv-gpu/Scripts/python.exe experiments/local_training_step03_20261007/resume_segment.py --checkpoint experiments/local_training_step03_20261007/runs/B_feature/continuous/update_0003.pt --name manual-recovery
```

현재 진입점은 이번 고정4업데이트 계획의 범위만 허용한다. 전체 자료 본학습은4단계 산출물을 연결한 별도 실행 계획으로 진행한다.

## 본학습 비교 규약과 다음 단계

`comparison_protocol.json`에 향후 비교 조건을 고정했다. 이 파일은 설계 규약이며 전체 학습을 실행한 결과가 아니다.

- 학습441문장·개발71문장, 기존 분할과 시간 보정값을 유지한다.
- 시드42·43 각각에서 A/B를 같은 새 초기값으로 시작하고, 경로당3,200업데이트·문장2개 누적을 사용한다. 같은 시드의 자료 순서는 A/B에서 동일하게 저장한다.
- 기본 손실·보조 손실 가중치·옵티마이저·FP32 조건은 이번 검증과 같다. 매100업데이트와 종료 시 저장한다.
- 주 비교 대상은 고정된3,200번째 상태다. 개발 결과를 보고 유리한 중간 체크포인트나 시드를 고르지 않는다.
- 정상·정지 영상·프레임 순서 섞기 조건에서 같은 greedy 디코딩을 사용한다. 주 지표는 내부 공백을 포함한 NFC 문자 CER, 즉 전체 편집 거리 합계를 전체 정답 문자 수로 나눈 값이다. 문장 완전 일치 등도 함께 기록한다.
- 개발 자료는 기존8명의 녹화를 나눈 자료이며 최종 미학습 화자·웹캠 평가가 아니다. 개발 결과만으로 일반화 성능을 확정하지 않는다.

**다음4단계는 전체512문장의 시간 보정 입력과 학습441문장의 교사 특징을 준비하고 독립 검산하는 작업이다.** 개발71문장은 학생 평가 입력만 준비한다. 완료된8문장 파일럿을 유지하고, 새 전체 산출물의 해시와 자료 순서를 묶은 실행 계획을 확정한 뒤5단계 본학습으로 진행한다.

추가 다운로드는 현재 선정한441/71 실험에 필요하지 않다. 자료 확대가 필요한 단계에서는 사용자에게 먼저 알린다.
