## 어떻게 읽도록 바뀌었는가

기존 `feature_transfer_step07/data_plan.json`은 G: 경로를 포함한 과거 실험 계획으로 그대로 보존했다. 새 `local_source_step01_20261007/d_source_plan.json`이 각 녹화를 D: TAR의 정확한 내부 파일명, 바이트 위치, 길이, SHA-256에 연결한다. 원래 문장 ID·정답·프레임 수·학습/개발 분할·시간 보정값은 바꾸지 않았다.

1. 기존 계획과 10월 2일 무결성 검사 근거의 해시를 검증한다.
2. 선택한 TAR가 검사 당시 크기·수정 시각과 일치하는지 확인한다.
3. 필요한 녹화 한 개의 영상과 라벨을 프로젝트의 임시 폴더로 복사하면서 파일 전체 SHA-256을 대조한다. 이번 재현 검사에서는 연결 확인을 위해 음성도 복사·해시 검사했다.
4. 기존 전처리 함수를 수정하지 않고 임시 경로로 실행한다. 영상의 실제 FPS, 라벨 좌표, 문장 정보 등 기존 검증을 그대로 적용한다.
5. 결과에는 원래 문장 레코드와 실제 D: 출처를 함께 기록하고 임시 사본을 지운다. 오류가 나도 해당 실행에서 만든 임시 사본을 정리한다.

음성은 출처 확인용으로만 읽었으며 모델 입력으로 전달하지 않았다. 앞으로 입술 입력을 만들 때는 영상·라벨만 요청할 수 있다. G: 자료를 읽거나 변경하지 않았고, D: 원본도 읽기 전용으로 사용했다.

기존 G: 파일의 수정 시각을 임시 파일에 억지로 설정하지 않는다. 임시 파일의 실제 상태를 검사하며, 기록되는 출처도 D: TAR임을 명시한다.

## 저장 공간과 사용 방법

59녹화의 영상·라벨·음성 합계는 약 **20.14GiB**지만 동시에 보관하지 않는다. 녹화 한 개씩 처리할 때 최대 임시 파일 합계는 **480,586,070바이트, 약 458.32MiB**다. 복사 후에도 최소 10GiB 여유 공간이 남도록 검사한다. 이는 선택한 원본의 임시 복사 공간이며, 앞으로 생성할 전처리 캐시·교사 특징·학습 체크포인트 용량은 별도로 산정해야 한다.

현재 C:의 프로젝트 폴더에 작은 임시 사본이 생기므로 C: 사용량이 완전히 0은 아니다. 그러나 전체 자료 추출이나 G: 동기화는 필요하지 않다. TAR는 D:에 그대로 두면 된다. 이번 단계에 추가 데이터 다운로드는 필요 없다.

구현 파일은 `experiments/local_source_step01_20261007/`에 있다.

| 파일 | 역할 |
|---|---|
| build_plan.py | 검사 근거와 기존 문장을 연결하고 매핑·현재 원본 상태 검증 |
| d_source_plan.json | 고정한 D: 파일 참조 계획 |
| tar_source.py | 제한된 바이트 범위 복사, SHA 검사, 공간 확인, 임시 파일 정리 |
| adapter.py | 기존 전처리에 임시 경로를 전달하고 원래 문장 정보·실제 출처 보존 |
| reproduce.py | 이번 고정 4문장 재현 검사 실행 |
| results/reproduction_gate.json | 실제 실행 결과와 프레임별 근거 |
| results/independent_validation.json | 로컬 근거 독립 검산 결과 |

프로젝트 루트 PowerShell에서 연결 상태만 다시 확인하는 명령:

```powershell
.venv-tokenizer/Scripts/python.exe experiments/local_source_step01_20261007/build_plan.py --verify-sha256 d3a26f26e0f87f42928dcfff3f644fff2eaf0ab63e79d3213bd3d7bb5f0cadc9
```

이 명령은 로컬 검사 기록을 읽고 D: TAR의 현재 파일 상태를 확인한다. 영상 전체를 다시 디코딩하거나 학습을 시작하지 않는다. 완료된 계획과 재현 결과는 실수로 덮어쓰지 않도록 재생성을 거부한다.

## 확인 범위와 다음 단계

10월 2일에 수행한 정면 영상 300개·음성 300개 전체 디코딩 검사를 재사용했다. 오늘은 59녹화 전체의 payload를 다시 해시 검사하지 않았으며, 실제로 읽은 4녹화의 12개 파일만 다시 해시 검사했다. 선택한 파일은 앞으로 꺼낼 때마다 해시를 검증한다. 공식 배포처 체크섬 대조, 전체 정답 전사 검수, 모든 문장의 입술 동기 확인까지 완료했다는 의미는 아니다.

신규 120문장 확대 자료는 이번 계획에 포함하지 않았다. C025의 시간 오류 자료도 포함하지 않았다. 기존 캐시·가중치·서비스 설정·최종 평가 자료는 변경하지 않았다.

**다음 2단계는 고정된 8문장으로 시간 보정 학생 입력과 교사 입력을 만들고, 원본 프레임 대응·입술 영역·실제 특징 추출 비용과 GPU 메모리를 확인하는 작업이다.** 교사 입력과 특징 추출이 타당한지 먼저 확인한 뒤 512문장으로 확대한다.

2단계에서 새 출력 디렉터리와 D: 출처 검증을 포함한 실행·검산 경로를 연결해야 한다. 기존 `verify_inputs.py`는 G: 기반 출처 형식을 강제하므로 그대로 사용하면 안 된다. D: 출처를 검증하는 별도 검사 경로를 마련하고 원래 픽셀·토큰·프레임 대응 검사를 유지한다. 이번 단계에서는 8문장 파일럿, 교사 특징 추출, 새 모델 학습을 실행하지 않았다.
