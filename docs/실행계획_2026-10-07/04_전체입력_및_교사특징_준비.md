# 새 실행계획 4단계 — 전체 입력과 교사 특징 준비

작성일: 2026-10-07. [3단계 학습 실행기·재개 검사](03_AB학습실행기_및_재개검증.md) 이후, 고정된 전체 자료를 준비한 결과다.

## 무엇을 어떻게 준비했는가

1단계에서 연결한 D:의 `TS1.tar`, `TS10.tar`, `TL1.tar`, `TL10.tar`를 사용했다. 기존 부모 계획의 문장 ID·텍스트·토큰·분할·시작/종료 시각·보정값은 변경하지 않았다. 과거 G: 경로는 원래 계획의 기록으로 남아 있으며, 이번 실제 파일 읽기는 검증된 D: TAR를 통해 이루어졌다.

한 녹화의 영상·라벨만 프로젝트 내 임시 폴더로 꺼내 해시를 확인하고, 해당 문장들을 처리한 뒤 임시 원본을 정리했다. 59개 고유 영상·라벨의 용량 합계는 18,153,281,778바이트(약16.91GiB)이며, 가장 큰 한 녹화의 임시 원본은 414,312,500바이트(약395.12MiB)다. 이 합계는 디스크의 실제 누적 읽기량을 측정한 값이 아니다. 전체 TAR 압축 해제나 Google Drive 동기화를 하지 않았고, 완료 후 임시 원본 파일은 0개다.

학생 입력은 기존 규약인 **25fps·RGB·96×96·입술 영역 여유 20%**를 유지했다. 입력은 가변 길이의 uint8 배열로 저장했으며, 학습에서 기존 정규화를 적용한다. 학습 441문장에 대해서는 교사 추출용 **원본 FPS·BGR·96×96·여유 0%** 영상도 함께 저장했다. 같은 원본 프레임을 가리키는 정수 인덱스로 두 입력을 연결하고, 교사 입력에는 앞뒤 실제 2프레임 문맥을 포함했다. 독립 검사에서 문맥 경계 잘림은 0건이었다.

개발 71문장의 저장 파일에는 학생 픽셀·학생 프레임 번호·정답 토큰·검증 메타데이터만 있다. 변경하지 않은 전처리의 대응 검사를 유지하기 위해 개발 자료도 준비 과정에서 교사 쪽 픽셀을 임시 계산했지만, 저장 전에 제거했다. 교사 모델 실행기는 개발 NPZ를 열거나 개발용 특징을 만들지 않았다.

교사 특징은 이전에 검증한 OLKAVS 모델의 고정된 시각 특징 추출부를 사용했다. 음성·텍스트 디코더·학생 학습은 실행하지 않았다. 교사 입력 전체 구간의 평균과 표본 표준편차로 정규화하고, 학생 프레임과 정확히 같은 원본 프레임의 512차원 특징을 가져왔다. 교사 상태 해시는 실행 전후 및 기존 파일럿과 같았다.

따라서 웹캠용 자체 모델의 구조는 그대로다. 교사의 저장 특징은 다음 단계에서 자체 모델의 학습을 돕는 보조 목표로 사용한다.

## 검사 결과와 범위

입력 독립 감사는 512개 NPZ와 메타데이터 해시, 한글 자모 인코딩, 보정된 시간 범위, 25fps 프레임 선택, 원본 영상의 물리적 경계, 학습·개발 분할을 검사했다. 학습 입력은 학생·교사 양쪽의 프레임 추적과 정수 대응도 확인했다. 기존 8개 항목은 원래 파일럿 목록과 정확히 일치했다.

특징 독립 감사는 NumPy로 저장된 441개 특징의 모양·유한값·비영 벡터·시간에 따른 변화·프레임 연결·정규화·출처를 검사했다. 모든 특징 행이 유한하고 0이 아니었으며, 정확히 동일한 특징만 반복하는 문장은 없었다. 모든 문장에서 512차원 모두 시간 변화가 있었다. 교사 입력의 평균·표본 표준편차를 FP64로 별도 계산한 값과 기록된 FP32 값의 최대 차이는 각각 약1.16e-5와1.91e-6이었다.

59개 녹화마다 선정 문장 중 가장 이른 문장 하나를 골라 처음·중간·끝 프레임을 확인했다. 표시된 177개 이미지에서 입술이 잘리거나 잘못된 영역·빈 화면·검은 화면이 저장된 문제는 보이지 않았다. 녹화별 얼굴 방향과 영역 크기 차이는 남아 있다. 표본 시트는 `experiments/local_dataset_step04_20261007/review/`에 저장했다.

이 검사는 전처리와 특징 저장의 일관성을 확인한다. 독립 감사는 원본 영상을 다시 디코딩하거나 교사 추론을 다시 실행한 검사는 아니며, 저장된 배열·추적 정보·고정 코드·이전 원본 검사 및 재현 근거를 검산했다. 이미지 검수도 전체 512문장/58,419프레임 중 표본만 확인한 것이다. 정답 문장을 모두 청취 검수했다거나 특징 전달의 학습 효과·웹캠 인식률을 입증했다는 의미는 아니다.

## 고정한 인계 계획과 다음 단계

`full_data_plan.json`에 입력·특징·독립 감사·표본 검수의 파일 해시와 기존 비교 규약을 연결했다. 시드42·43 각각 **3,200업데이트×2문장**의 전체 학습 순서도 저장했다. 같은 시드에서는 A/B가 같은 순서를 사용하며 개발 문장은 학습 순서에 들어가지 않는다.

**다음 5단계는 이 자료로 자체 경량 모델의 A/B 본학습을 실행하는 단계다.** A는 CTC만, B는 같은 CTC에 교사 시각 특징 보조 손실을 더한다. 두 시드 모두 새 학생·adapter 초기값에서 시작하고, 이전 학습 가중치나 3단계 점검용 체크포인트를 이어 쓰지 않는다. 경로당 고정3,200업데이트를 실행한 후 정상·정지 영상·프레임 순서 섞기 조건을 비교한다.

3단계의 실행 CLI와 자료 로더는 여전히 고정8문장 점검용이다. 5단계에서는 전체 입력 및 기존8개/신규433개 특징의 서로 다른 출처를 검증하는 전체 자료 로더·진입점을 연결하고, 그 코드·실행환경을 별도 실행 계획에 고정한 뒤 첫 학습 업데이트를 수행해야 한다. 이번 인계 계획은 데이터와 순서를 고정한 산출물이며 본학습을 실행한 결과가 아니다.

개발71은 기존8명 안에서 녹화를 나눈 자료다. 이전 실험에서 사용한 이력이 있으므로 미사용 최종 시험이나 새 화자·실제 웹캠 성능으로 해석하지 않는다. 추가 학습 데이터가 필요한 단계에서는 사용자에게 먼저 알린다.
