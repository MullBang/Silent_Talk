# 녹화형 계획 2단계 — 전사·어절 경계 정렬 파일럿

작성일: 2026-10-12. 최종 자동 산출물: `results/stage2_summary_r2.json`.

**자동 처리와 검산을 마쳤고, 실제 어절 경계의 청취·시각 검수는 남아 있다.** 자동 후보를 학습 정답으로 승인하거나 립리딩 모델을 새로 학습하지 않았다.

## 이번에 확인한 결론

기존 D: 자료로 경계 검수용 16문장을 만들 수 있었다. 원본 WAV와 MP4의 시간 대응, 입술 영역 추출에는 이번 점검 범위에서 문제가 없었다. 다만 음성 CTC 정렬의 비공백 토큰 구간은 실제 발음 전체보다 좁게 잡힐 수 있다. 따라서 **자동 시각으로 단어를 곧바로 잘라 학습하는 방식은 아직 적절하지 않다.**

정렬 후보 125어절 중 78개가 기존 69토큰 시각 CTC의 최소 길이 조건을 만족했다. 같은 후보를 연속 2~4어절로 묶으면 285구절 중 273개가 길이 조건을 만족했다. 짧은 구절을 함께 검토할 이유는 있지만, 이 숫자만으로 경계가 정확하다거나 인식 성능이 좋아졌다고 말할 수는 없다. 부족한 47어절도 실제 발음이 너무 짧아 학습이 불가능하다는 뜻이 아니다. 먼저 정렬 후보가 발음을 충분히 포함했는지 확인해야 한다.

## 원본과 검수 자료

1단계의 8화자·16녹화·16문장을 그대로 사용했다. D: TAR의 영상·음성·라벨 총48개 멤버, 5,850,530,249bytes를 기존 오프셋으로 읽으며 크기와 SHA-256을 검증했다. 한 녹화씩 처리하고 임시 원본 사본을 삭제해, 전체 압축파일을 풀거나 G: 동기화를 거치지 않았다.

문장 음성 합계는 60.3111875초다. 각 문장에 다음 자료를 만들었다.

- 원라벨 WAV 시각의 본문 `sentence.wav`와 앞뒤0.35초 문맥 `context.wav` — 16kHz mono PCM.
- 같은 문맥의 전체 영상640×360 및 입술96×96 검수 MP4 — 25fps, 음성·영상 시각 보정 적용.
- 원본 멤버 해시, 실제 WAV 시작 샘플, 영상 프레임 시각·번호, ROI 좌표, 원문과 기존 보정값.

검수 미디어는 약19.08MB이며, 재압축한 MP4를 학습 입력으로 재사용하지 않는다. 원문·원본 라벨·과거 캐시·서비스 가중치는 보존했다.

16녹화의 지역 파형 대응은 모두 통과했다. 최소 상관0.999163, 기존 오프셋과 측정값의 최대 잔차는 약20.833µs다. 이 수치는 **음성 시간축 대응의 검사 결과**이며 입술 동작의 의미나 어절 경계 정확도는 아니다. 원본 프레임 선택의 시간 반올림은 별도로 최대 약16.7ms가 있을 수 있다.

문맥의 1,786프레임과 MP4 32개 전체 디코딩을 확인했다. 입술 ROI 48표본과 추가 경계 ROI 24표본에서 입술이 포함되는 것을 관찰했다. 이 표본 검사로 모든 프레임의 시각 발화 경계를 확정하지 않는다.

`C002_A_012_035`는 앞뒤 문맥이 이웃 라벨 구간과 겹친다. 문맥은 청취용으로만 쓰고, 본문 전사에 대한 강제 정렬에는 `sentence.wav`만 사용했다.

## 전사 검사와 실제 사용자 답변

기존 로컬 Whisper large-v3를 문장 본문과 문맥에 각각 실행했다. 정답이나 힌트 문장을 모델에 주지 않았으며, 이번에는 Whisper의 단어 시각을 사용하지 않았다. 두 조건의 차이는 독립된 두 모델 비교가 아니다.

자동 전사와 원문이 다른 세 표현을 사용자에게 질문했고, 실제 답변을 다음과 같이 반영했다.

| 문장 | 원라벨 표현 | 사용자 답변 | 이번 파일럿 처리 |
|---|---|---|---|
| C002_A_009_045 | 꿀 | **꿀** | 유지; Whisper의 ‘풀’로 바꾸지 않음 |
| C017_A_008_004 | 거 같아 | **것 같아** | 별도 canonical 전사에서 수정 |
| C312_A_010_010 | 되어 있어 | **돼 있어** | 별도 canonical 전사에서 수정 |

원라벨을 덮어쓰지 않았다. 이 답변은 해당 표현을 확인한 근거3건이며, 문장 전체나 어절의 시작·끝을 모두 승인한 근거가 아니다. 별도 전사로 비교하면 16문장 중15문장은 본문/문맥 두 자동 전사 모두 공백 제외 일치한다. 나머지1개는 사용자가 ‘꿀’을 확인한 문장이다. 자동 일치는 학습 승인과 구별한다.

원응답은 `user_evidence/001_transcript_answers.json`, 두 전사 변경 규칙과 근거 해시는 `canonical_policy_r2.json`에 보존했다.

수정한 전사를 기존 보호 전사와 다시 대조해 충돌0건을 확인했다. 파일럿 안에서는 C293_A_011_018과 C312_A_010_010이 동일한 전체 전사가 됐다. 이 두 문장을 향후 ‘새로운 문장’ 학습/개발 양쪽에 나눠 놓으면 안 된다. 현재는 새 분할을 만들지 않았다. 대조 기록은 `results/canonical_text_overlap.json`이다.

## 정렬 도구와 적용 범위

별도 `.venv-alignment`에 Transformers4.57.6을 준비하고, 기존 GPU 환경의 torch2.10.0+cu128을 읽기 경로로 재사용했다. 기존 환경에 패키지를 설치하거나 버전을 변경하지 않았다. 자료 준비용 한국어 음향 모델은 [kresnik/wav2vec2-large-xlsr-korean](https://huggingface.co/kresnik/wav2vec2-large-xlsr-korean)이며 공개 revision `629c9a3501c10ba128bf3fa1eebb12af3be03f61`의 safetensors와 필요한 설정만 받았다. 모델은 Apache-2.0 표기이고, 이 모델/설정 다운로드는 약1.267GB다. 새 AIHub 원본은 받지 않았다.

음향 모델은 16kHz 파형을 읽고 음향 사전1,205종·blank1204의 확률을 출력한다. **이 사전은 기존 립리딩 모델의 69자모·blank0과 별개**다. 신경망에는 전사를 주지 않고, 저장한 음향 확률과 전사로 별도의 CTC Viterbi 최대 경로를 계산했다. 기존 립리딩 인식 모델은 실행하거나 교체하지 않았다.

`C293_A_012_019`의 ‘탔’은 이 음향 모델 사전에 없다. 해당 문장6어절의 자동 정렬을 보류했다. 글자를 삭제하거나 다른 글자로 바꾸거나 wildcard로 숨기지 않았다. 이는 AIHub 영상 손상이나 원문 오류가 아니라 선택한 정렬 도구의 어휘 제약이다.

지원되는15문장에 대해 자동 경계 후보를 얻었다. 음향 출력은320샘플(20ms) 간격, convolution receptive field는400샘플(25ms)이다. 시각 학습의25fps(40ms)와 다른 시간축이다. 논리 시각은 음향 bin 중심을 기준으로 정했으며 이것을 실제 조음 시작·끝의 정답으로 부르지 않는다. 모델과 입력의 일반 규약은 [Transformers Wav2Vec2 문서](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/wav2vec2)를 참고했다.

사용자 확인으로 바뀐 두 문장은 저장된 확률로 정렬만 다시 계산했다. 이 전사·기하 수정 과정에서 신경망을 다시 실행하지 않았다.

78개와273개는 입력 길이의 기계적 조건을 만족하는 **후보 수**다. 단어 인식 정확도, 학습 완료 수량, 사람 검수 통과 수량으로 인용하면 안 된다. 2~4어절의 겹치는 후보는 서로 독립된 녹화나 독립 표본이 아니다.

경계의 수동 참조 정답이 없으므로 ‘경계 오차 몇 ms’라는 정확도는 산출하지 않았다. `manual_boundary_error_ms`는 `null`이다. 음향 경로 점수도 보정된 confidence가 아니며, 0.5 미만 표시는 검수 우선순위를 위한 휴리스틱이다.

## 발견한 구현 문제와 보정

첫 실행은 음향20ms 구간을25fps로 환산할 때0프레임이 되는 후보를 오류로 처리해 첫 문장에서 중단했다. 해당 코드·실행 계획·첫 posterior를 보존하고, r1에서는0프레임을 길이 부족 후보로 남기도록 수정했다. 프레임 반복 패딩이나 임의 시간 확장은 하지 않았다.

추가 검산에서는 소수점 시간의 뺄셈 순서에 따라0.5프레임 근처 반올림이 달라지는 문제가 확인됐다. 최종 r2는 음향 구간을 **16kHz 정수 샘플 수로 표현하고 `round(Fraction(samples×25,16000))`의 half-even**으로 환산한다. 실제 클립을 만들3단계도 이 규약을 명시적으로 맞춰야 한다. 원래 문장 전처리의 부동소수점 계산을 그대로 가져오면 수량이 달라질 수 있다.

r1 원라벨 및 첫 전사 수정본의79/125는 과거 규약 수치다. 최종 r2의78/125와 혼용하지 않는다. 과거 실패·중간 산출물은 삭제하지 않았다. 실제 음향 신경망 호출은 Whisper32회, Wav2Vec217회(초기 실패에서 저장된1회 포함)이며 시각 모델 호출은0회다.

## 검산과 검수 화면

CTC 구현은 독립 전수열거2,184경로·168조건을 포함하는8개 테스트를 통과했다. 생산 CTC 함수를 불러오지 않는 별도 DP로 저장 확률의 최대 경로·점수·전사 복원, 어절/구절 시간, 자모 최소 길이, 프레임 번호를 다시 검산했다. r1 감사와 최종 r2 감사는 별도 파일로 보존한다.

최종 r2 독립 검산은 통과했으며, 저장된16개 greedy 출력과15개 최적 경로의 점수 차이는0이었다. 이는 저장 확률에 대한 계산의 정확성 검증이고, 음성 모델이나 어절 경계의 실제 정확도 검증은 아니다.

검수 화면: **http://127.0.0.1:8767/review_r2/index.html**

화면에서 문장 음성, 전체 영상, 입술 영상을 함께 재생할 수 있다. 어절을 선택하면 추정 경계와 앞뒤 문맥을 재생하고, 문장 전사·문장 시작끝·어절 음성 경계·입 움직임 범위를 따로 기록한다. 기본값은 모두 미응답이며, 경계 수정은 이유가 필요한 제안으로 저장한다. 화면의 ‘내 검수 기록 내려받기’는 JSON을 내보내며 원라벨이나 학습 상태를 자동으로 바꾸지 않는다.

브라우저에서 실제 본문·어절 재생과 WAV/두 MP4의 로딩을 확인했다. 그 과정에서 사람 판정을 대신 입력하지 않았다. 사용자가 만든 검수 JSON도 후속 가져오기에서 명세 해시·ID·전사·범위와 실제 제출 근거를 확인해야 한다. JSON 안의 reviewer 선언만 사람 인증으로 간주하지 않는다.

## 남은 일과 3단계 진입 조건

1. 현재16문장의 전사 전체와 본문 시작·끝을 실제로 검수한다. 표현3건 확인은 이미 기록돼 있다.
2. 경고 없는 반복 어절부터 실제 발음과 앞뒤 입 움직임이 포함되는지 확인한다. 20ms처럼 지나치게 좁은 후보는 자동 승인하지 않는다.
3. 개별 어절 경계가 모호하면 자연스러운2~4어절 구절을 우선 검토한다. 임의로 문맥만 넓히고 정답을 하나의 단어로 유지하지 않는다.
4. ‘탔’ 문장은 수동 경계 또는 별도 정렬 도구의 파일럿으로 해결하거나, 이유를 남긴 채 보류한다.
5. 확인된 구간만 새 명세에 연결하고, 부모 녹화 단위 분할·중첩 누수·정수시간·실제 추출 프레임을 검증한 다음3단계 자료를 생성한다.

**현재 필요한 것은 추가 대용량 데이터가 아니라 경계 품질 확인이다.** 이번 후보를 곧바로 학습에 투입하지 않는다. 기존의 문장 직접 학습과 단계 학습 비교는4~5단계에서 새 계획을 고정한 뒤 수행한다.
