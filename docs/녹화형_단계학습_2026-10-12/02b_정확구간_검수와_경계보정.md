# 녹화형 2단계 후속 — 정확 구간 검수와 끝 경계 보정

작성일: 2026-10-13. 작업 폴더: `experiments/offline_boundary_review_step02b_20261013/`.

**구절 3개의 음성 범위를 사용자 청취로 확인했다. 그중 1개는 끝이 잘린 것으로 의심돼 종료를 0.12초 늘린 후보를 만들었고, 사용자가 새 후보는 온전히 들린다고 확인했다. 입술 움직임의 범위와 부모 문장 전체 검수는 아직 미완료이며, 학습 자료 승인이나 새 학습은 수행하지 않았다.**

## 이번에 바꾼 이유

이전 화면은 어절만 표시했고, 재생 버튼은 기본으로 앞뒤 0.12초를 붙였다. 또한 30ms 간격 타이머로 재생을 멈췄다. 매우 짧은 자동 후보에서는 사용자가 실제 후보 밖의 소리를 듣고 온전하다고 판단할 수 있었다. 285개 연속 구절 후보도 기존 화면에서는 직접 검수할 수 없었다.

새 화면은 어절125개와 구절285개를 모두 보존하고, 8화자의 구절8개를 우선 검토 순서로 제시한다. 이 선택은 검수 부담을 줄이기 위한 예시 선정이며 무작위 표본, 독립 시험군, 좋은 경계만 고른 학습 선정이 아니다. 서로 겹치는 구절은 독립 예시로 계산하지 않는다.

- **후보 그대로 재생:** 16kHz PCM의 정확한 시작 샘플과 길이를 WebAudio에 전달한다. 문맥이나 반복 패딩을 추가하지 않는다.
- **앞뒤 문맥 재생:** 앞뒤 최대0.20초를 별도 버튼으로 재생하며 비교용이라고 표시한다.
- **문장 전체 재생:** 기존 문장의 실제 음성 샘플 범위를 사용한다.
- 얼굴/입술 영상과 ±0.04초 이동을 제공한다. 브라우저 탐색과 검수용 재압축 영상이므로 원본 프레임 수준의 정밀 동기를 보장하지 않는다.
- 문장 전사, 문장 경계, 개별 구절 전사, 음성 경계, 시각 범위를 각각 기록한다. 미응답은 그대로 남긴다.

초기 브라우저 시험에서 영상 탐색이 시작 위치로 돌아가는 현상도 관찰했다. 로컬 서버에 HTTP 바이트 범위 요청(206) 처리를 추가하고, 화면은 탐색 완료와 실제 시각을 확인한 뒤 재생하도록 보완했다. 영상 이동 실패를 정상 동기 재생으로 표시하지 않도록 했다.

## 실제 사용자 청취 결과

질문에 쓴 음성은 문맥 재생이 아닌, 별도로 저장한 정확한 PCM 절단 파일이다.

| 구절 | 원래 후보에 대한 답변 | 처리 |
|---|---|---|
| C002_A_009_045 · 못 꿀 것 같아 | 온전히 들림 | 해당 구절 음성 범위 확인 |
| C017_A_008_004 · 못살게 구는 것 같아 | 온전히 들림 | 해당 구절 음성 범위 확인 |
| C312_A_010_010 · 정말 잘 돼 있어 | 맨 끝에 “어” 부분이 살짝 잘린 것 같음 | 원래 후보는 잘림 의심으로 보존 |
| 같은 C312 구절, 끝 +0.12초 | 이제 온전히 들림 | 수정 후보의 음성 범위 확인 |

C312 수정은 문맥 WAV 기준 시작30,920샘플을 유지하고 끝48,200→50,120샘플로 늘린 것이다. 이는1,920샘플/16kHz=0.12초이며, 부모 문장 끝53,154샘플 안에 있다. 기존25fps 유리수 half-even 계산으로27→30프레임이고, 전사의 CTC 최소 길이는19프레임이다. **0.12초는 이번에 시험한 수정 폭이지, 실제 경계 오차를 정밀 측정한 결과가 아니다.**

최신 명세에는 기존410후보와 별도 수정1후보, 총411개가 있다. 원래 잘림 의심 후보는 수정 후보로 덮어쓰지 않았다. 최신 음성 확인은3개 구절이며, 원래 후보와 수정 후보를 각각 독립 성공 예시로 세지 않는다.

세 구절의 확인을 부모 문장 전체 승인, 입술 경계 승인, 어절 각각의 승인으로 확대하지 않는다. 답변은 `user_evidence/001_phrase_audio_answers.json`과 `002_repaired_audio_answer.json`에 질문ID·원문 답변·재생 파일 해시·샘플 범위와 함께 보존했다. 화면에서는 채팅 근거를 별도로 보여주고, 사용자가 누르지 않은 화면 선택 항목을 자동으로 채우지 않는다.

## 검증과 보존

기존2단계의 동결 산출물74개가 그대로임을 확인했다. 독립 검산은410후보의 전사·정수 샘플 시각·원본 시간 기준·69토큰 CTC 조건을 재계산했다. 질문용16WAV는 원본 문맥 PCM의 해당 구간과 바이트 단위로 같고, 문맥은 앞뒤3,200샘플씩이다. 수정 WAV도 별도 독립 검산에서 원본 PCM과 일치했다.

검수 JSON 검증기19개 테스트가 통과했다. 해시·ID·전사·샘플 범위 불일치, 중복 JSON 키, NaN/Inf, 미응답, 잘못된 승인 필드, 길이 미달, 기존 파일 덮어쓰기를 검사한다. 유효한 JSON이라는 사실만으로 사람의 실제 제출이나 학습 승인을 인증하지 않는다. 실제 UI 내보내기 파일의 가져오기는 아직0건이며, 이번 실제 답변은 채팅 근거 파일로 따로 저장했다.

서버는127.0.0.1에만 바인딩하고 화면과 선언된 미디어만 제공한다. 원본을 복사하지 않고 기존 검수 미디어를 읽는다. 추가 AIHub 다운로드·음향 신경망 실행·시각 모델 추론·새 학습·서비스 가중치 변경은 모두0이다.
