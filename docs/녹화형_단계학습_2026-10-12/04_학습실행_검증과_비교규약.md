# 녹화형 4단계 — 학습 실행 검증과 비교 규약

작성일: 2026-10-13. 사용자 목표는 **30초 미만 웹캠 녹화 후, 음성 입력 없이 입술 영상으로 한국어 텍스트를 추출하는 것**이다. 이 문서의 단계 번호는 녹화형 계획을 따른다.

## 이번 단계에서 확인한 것

3단계에서 준비한 구절·문장 캐시를 실제 compact 모델에 연결했다. **48회의 작은 역전파 점검과 16개 체크포인트의 저장·복구 검증을 통과했다.** 두 초기값과 두 학습 경로 모두, 중단 후 재개한 최종 모델·Adam·난수 상태가 연속 실행과 비트 단위로 같았다. 다음 단계에서 비교학습을 실행할 준비가 됐다.

이번 48회는 학습 코드가 정상 작동하는지 확인하는 점검이다. 인식 정확도, 새로운 문장 인식, 웹캠 성능을 측정한 결과는 아니다. 다음 본실험 5,040회는 아직 실행하지 않았다.

## 데이터와 입력 처리

기존 15개 부모 문장에 각각 구절과 문장 캐시가 있어 총30클립이다. 부모12개는 학습(24클립), 부모3개는 내부 개발(6클립)로 유지했다. 구절과 문장은 같은 원본 픽셀을 공유하므로 독립된30발화라고 계산하지 않는다. OOV 보류 부모 `C293_A_012_019`는 양쪽에서 제외한다.

새 로더는 기존114개 동결 파일과 입력 해시·전사·분할·69토큰·CTC 길이를 검사한다. RGB uint8 캐시를 float32로 바꾸고 `/255 → 채널별 평균/표준편차 정규화`를 적용한다. 단일 입력은 `[C,T,H,W]`, 배치는 `[B,C,T,H,W]`이며 H=W=96이다. 짧은 입력은 배치 안에서 마지막 실제 프레임을 반복해 맞추되, **원래 길이를 CNN·양방향 LSTM·CTC에 계속 전달한다.** 패딩은 새 발화나 새 정보로 계산하지 않는다.

30캐시·2,023프레임의 정규화를 별도 계산과 완전히 대조했다. 개발 자료를 optimizer에 넣는 경우, 길이·해시·라벨·음성 배열·승인 상태가 바뀌는 경우는 거부한다. 기존 `provisional=true`, `training_ready=false`와 경계 주의 표시를 유지하며, 이번 요청 범위의 작은 기술 점검에만 별도 정책을 적용했다. 이 정책이 본학습이나 배포를 자동으로 실행하지는 않는다.

## 모델 구성

기존 `lipnet-compact-v1` 구조를 사용하고 가중치는 새로 초기화했다. 이전 실험의 학습 가중치나 교사 특징을 이어받지 않았다.

`입술 RGB 영상 → 3D CNN(32→64→96채널) → 프레임 특징256차원 → 2층 양방향 LSTM(방향별256) → 69토큰 CTC`

학습 파라미터는 **3,287,781개**다. CNN이 입 모양과 짧은 시간 변화를 추출하고, 양방향 LSTM이 앞뒤 프레임의 흐름을 통합한다. CTC는 프레임별 정답 없이 자모 열을 학습한다. 프레임마다 정규화하고 실제 길이로 LSTM을 묶어, 함께 들어온 긴 영상의 패딩이 짧은 영상의 결과를 바꾸지 않게 한다.

이번 비교는 두 방식 모두 CTC만 사용한다. 구절부터 학습하는 구성의 차이를 보기 위한 조건이며, 과거 시각 특징 전달 방식이 무효라는 결론은 아니다. 이전 특징은 새 D 시간격자에 그대로 대응하지 않는다는 이유도 있다. 음성·외부 교사·언어 모델을 인식 입력으로 쓰지 않는다.

GPU FP32, CPU FP32 CTC 역전파, Adam, gradient norm1을 사용한다. AMP/TF32를 끄고 엄격한 결정성을 적용했다. 과거에 검증한 수학적으로 동등한 공간 풀링을 사용하며 기존 모델 소스는 바꾸지 않았다.

## 실제 실행과 결과

작은 점검에는 학습 부모3개(기존 화자2명), 구절/문장6클립만 사용했다. 초기값42·43, A/B 각각에 연속6회와 중단2회→재개4회를 실행했다. 실제 optimizer 호출은 `(6+2+4)×4=48회`다. B는2회 구절 후 문장으로 전환하므로 재개 시 자료 종류와 학습률이 함께 바뀌는 경계를 검사했다.

| 항목 | 결과 |
|---|---|
| 로더·복구·예측 복원 테스트 | 15+10+13=38개 통과 |
| 별도 독립 입력 부정 사례 | 21개 모두 거부 |
| 실제 역전파·파라미터 갱신 | 48회, 모든31개 파라미터 텐서에서 유한한 비영 기울기 |
| 저장 체크포인트 | 16개, 모델·Adam·난수·순서·단계·학습률 독립 검산 통과 |
| 연속/재개 최종 상태 | 4쌍 모두 비트 단위 동일, 최대 차이0 |
| 패딩 영향 검사 | T23/T179 동시 처리와 개별 처리 차이 최대9.54×10⁻⁷; 사전 허용 오차 내 |
| 프레임 처리 | 실제9,932 + 배치 패딩3,180 = dense13,112; 재실행 포함 |
| 신경망 호출 | 학습48 + 패딩 비교3 = 51회; 개발 영상 호출0 |
| 본 비교학습 / 인식 성능 평가 | 미실행 |

예측 복원은 `argmax → 인접 반복 축약 → blank 제거 → strict=False 자모 조합`이다. 불완전한 자모를 U+FFFD 오류 문자로 남긴다. 원래 프레임 토큰과 축약 토큰도 저장하도록 규정했다. CER는 NFC 문자 기준으로 내부 공백과 오류 문자를 유지하며, 전체 편집거리 합을 정답 문자수 합으로 나눈다. 기존 토크나이저의 NFD 자모 CER 함수와 혼용하지 않는다. 빈 예측과 실패 사례도 평가에서 빼지 않는다.

기존 메타데이터의 `TCHW at loader`라는 미래 입력 설명이 비교 규약에 복사되어 있었다. 실제로 구현·검증한 축은 CTHW/BCTHW다. 원문은 보존하고 별도 `execution_clarifications.json`에 명시했다. 데이터나 실행 결과를 바꾼 수정은 아니다.

## 다음 5단계의 고정 비교

| 항목 | A: 문장 직접 학습 | B: 구절→문장 학습 |
|---|---|---|
| 출발 | 새 compact 초기화 | 같은 seed의 동일 초기 상태 |
| 앞420회 | 전체 문장 | 대응 구절 |
| 뒤840회 | 전체 문장 | 전체 문장 |
| 부모별 총 노출 | 문장210회 | 구절70회+문장140회 |
| 초기값 | 42·43 | 42·43 |
| 실제 프레임/실행 | 253,260 | 202,510 |

총4실행·각1,260회, **예정5,040업데이트**다. 같은 seed에서는 부모 배치 순서를 맞춘다. LR은1–840회0.001, 841–1050회0.0003, 1051–1260회0.0001이다. 전체 실제 프레임911,540, dense처리1,085,994, 패딩174,454를 사전에 계산했다.

420·840·1260회에서30클립을 정상·정지·순서 섞기 조건으로 평가한다. 총1,080건은 같은 자료와 조건의 반복 평가 건수이며 독립된1,080문장이 아니다. 주평가는 **최종1260회, 개발 전체문장3개의 정상조건 corpus CER**다. WER·완전일치·오류 문자·반복 출력과 정지/섞기 결과를 함께 보고한다. 좋은 중간 체크포인트를 골라 주결과로 바꾸지 않는다.

추가 연구의 기술적 신호는 두 seed 모두 B의 주 CER가 낮아지고 평균 감소가5%p 이상인 경우로 고정했다. 통계적 유의성이나 제품 사용 가능 판정은 아니다. 개선이 없으면 결과를 기록하고 원인을 다시 점검한다.

업데이트 수와 부모 방문 횟수는 같지만 B의 실제 프레임은 A보다20.04% 적고 전체 문장 노출도 적다. 따라서 **고정 업데이트 예산의 학습 구성 비교**이며 학습 순서 하나의 순수 인과 효과로 해석하지 않는다. 기존 화자·내부 개발3문장의 작은 파일럿이므로 미지 화자나 실용적 일반화 성능을 주장하지 않는다.

## 자원과 실행 범위

RTX3080 10GiB에서 이번 스모크의 PyTorch 최대 할당은823.88MiB, 예약은1,134MiB(약1.11GiB)였다. 48회 optimizer 구간 합계는약6.00초, 초기화·데이터 확인·저장 등을 포함한12개 실행 구간 합계는약22.74초다. 둘 다 전체 작업시간이나 본실험 시간으로 해석하지 않는다. 본실험은1,080평가가 추가되며 실행기·저장 빈도에 따라 시간도 달라진다.

다음 실험도 최대 dense 모양은 `2×3×179×96×96`지만 두 입력의 실제 길이 합 최대316은 이번 점검의263보다 크다. 다음 실행기에서 이 조합을 먼저 확인한다. 다음 단계의 보수적 한도는 실행당1시간·전체4시간, 시작 시 로컬 여유4GiB·CUDA 여유2GiB, 예약 메모리6GiB 초과 시 중단이다. 이는 예상 완료시간이 아니라 이상 진행을 멈추는 한도다. 오류 발생 시 마지막 완전한 상태와 실패를 보존하며 조건을 몰래 줄여 계속하지 않는다.

스모크 체크포인트16개의 실제 크기는632,082,704bytes다. 본실험은 고정 체크포인트12개와 로그·평가 확률을 별도 저장하도록 준비한다. **현재 파일럿에는 추가 AIHub 원본 다운로드나 코랩이 필요하지 않다.** 이 결과를 테라바이트 전체 학습이나 30초 원본 영상 통째 입력의 자원 보장으로 확대하지 않는다.

원본 TAR·음성·추가 다운로드 접근0, 서비스 교체0이다. 이전114개 동결 파일과 서비스 범위10항목을 보존했다. 기본 서비스 체크포인트는 이번 작업 전부터 없던 상태를 유지한다. C002_A012_035의 표시구간2.6667ms 주의 표시는 유지하며, 이전에 원본 프레임 교집합0을 확인한 범위 이상으로 정밀 조음 경계를 인증하지 않는다.
