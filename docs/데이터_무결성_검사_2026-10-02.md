# D: 학습 데이터 무결성 검사

검사 기준일: 2026-10-02

**최종 결과: 검사 완료. 정면 영상 300개·WAV 300개는 전체 디코딩과 길이·프레임 수 대조를 통과했고, 압축 해제 사본 360개는 TAR 원본과 바이트가 일치했다. 일부 기존 라벨의 시간 범위 오류는 별도 검수가 필요하다.**

정면 영상은 총 25.46시간·2,746,448프레임이다. 디코딩 작업에는 약 66.96분, 별도로 병행한 사본 해시 비교에는 약 31.58분이 걸렸다. 검사 종료 후 원본 TAR 10개, 사본 360개, 보호된 선택·분할 명세에 변경이 없음을 확인했다. 디코딩용 임시 파일은 모두 제거됐다.

## 검사 대상과 방법

`D:\009.립리딩(입모양) 음성인식 데이터` 안의 TS1·TS10·TS2·TS20·TS200 및 짝을 이루는 TL TAR 10개를 대상으로 했다. TAR 총 크기는 462,434,406,400바이트(430.68GiB)이며, 내부 정규 파일은 MP4 1,500개·WAV 300개·JSON 1,500개다. 이미 풀린 TS2의 MP4 300개·WAV 60개도 TAR 내부 파일과 비교한다.

원본은 읽기만 했다. TAR 전체를 압축 해제하지 않고, 디코딩할 파일만 프로젝트 임시 폴더로 꺼내 검사 직후 지운다. 기존 G: 손상 사본은 과거 검사 기록만 비교하며 다시 내려받거나 수정하지 않았다. 모델 학습·추론·정확도 평가 및 기존 데이터 분할 변경은 수행하지 않는다.

현재 선택된 89개 영상은 먼저 전체 디코딩과 독립 교차검사를 완료했다. FFmpeg가 끝까지 디코딩한 프레임 수, OpenCV가 읽은 메타데이터, MP4 샘플 테이블 수, 입술 좌표 개수가 모두 일치했다. 프레임 출력 중복·누락과 디코딩 경고는 없었다. 단계17 선정 59개는 stage7 계획에서 학습 51개·개발 8개로 나뉘며, 신규 30개는 학습 24개·개발 6개다. 신규 120문장도 학습 96문장·개발 24문장으로 나뉜다.

최종적으로 정면 300개 전체에서도 디코딩 프레임 수와 메타데이터가 일치했고 출력 프레임 중복·누락은 0개였다. WAV 300개는 모두 48kHz·16비트·2채널 PCM이며, 실제 디코딩 종료 시각과 PCM 샘플 수로 계산한 재생 길이의 최대 차이는 0.5마이크로초로 시간 표기의 반올림 범위였다. FFmpeg가 WAV 300개에 출력한 `Guessed Channel Layout: stereo`는 채널 배치 추정 안내이며, 다른 디코딩 메시지는 없었다.

정면 원본 300개 중 288개는 디코딩과 라벨 메타데이터 조건을 함께 통과했고, C025의 12개는 영상 자체는 정상이나 라벨 시간 검수가 필요하다. 전체 원본의 통과 여부와 특정 문장을 학습에 사용할 수 있는지는 구분한다. 사본 비교와 디코딩 양쪽에서 읽은 공통 파일 120개(정면 MP4 60개·WAV 60개)의 SHA-256도 모두 일치했다.

## 이전 손상 사본과의 비교

과거 G:에서 검사한 정면 180개와 이번 D: TAR member 180개를 파일명으로 고유하게 연결했다. 과거 잘린 파일 161개와 빈 파일 2개는 새 사본에서 크기가 증가했고 컨테이너 구조를 통과했다. 과거 구조 검사만 통과했던 17개는 같은 크기다. 크기가 같다는 사실만으로 바이트가 같다고 판단하지 않았다.

새 TS2·TS20·TS200의 정면 영상 180개는 이번 전체 디코딩도 전부 통과했다. 과거 문제 파일 163개의 **새 D: 사본**은 구조와 디코딩 검사 모두 통과했으며, 과거 G: 사본을 복구·덮어쓰기한 것은 아니다.

대표 파일 `lip_J_1_F_02_C040_A_001.mp4`는 과거 18,874,368바이트였으나 새 사본은 349,118,878바이트다. 새 파일에는 mdat 끝(348,888,707바이트) 다음의 moov도 끝까지 존재하며, 전체 9,098프레임 디코딩을 통과했다. 이미 풀린 D: 사본과 TAR 내부 파일의 SHA-256도 같다.

이는 새 D: 사본에 대한 검사 결과다. 과거 손상이 다운로드·분할 병합·압축 해제·업로드·동기화 중 어디에서 발생했는지는 현재 증거만으로 확정할 수 없다.

문장 종료 시각이 실제 영상 트랙 길이를 넘는 주석은 전체 각도 기준 88개, 고유 녹화·문장 조합 기준 18개다. 정면 A에서는 **C025의 12개 라벨에 포함된 16문장**이 해당한다. 한 프레임 이하의 단순 경계 초과는 없다.

- C025: 12녹화 × 5각도, 라벨 60개·문장 주석 80개. 초과 범위는 약 0.600~7.550초다.
- C002: C/E/G/I 각도 005 영상의 문장 ID50이 각각 약 2.002초 초과한다. 정면 A에는 이 오류가 없다.
- C032: B/D/F/H 각도 011 영상의 문장 ID38이 약 3.293~3.427초 초과한다. 정면 A에는 이 오류가 없다.

예를 들어 `lip_J_1_F_02_C025_A_006.mp4`는 실제 길이가 301.868233초인데, 라벨 ID42의 종료는 305.450667초, ID43의 종료는 309.418667초다. 원시 시각을 그대로 사용하면 정상적으로 문장 클립을 만들 수 없다.

문제가 있는 시간만 영상 끝으로 잘라 붙이거나 기존에 측정한 시간 이동량을 다른 녹화에 일괄 적용하지 않았다. **C025는 말미 16문장만 제외한 뒤 나머지를 자동으로 정상 처리해서도 안 된다.** 앞선 분석에서 시간축 차이가 발견된 자료이므로 녹화별 시간 매핑을 확인해야 한다. 단계17에서 선정했던 기존 59개 영상과 신규 파일럿 30개에는 이 화자가 포함되지 않는다.

문장 ID·라벨 해시·시작/종료 시각·초과량은 [시간 오류 후보 목록](../experiments/data_integrity_20261002/label_results/sentence_time_exclusions.json)에 저장했다. 이는 후속 준비 단계의 검수·제외 후보이며, 원본 라벨이나 기존 캐시를 수정한 것은 아니다.

## 학습 준비에 적용할 사항

1. 검증된 D: TAR를 원본으로 보관하고 선정한 영상·문장만 꺼내 전처리한다. 모든 원본을 상시 압축 해제할 필요는 없다.
2. 현재 선정된 기존 512문장·신규 120문장은 라벨 바이트와 선택 구간의 메타데이터 조건을 통과했다. 신규 녹화의 음성·영상 시간 매핑과 실제 전사 일치는 별도로 확인한 뒤 학습용 ROI 캐시를 만든다.
3. 모든 영상은 29.97002997fps의 일정한 프레임 간격이다. JSON의 FPS=30 대신 실제 영상 시간축을 사용한다.
4. 비정면 JSON 1,200개는 자기 각도 이름의 WAV를 기재하지만 실제 WAV는 녹화당 정면 A 이름 한 개씩 있다. 공유 음성 후보가 있다고 기록했으며 다른 각도와 시간 정렬이 같다고 가정하지 않았다.
5. 정상 파일 목록을 곧바로 전체 학습 목록으로 사용하지 않는다. 기존 검증 화자 C025·C294, 신규 개발 화자 C040·C059·C769, 기존 녹화별 분할과 고정 test는 보존한다. [역할 매핑](../experiments/data_integrity_20261002/archive_results/readiness_role_map.json)에 상세 범위를 기록했다.

## 검사의 한계

- 정면 300개와 WAV 300개를 전체 디코딩 대상으로 삼았다. **비정면 MP4 1,200개는 컨테이너·메타데이터·라벨 검사 대상이며 전체 디코딩 통과로 표시하지 않는다.**
- AIHub 제공 원본 checksum과 대조하지 않았고 TAR 전체 payload 해시도 계산하지 않았다. member 해시는 이번에 읽은 바이트의 지문이며, 사본 해시 일치는 로컬 압축 해제 결과가 TAR와 같다는 뜻이다.
- 파일이 열리고 좌표가 영상 안에 있다는 사실은 실제로 입술을 정확히 가리키는지, 전사가 실제 발화와 같은지, 음성과 입술이 동기화되는지까지 보장하지 않는다. 전체 수동 청취·입술 검수는 이번 범위에 포함되지 않는다.
- 검사 결과는 모델 정확도 향상이나 웹캠 인식 성공을 입증하는 실험 결과가 아니다.
